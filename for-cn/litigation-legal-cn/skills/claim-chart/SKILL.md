# /claim-chart

1. 读 `CLAUDE.md` → 角色、工作产品头、决策姿态、文档存储。
2. 若启用案件工作区：确认或选择当前案件；读 `matter.md`（立场、法域、阶段、代理思路、诉讼请求）。
3. 按下方工作流。
4. 模式选择：
   - `--patent` → 专利权利要求对照表。需要专利号与至少一个主张权利要求。子模式：`--infringement`、`--invalidity`、`--review`。
   - `--civil` → 民事构成要件对照表。需要诉讼请求或抗辩类型与我方立场。
   - 无参数 → 询问。
5. 民事模式：查阅本 skill 目录下 `references/element-templates.md` 取基线要件。映射前与用户确认适用的成文法条与司法解释。
6. 专利模式：解析主张权利要求为技术特征，标出争议术语（等同/功能特征/说明书界定），若有权利要求解释裁定或人民法院指导性案例的解释则适用。
7. 对每个要件映射对目标（被诉侵权产品 / 现有技术 / 证据 / 待复核对照表）。每格附出处引用。写入前对首字符为 `=`、`+`、`-`、`@`、Tab、`\r` 的格值前置单引号以中和公式解析。
8. 生成缺口清单（民事）或需证据清单（专利）—— 首要输出。
9. 按用户偏好写 markdown、CSV（数值 + `_sources` 伴随文件）、Excel 或 Sheets。每份输出加工作产品头。
10. 有活跃案件则写到该案件 `claim-charts/` 文件夹；否则执业级 `claim-charts/`。有活跃案件则往 `history.md` 加一行事件。
11. 返回摘要读数：权利要求 / 诉讼请求、目标、法域、阶段、按状态的要件计数、缺口清单、文件路径，以及"每一格都是待核对的引子"这一提醒。

# 要件对照表

## 已披露文书使用限制

见 chronology.md 同款警示：民诉法第 68 条、证据规定关于保密处理规则。若涉外调取，核对当地。

## 对照表是草稿，不是最终认定或诉讼请求

**放在每份输出顶。别删。别弱化。**

> 本对照表是律师分析与核验用草稿，不是已递交的诉讼请求、举证质证意见、代理词或法律意见。每处映射是律师须对源核验的引子。所列要件来自成文法、司法解释、指导性案例或权利要求解析 —— 具体案件的**控制性**依据（现行有效的成文法、最高法司法解释、指导性案例、人民法院案例库参考案例）优先。缺口检测是取证或申请的起点；不是对实体的结论。

漏标缺口是单向门 —— 起诉状某要件无充分事实基础、答辩状对某有争议要件无证据、庭审中损失无证明。多标是双向门 —— 律师复核清旗。默认偏向双向门。

## 模式选择

在动手前先问：

> 哪种对照表？
>
> 1. **专利权利要求对照表** —— 逐特征映射：被诉侵权产品的权利要求技术特征（`--infringement`）、现有技术（`--invalidity`）、他方对照表（`--review`）。用于专利侵权比对、专利无效请求书、FTO 分析。
> 2. **民事构成要件对照表** —— 逐要件映射诉讼请求（或抗辩）的构成要件对证据。用于起诉条件评估、举证准备、庭审要点、判决预分析。

加上通用采集：

- **立场。** 主张还是抗辩？（民事模式中翻转举证责任；专利模式中翻转侵权/无效框架。）

- **阶段。** 诉前 / 立案 / 举证 / 庭审 / 上诉 / 再审 / 执行。
- **已有对照表？** 若 `--review`，读入。

# 模式 1 —— 专利权利要求对照表

## 子模式

- `--infringement` —— 权利要求技术特征 vs 被诉产品（诉状附件、行政投诉附件、临时禁令行为保全申请附件、专利无效答辩证据）
- `--invalidity` —— 权利要求技术特征 vs 现有技术（专利无效请求书附件、无效答辩证据、专利法第 22 条三性抗辩）
- `--review` —— 复核他方生成的对照表

## 专利模式加载

- **专利号与主张权利要求。** 哪些独立、哪些从属。（除非要求，不对未主张权利要求作图。）
- **申请日 / 优先权日。** 建立现有技术判定基线。
- **权利要求解释。** 说明书界定、审查档案禁反言（`Festo` 类比在中国实务中转化为审查档案禁止反悔原则）、最高法或知识产权法院的解释裁定、专利复审委的解释、人民法院案例库参考案例。

## 专利模式工作流

### 步 1：解析权利要求

按编号解析主张独立权利要求为技术特征。处理：

- **前序。** 是否是限定性 —— 权利要求解释问题（人民法院案例库有相关参考）。若解释裁定未定，标 `preamble-limiting: unresolved`。
- **过渡词。** "包括"（开放）/"由……组成"（封闭）/ "主要由……组成"（半开放）。影响是否附加未主张技术特征即不侵权。
- **技术特征** 按逗号 / 分号分，编号 `[1a]`、`[1b]`、`[1c]`。编号保持稳定 —— 是对照表的脊柱。
- **功能性特征** —— 专利法第 26 条与最高法司法解释关于功能性特征解释的规则（依说明书公开的实现方式及等同方式解释）。若说明书未公开对应结构，标 `功能性特征-不清楚`。
- **马库什权利要求、产品-由方法定义、方法步骤依赖顺序** —— 各附特殊解释规则说明。
- **从属权利要求** —— 引父级；只对附加特征作图。**执行不做手势。** 若主张权利要求含从属，第 4 步逐一从属产出附加特征行，不发"从属应作图"的备注。
- **结构性用语的同义族 —— 默认 `依权利要求解释而定`。** 每个使用领域常见同义词的结构性名词，除非说明书专有界定或已有权利要求解释裁定排除歧义，行默认状态标 `字面-依解释而定`。中国实务中的常见争议家族与美国类似 —— 紧固件（倒钩 / 螺纹 / 突出）、流控（管腔 / 通道 / 孔）、机械外壳（轮毂 / 凸台 / 法兰）等。

对用户展示解析。映射前确认。错误解析污染下方每一行。

### 步 2：权利要求解释检查

标出争议术语：

- 说明书界定的自造词或明确定义
- 有审查档案历史（修改、争辩、放弃 —— 审查档案禁止反悔原则，最高法关于审理专利侵权司法解释）
- 功能语言（"用于"、"配置为"、"能够"）
- 相对术语（"基本上"、"约"）—— 明确性风险（专利法第 26 条充分公开）
- 计算机实现术语 —— 客体审查风险（专利法第 25 条智力活动的规则和方法、计算机程序保护规则）

每个标出的术语，说明按 X 解释时映射成立、按 Y 解释时映射失败。若已有解释裁定则适用；若在争议中，按双方拟解释各作图。

### 步 3：映射

对每个技术特征，对每个目标：

1. **找证据。** 被诉产品：产品文档、说明书、宣传材料、拆机、源码（若涉计算机专利）、证人陈述、司法鉴定意见。现有技术：中国专利用公开号 + 段落 / 图；外国专利同；非专利文献用页 / 图。对现有技术，标出该引用是否符合"公开"要件（专利法第 22 条第 3 款申请日以前在国内外为公众所知）。若不清楚，标 `现有技术资格：待举证`。
2. **逐字引用。** 逐字，不改动。跨句处断句并标示省略。
3. **给映射定性。**

   | 映射 | 含义 | 用于 |
   |---|---|---|
   | `literal` | 权利要求技术特征在被诉技术方案 / 现有技术公开中相同 | 两者 |
   | `literal-构成解释相关` | 按 X 解释字面成立；按 Y 失败 | 两者 |
   | `等同` | 等同侵权（相同的功能-相同方式-相同效果，且本领域普通技术人员容易联想） | 仅侵权 |
   | `新颖性破坏` | 单份现有技术公开全部技术特征（专利法第 22 条第 2 款） | 仅无效 |
   | `创造性破坏` | 现有技术组合 + 结合动机 + 效果可预期（专利法第 22 条第 3 款；KSR 式检验在中国实务中体现为"三步法"，最高法司法解释） | 仅无效 |
   | `部分` | 特征部分呈现 | 两者 |
   | `未发现` | 特征未呈现 | 两者 |
   | `待举证` | 从现有材料无法判断 | 两者 |
   | `依解释而定` | 视争议术语解释而定 | 两者 |

4. **每格状态。** `映射` / `映射-等同` / `部分` / `未发现` / `待举证` / `依解释而定` / `新颖性破坏` / `创造性破坏`。
5. **标未决问题。** "本项映射成立若 [X]。需要 [拆机 / 源码 / 证人 / 鉴定意见] 确认。"

**不做隐性补充。** 文档薄意味 `待举证`，不是从类似产品外推。

### 步 4：从属权利要求 —— 执行不做手势

对每个主张从属权利要求，产出实际一行（或多行）就附加限定作图对目标。父级依赖记录；从属侵权 / 无效要求父级的。**产出行，不产出"应产出行"的占位备注。**

若用户提供的主张权利要求列表含从属，输出必须含其行。若只给独立权利要求并说"暂图独立"，可以 —— 输出不图从属但显式浮出已略去的（"主张从属 [X、Y、Z] 本次未图 —— 请求：附 `--include-dependents` 重跑或粘贴从属权利要求文本"）。不悄悄跳过从属。

### 步 4.5：等同分析补充 —— 执行不做手势

对每个图为 `literal` 但被诉产品结构相似非完全相同的技术特征 —— 或 `literal` 依赖有争议权利要求解释的 —— 产出**配对的等同候选行**（侵权模式）。不给"等同分析另论"的脚注而不产出等同映射。

等同候选行加一段"功能-方式-效果"素描，每一特征附审查档案禁止反悔与捐献原则的风险旗，引用支持等同的证据。若等同不适用（技术特征在被诉产品中字面成立且无争议），跳过。若 `literal` 依解释而定且等同是律师在较窄解释下的替代方案，产出等同行。

### 步 5：间接、共同、故意（仅侵权）

标而不论：

- **间接侵权** —— 帮助侵权：明知他人利用其产品或方法侵犯专利权仍提供、诱导，或专门用于侵权的产品（最高法关于审理专利侵权司法解释）
- **共同侵权** —— 数人分别实施权利要求各步骤（分工分立侵权）时的责任归属
- **故意 / 恶意侵权** —— 加重赔偿依据（专利法第 71 条，惩罚性赔偿 1-5 倍，故意 + 情节严重）

### 步 6：无效门槛（仅无效）

对新颖性（专利法第 22 条第 2 款）：单份现有技术公开全部特征。跨引用组合是创造性范畴。

对创造性（第 22 条第 3 款）：主要现有技术 + 次要现有技术 + 有文档的结合动机（三步法 —— 最接近现有技术、技术特征差异、实际解决的技术问题 / 是否显而易见）。标显式教导-建议-动机、市场或设计需要动机、成功预期，以及**辅助证据**（专利复审委实务参考中类比 Graham 的辅助考虑）—— 商业成功、长期需要、他人失败、行业赞誉、复制。

也标：
- **客体审查**（专利法第 25 条智力活动规则和方法、计算机程序保护规则）
- **充分公开** —— 说明书应当清楚完整（专利法第 26 条第 3 款）
- **权利要求明确** —— 权利要求应当以说明书为依据，清楚简要限定专利保护范围（第 26 条第 4 款）
- **功能性特征结构公开** —— 见步 1
- **不可执行** —— 骗取专利、审查历史禁止反悔（律师执业行为规范禁止的以欺诈手段获得的专利权）

无效必须**清楚且令人信服**（专利复审委实务倾向标准；起诉过程中在民事案件中的证明力另论）。对照表中的初步展现不是庭审证明。

### 步 7（复核子模式）：审计

对每一行：映射有依据吗？出处引用准确吗？技术特征是否完全 covered？最强反驳是什么？最强反驳的机会是什么？逐行输出结论（`有依据` / `弱` / `无依据`）与对照表的漏洞。

## 专利模式护栏（加共同护栏之上）

- **律师执业责任。** 侵权 / 无效对照作为起诉状或专利无效请求书附件递交需合理调查与非无理由基础。本 skill 输出是草稿，不是可递交对照。
- **权利要求解释诚实。** 每个 `依解释而定` 行说明所假设的解释与失败时的解释。
- **等同诚实。** 等同映射不等于字面。每一特征加审查档案禁止反悔与捐献原则风险旗。
- **间接分开。** 别把帮助 / 诱导折进直接侵权行。
- **无效证明力。** 对照表说明清楚且令人信服（专利复审委）与庭审民事证明力（一般民事高度可能性）的差别。

# 模式 2 —— 民事构成要件对照表

对某诉讼请求（或抗辩）逐要件映射对证据。杀手输出：(a) 说清什么证据对应什么要件的对照表，(b) 告诉律师**还缺什么**的缺口清单。

## 工作流

### 步 1：识别诉讼请求

- 什么诉讼请求？（或抗辩？）若多个请求，逐个作图。
- 哪一侧？原告初步举证、被告抗辩、被告对原告初步举证的挑战。读 `## 立场` 取默认 —— `原告方` 默认映射原告初步举证；`被告方` 默认映射缺口与抗辩。开始前确认与本案立场一致。
- 哪个法域？内地法院 / 仲裁；若涉外，先跑跨法域识别。**构成要件与举证规则按案由与法域可能不同。** 模板库是基线；成文法、司法解释、指导性案例是控制性依据。
- 哪份诉状？读起诉状 / 反诉状 / 答辩，让对照表跟踪实际主张的诉请，不是通用版本。

### 步 2：加载要件

三条路径：

**(a) 模板库。** 参考 `references/element-templates.md`（本 skill 目录）。常见诉讼请求与抗辩的基线构成要件，附成文法条与司法解释引用及法域说明。选与主张诉请匹配的模板。

**(b) 自定义。** 用户定义要件，或粘贴一份司法解释 / 成文法 / 起诉状诉请让本 skill 解析。逐一解析为编号要件。

**(c) 抗辩。** 也支持映射抗辩 —— 诉讼时效、证据不足、免责事由、格式条款效力（民法典第 496-498 条）、违约金调减（第 585 条第 2 款）、比例过错等。抗辩有各自要件（被告须证明或原告需反驳），按之作图。

**法域专属表述 —— 主动浮出。** 若档案 `## 我们是谁 → 司法管辖足迹` 或活跃案件 `matter.md` 提到**上海、深圳、北京**这些商事案件常见地区，且案件涉及地方规定（例如上海地方数据条例、深圳数据条例、北京自贸区规则），或涉外，主动提示，别问"你法域是否加减改要件"。用户不应教 skill 本地规则；skill 应主动提供并让用户选。

主动浮出的差异（非穷尽 —— 模式复现时加入）：

| 诉讼请求 / 抗辩 | 基线（民法典/成文法） | 法域/案由专属表述 |
|---|---|---|
| 合同违约 | 4 要件（合同存在、我方履行或免除、对方违约、损失+因果） | **建工合同：** 加"竣工验收 / 结算"要件；工程款优先受偿权（民法典第 807 条）。**买卖合同（国际货物）：** 若约定 CISG 或涉外，规则不同。 |
| 侵权 | 3 要件（侵权行为、损害、因果关系）+ 过错（一般侵权） | **产品责任**（民法典第 1202-1204 条）：无过错责任；生产者与销售者关系。**机动车事故**（第 1208 条起）：无过错责任 + 交强险 + 商业险。**环境污染**（第 1229 条）：无过错 + 举证责任倒置。 |
| 违约金调减 | 民法典第 585 条第 2 款：过分高于损失可请求调减 | 实践参考：损失 130%。上市公司诉讼 / 大额商事更严；小额消费类相对宽松。 |
| 商业秘密（反不正当竞争法第 9 条） | 3 要件（信息符合秘密性、采取保密措施、被披露 / 使用） | 最高法关于审理商业秘密民事案件司法解释详细规定。举证难点：秘密性、保密措施是否合理。 |
| 名誉权 | 民法典第 1024 条：违反公共利益、公序良俗 + 损害后果 | 公众人物名誉权：更高证明门槛（部分司法解释与指导性案例参考）。 |
| 劳动争议 | 劳动合同法：因案由不同（解除、经济补偿、加班费等） | **仲裁前置**：劳动争议须先仲裁后诉讼（劳动争议调解仲裁法第 5 条）。仲裁裁决不予接受方可起诉。**举证责任**：与用人单位管理相关的争议（考勤、工资、社保）由用人单位承担举证责任（若干规定第 6 条）。 |

法域专属表述与基线差异实质时，对照表开头一行标注：

> **法域提示：** 你说本案为 [X 地 / X 案由]。本表使用 [法域/案由] 表述与基线的差异：[差异]。下方对照按此表述作图。若判断错，说一声我重新加载。

映射前与用户确认要件清单。若不在模板库覆盖，问："你法域 / 案由是否加、减、改这些要件？"

### 步 3：映射

对每要件：

- **支持证据** —— 什么证明本要件？附出处：
  - 证人陈述 —— `[证人 A 陈述]`
  - 书面陈述 —— `[书面陈述 X 第 X 段]`
  - 举证材料 —— `[被告举证 X 号 第 3 页]`
  - 自认 —— `[被告答辩状第 X 段自认]`
  - 证据（原告 / 被告举证清单） —— `[原告证据 X-Y]`
  - 鉴定意见 —— `[司法鉴定书第 18 页]`
  - 询问笔录 —— `[原告询问笔录第 8 条]`
  - 成文法 / 案例 —— 纯法律要件
- **逐字引用**（陈述性或书证性证据）。无转述。
- **反驳证据** —— 什么打反面？附出处。本行的脆弱点。
- **强度** —— `强` / `中` / `弱` / `无`。简单点。过度校准强度是噪音；`弱` 与 `无` 是重要的行。
- **每格状态** —— `已支撑` / `部分` / `有争议` / `缺口` / `待取证`。

### 步 4：缺口检测 —— 杀手输出

映射后产出缺口清单。这是对照表的用意。

> **证据薄或无的要件：** [清单]
>
> - 主张（原告）：这些威胁到起诉状能否被受理（民诉法第 122 条起诉条件）、庭审胜诉。发起下一动作前补齐。
> - 抗辩（被告）：这些是我方庭审攻击点、举证质证的攻击方向。原告要证每一要件；缺口就是抗辩。
> - 诉前阶段：这些是取证优先项 —— 需要哪些证人、书证、公证、司法鉴定申请把缺口变 `已支撑` 或确认 `无`。

缺口检测不是对实体的结论。是"案件哪里薄"的地图。

### 步 5：阶段感知框架

问阶段。同一表；输出框架不同：

- **诉前 / 立案。** 起诉状是否就每要件充分主张事实（民诉法第 122 条：明确的诉讼请求和事实、理由；证据规定关于起诉条件的把握）？依信息与信念主张而无事实基础的要件是被驳回起诉或不予立案的靶点。
- **举证。** 每个 `缺口` 或 `待取证` 要件需要什么举证？哪些证人、哪些书证申请、哪些鉴定申请。
- **庭审。** 每要件是否有实体上争议的事实？我方 `已支撑` 且对方无反驳证据的格是有利于我方的举证；`有争议` 格是庭审拉锯点。
- **判决预分析。** 举证顺序：哪个证人证要件 1、哪份证据证要件 2、认证程序如何。对照表成为庭审出示的顺序图。

### 步 6（复核子模式）：审计

对对方举证清单、答辩、外聘律师草稿：对每要件，其引证据是否实际证明它？哪里薄？我方最强反驳？

## 民事模式护栏（加共同护栏之上）

- **法域。** 要件清单是基线。永远确认控制性成文法 / 司法解释 / 案例。在对照表 `_elements` 页说明来源。
- **仅主张的诉请。** 图起诉状实际主张的诉请。别加起诉状未主张的（就算事实可能支持）—— 那是另一分析。
- **抗辩。** 若图抗辩，注明举证责任在被告（多数）还是原告（一旦抗辩提出）。
- **「缺口」≠「案件败」。** 缺口是引子。取证、书面陈述、鉴定意见可能填。对照表显示哪里可挖。

- **结论行** —— *"本 skill 不下结论。"* 已映射 / 已支撑的要件：[list]。需证据 / 缺口状态的要件：[list]。依解释而定（专利）/ 有争议（民事）要件：[list]。律师判断必需。
- **引用核验** —— 每处出处、案例、章节 / 段落、证人陈述时点须对源核对。

### CSV（永远）

每份对照表两个文件：
- `[chart-slug].csv` —— 值
- `[chart-slug]_sources.csv` —— 逐字引用、出处、备注

**CSV / 电子表格格安全。** 写入任何格值前，检查首字符。若为 `=`、`+`、`-`、`@`、Tab（`\t`）、回车（`\r`），前置单引号（`'`）以中和 Excel/Sheets 公式解释。逐字引用来自对方主张、竞品说明、第三方现有技术、抓取的网页、庭审记录、举证材料，可能含被电子表格作为公式执行的字符串（`=HYPERLINK(...)`、`=cmd|...!A1`、`+WEBSERVICE(...)`），把对照表变成律师打开时的数据外泄或远程执行入口。RFC 4180 引号本身不能防止 —— 首字符 `=` 仍被解释。在 CSV、XLSX、Sheets 输出上都加单引号前置。日志记录哪些格被中和以便复核律师看到。

### 电子表格（Excel 或 Sheets）

问用户团队用哪个。仿 corporate-legal `tabular-review` skill 的模式 —— 同一格出处引用模型、同一状态色标、同一 `已核` 列、同一 schema 页：

- 每行一要件（或要件 × 目标，若多目标对比）
- 每证据列配一隐藏源列含逐字引用与出处；格备注（Excel）或备注（Sheets）在悬停显示引用
- 按状态色标：
  - *专利：* 白 = `映射`、黄 = `依解释而定` / `部分` / 等同、橙 = `待举证`、红 = `未发现`
  - *民事：* 白 = `已支撑`、黄 = `部分` / `有争议`、橙 = `待取证`、红 = `缺口`
- `已核` 列每证据列一，默认空 —— 由复核律师标
- `_elements` 页记录要件来源：成文法（条文号）、司法解释、指导性案例、专利权利要求解析。这是让对照表可审计的部分 —— 阅读者能看到要件来自哪里。
- `_gaps` 页列出每个 `缺口`、`待举证`、`待取证` 行，附还需什么
- 仅专利模式：`_claim-parse` 页（技术特征分解）、`_constructions` 页（争议术语与所设解释）

在每一写入电子表格的格上加单引号前置中和。

前置工作产品头作首行。旁附：

> 本对照表派生自可能受保密或商业秘密约束的源文书。它继承源的保密与商业秘密属性 —— 分发到保密圈外可能破坏保密（律师法第 38 条、反不正当竞争法第 9 条）。存放于案件保密文件夹，分发决定要有意识。本对照表未递交或送达 —— 是给律师复核的草稿。

## 共同护栏 —— 清单

- **引用核验。** 每处出处（页 / 段 / 证据编号 / 证人陈述时点 / 公证书号）是对源的主张。律师核验。skill 不发明 —— 若出处无法产出，格为 `待举证` 或 `缺口`。

- **决策姿态。** 不确定某要件是否被证时，加旗；不做决定。`部分` 告诉律师缺什么。
- **公式注入。** 每一写入 CSV / XLSX / Sheets 的格检查首字符 `=`、`+`、`-`、`@`、`\t`、`\r` 并前置 `'`。默认：中和后写。
- **要件因法域而异。** 模板库是基线。控制性成文法 / 司法解释 / 案例优先。
- **对照表不是代理词 / 递交文书 / 诉请。** 每份输出是草稿。

## 这个 skill 不做的事

- **不下结论。** 不侵权、不无效、不责任、不无责。绝不。
- **不决定权利要求解释**（专利）或**控制性要件**（民事）。它标出争议术语 / 基线要件并在给定假设下作图。
- **不承担专利无效的清楚且令人信服举证责任**或**民事庭审的高度可能性证明**。它产出初步展示的草稿供律师复核。
- **不替代专家分析。** 源码复核、拆机、技术专家、损失鉴定是分开的工作产品，本对照表路由到它们，不替代它们。
- **不送达、递交、签署任何东西。** 每份输出是草稿。律师递交与签署。
- **不外推。** 若证据不在，格为 `待举证` / `缺口` —— 绝不猜。
