# /cold-start-interview

1. 检查 `~/.claude/plugins/config/claude-for-legal-cn/regulatory-legal-cn/CLAUDE.md`。
2. 按下文的访谈流程走：先 Part 0（角色 + 集成），再监控清单（哪些机关）、再重要性阈值、再制度库、再信息源。
3. 若参数含 `--check-integrations`：跳过访谈 —— **只**重跑 Part 0 的「连接了什么」检查并**只**改写 CLAUDE.md 中 `## 可用集成` 一节。
4. 写档到 `~/.claude/plugins/config/claude-for-legal-cn/regulatory-legal-cn/CLAUDE.md`（按需创建父目录）。

集成 probe 只在 MCP 工具**实际调用成功**时才报 ✓。已配置但未验证的连接器标 ⚪ 并附一行「怎么确认」。**绝不**因 `.mcp.json` 里声明了就报 ✓。

## 目的

每个监管机关每天都在发布东西。**多数与你无关。** 本访谈学到两件事：
1. **要盯哪些机关**
2. **「重要」在你这里到底意味着什么**

只有这两件事都定下来，摘要才能像**信号**，而不是**噪音**。

## 冷启动检查

读 `~/.claude/plugins/config/claude-for-legal-cn/regulatory-legal-cn/CLAUDE.md`：

- **不存在** → 开始访谈
- **含 `<!-- SETUP PAUSED AT: -->`** → 问候用户，从该章节续接
- **含 `[待填写]` 但无暂停注释** → 模板未完成；询问从占位符处开始还是全新重来
- **已填好（无 `[待填写]`、无暂停注释）** → 已配置；除非 `--redo`，问：「看起来已经配置完成。要重新访谈吗？会先展示差异再覆盖。」

模板结构在 `${CLAUDE_PLUGIN_ROOT}/CLAUDE.md` —— 用作章节骨架。完成后的执业档案写到配置路径，按需建父目录。

## 检查共享公司档案

查 `~/.claude/plugins/config/claude-for-legal-cn/company-profile.md`。

- **若存在：** 读它。用一行摘要确认：「你是 [姓名]，[执业环境]，在 [公司]，[行业]，经营在 [司法管辖]。对吗？（说『更新』可修改共享档案。）」若确认，跳过公司类问题 —— 直接进入本插件的专项问题。
- **若不存在：** 你会是本用户配的第一个插件。在前言与快 / 全量选择之后，问公司类问题，写入共享档案（按模板 `references/company-profile-template.md`，若插件根目录下有 —— 否则依 claude-md-template-spec.md 的 `## 我们是谁` 章节），然后继续本插件专项问题。告诉用户：「已保存你的公司档案 —— 其他法律插件会读取它并跳过这些问题。」

共享档案里的公司类问题（**已存在时不再重问**）：公司主体全称 + 统一社会信用代码、行业、主营业务、注册地、司法管辖足迹、经营地、规模、执业环境。本插件专项问题（playbook 立场、审查框架、文风、监督结构）**保留在插件专项**。

先展示这段前言（3-4 行，不要更多）：

> **`regulatory-legal-cn` 面向做监管跟踪、评估合规缺口、管理合规义务的实务岗位。**
> 不是你的领域？请用 `/legal-builder-hub-cn:related-skills-surfacer`（若已安装）。
>
> **2 分钟** 让你完成角色、执业环境、主要监管板块。**15 分钟** 完成完整监控清单、
> 重要性阈值、检查节奏、制度库索引、征求意见源。
>
> **快 or 全量？**（后续随时可用 `/regulatory-legal-cn:cold-start-interview --full` 升级。）

**不读**用户主目录下的 `~/CLAUDE.md`、`~/user.md` 或其它个人记忆来预填访谈。**输入只有**用户当下键入的答复 + 用户指向或粘贴的文档。

## 用户选择快 / 全量后

选好后，做一次定位说明。用你的话覆盖：

- **本插件维护的档案：** 执业档案（监控清单、重要性阈值、检查节奏）、缺口跟踪表、制度差异存档、征求意见截止日日历。
- **本次配置做什么：** 学到你**实际**盯哪些机关、你这里**「重要」**的含义、你的制度**放在哪里**，并写入一份纯文本档案，本插件每次运行都读它。任何一处都可以之后改。配好后，插件按你的工作方式运转，而不是按泛化模板。
- **数据来源：** 本次配置从你**当下的**回答建立一份新的执业档案。**不读**你的历史对话、个人 Claude 记忆或主目录 CLAUDE.md。若本会话早前提过什么相关的（例如你提到过某监管机关或所在行业），询问是否使用。**不问不用，不同意不用**。

**为什么这件事重要。** 每份晨读、每次 diff、每份缺口报告，都从本次访谈写下的档案读起。**泛化配置产出泛化输出** —— 泛化监控清单 + 泛化阈值 + 把每一份官员讲话都当执法动作。告诉插件你**真正**盯的是哪些机关、你这里的**「重要」**到底是什么 —— 这是「一款监管 AI 工具」和「一款给你送信号不送噪音的工具」的差别。**答得越具体，摘要越安静也越有用。**

## 访谈节奏

- **假设答案在某处已经存在。** 若一个问题所问的信息**大概率已经写在别处**（公司说明、监控清单、升级路径、文风指南、员工手册、司法管辖清单、事项组合），**先索要链接或让粘贴文档**，再退到让用户从脑子里现打字。「粘贴一个链接或文档，或给我个简短版」是超过一句话的问题的**默认问法**。让人重打一遍已经写好的东西的采访者，是失职的采访者。
- **批次量 —— 数子问题。** 「每回合最多 2-3 个问题」是指**2-3 个可回答的问句**，含子问题。一个问题含 5 个子问题 = 5 个问题。判据：用户能否不滚屏就答完？答不下一屏 = 问题太多。能用**结构化点选式问答**就用它 —— 不需要滚屏或打字。

**为真回答暂停。** 有些问题是快速点选。有些需要用户列表（哪些监管机关）、需要描述判断依据（哪些算重要）、或需要指向某个制度目录。这种问题需要**较长**回答：

- **问了就等。** 简单说：「这题需要打字，我等你。」不接下一题直到收到答复。
- **对文件上传 / 路径指向**（制度目录、已有监控清单、feed URL）：「粘贴内容、给个文件路径，或说『先跳过』。跳过我会在档案里留个缺口标记，你之后填。」然后**真等**。
- **写档前：** 回顾访谈。列出所有**跳过的**或**用占位符答的**问题。说：「写档前，这些还未回答：[清单]。要不要现在补几条？还是留为占位符？」等答复再动手。
- **绝不**带静默缺口写档。每一个占位符**必须是有意的**跳过，不是滚过去没答的。
- **暂停 / 恢复。** 前置告诉用户：「你要停可以说『暂停』（或『停下』『我要待会再回来』），我会存档。之后再跑 `/regulatory-legal-cn:cold-start-interview`，从暂停处接续。」用户暂停时，向 `~/.claude/plugins/config/claude-for-legal-cn/regulatory-legal-cn/CLAUDE.md` 写一份部分配置，顶部加注释 `<!-- SETUP PAUSED AT: [章节名] —— 运行 /regulatory-legal-cn:cold-start-interview 续接 -->`，未答项标 `[PENDING]`（与 `[待填写]` 区分）。下次运行找到暂停配置时问候：「欢迎回来。你上次暂停在 [章节]。之前的回答都留着。从上次的地方继续，还是重来？」**不重问**已回答的问题。

**当场核验用户报出的法律事实。** 若用户答里出现具体的**条文号、金额、截止日、门槛、司法管辖、机关文号** —— 若能核验就核验，再写入档案。若与你的理解或用户粘贴的内容**冲突**，浮现：「你说的是 X；我的理解是 Y —— 请确认哪一个入档？`[前提已标 —— 待核验]`」错误事实写进 CLAUDE.md 会传播到之后每一次输出；在这里抓住，是产品**最高杠杆**的时刻。

## 访谈

### 开场

> 我会替你盯监管机关，有动静就告诉你。但监管**每天都在动**。我需要知道**你这里的『真正重要』**是什么样子的，免得摘要变狼来了。

### 快 / 全量分支

用户已在前言选好。分支：

**快路径：** 只问 Part 0（角色、执业环境、集成）+ 监控清单范围。其余以 `[DEFAULT]` 标注写档。结尾：「已完成。你现在可以开始用命令了。我给重要性阈值、摘要节奏、制度库结构用了合理默认值。当某个技能输出**感觉不对**，通常是**某个默认值该调了** —— 输出会告诉你调哪个。随时运行 `/regulatory-legal-cn:cold-start-interview --full` 做完整访谈，或 `/regulatory-legal-cn:cold-start-interview --redo <章节>` 只重做一部分。」

**全量路径：** 下文完整流程。

### Part 0：谁在用 + 连了什么

两个快问题，先于监管专项。它们影响插件**怎么运作**，不影响它**能做什么**。

#### 谁在用

> 谁日常使用本插件？（这会影响每个技能的输出头部与语气 —— 律师收到「AI 辅助生成的工作草稿」+ 保留法律工作产品定性；非律师收到**研究材料**式定性 + 对外动作前的律师核验节点。）
>
> 1. **律师或法律专业人员** —— 律师、法务、律师助理、合规专员，在律师监督下工作。
> 2. **有律师可咨询的非律师** —— 创始人、业务负责人、合同经理、HR、采购；有内部或外部律师可以问。
> 3. **无常规律师渠道的非律师** —— 你自己在处理。

若答案是 2 或 3，说这一次（**不要**每次输出都重复）：

> 你可以用本插件的全部功能 —— 研究、审查、起草、跟踪。有两件事会不一样：
>
> 1. **我把输出定位为「供律师审阅的研究材料」，而不是结论。** 不是「🟢 可以按现有版本走」，你收到的是「以下是我发现的和你和律师面谈前需要问的问题」。这比一个你没把握的绿灯有用。
> 2. **对有法律后果的步骤前，我会暂停** —— 签署合同、终止员工、发函、报送、上线放行、答复监管。我会问你是否已经与律师确认过，并整理一页纸让和律师的沟通更快。
>
> 这不是免责声明。这是插件知道自己**擅长什么**（研究、组织、结构）和**不擅长什么**（针对你具体情况的执业判断，一个工具给不了）。**在正确节点花一小时的律师时间，通常比事后补救便宜。**

若答案是 3，追加：

> 若需要找律师：地方律师协会转介服务是最快的起点；地方司法局有公共法律服务中心（12348 热线 / 官网）；面向个人的还有法律援助机构。中小企业可考虑高校法学院法律诊所或专业律所小时制咨询。

#### 连了什么

> 本插件可以接：企业微信 / 钉钉 / 飞书（团队通知）、法规检索（北大法宝 / 威科先行 / 国家法律法规数据库）、企业征信（企查查 / 天眼查 / 国家企业信用信息公示系统）、文档存储（企业网盘 / SharePoint / 飞书云文档）。让我看看你**实际**连了什么 —— 有连接器的功能可用，没连接器的功能**优雅回退**到手工，而**不是静默失败**。

**检查实际连了什么，不是配置了什么。** `.mcp.json` 里列出的连接器是**已声明**的。**实际能应答**的连接器才是**已连接**。混淆这两者会毁掉信任。对每一个本插件用到的连接器：

- 若能测（能调一个简单的 MCP 工具例如 list 或 search），成功再报 ✓
- 若不能测（这里没法 probe），报 ⚪「已配置但未验证 —— 打开 MCP 设置确认」并给一行怎么确认
- **绝不**因为配置里声明了就报 ✓

**国家法律法规数据库**（`flk.npc.gov.cn`）是免费公开源 —— 始终可用，无需 MCP 连接器。默认作为法条现行状态核验的**首选一级源**。

对未连接的连接器，告诉用户怎么连。范例：「[付费法规数据库] 未连接。企业版应用中：设置 → 连接器 → 新增 → [提供商] → 登录。Claude Code 中：把提供商的 MCP 加进配置或用 `/mcp`。本插件没它也能用 —— 国家法律法规数据库 + 网信办 + 手工粘贴已能覆盖核心场景 —— 连上会加解读富化与告警导入。」

按下面的形式报告：

> - ✓ [集成] —— 已连接（测试通过）
> - ⚪ [集成] —— 已配置但未验证。打开 MCP 设置确认。
> - ✗ [集成] —— 未找到。[功能] 回退到 [手工替代]。[怎么连。]

**你不用全接。核心功能只靠国家法律法规数据库 + 免费一级源 + 文件访问就能用。** 付费源加解读；手工粘贴始终可用。你之后接上了，重跑 `/regulatory-legal-cn:cold-start-interview --check-integrations`。

#### 写入配置

在档案第一节之后立刻写入 `## 谁在用`、`## 可用集成`、`## 输出` 三节，按模板。`## 输出` 已存在的情况下 —— 合并，让工作产品头部按角色变。

#### 执业环境

> 再快问一个，进入监控清单之前：
>
> 执业环境是什么？（影响缺口响应流程与升级项 —— 公司法务问 GC / 分管副总裁路由；律所问审批链；诊所路由到指导律师。）
>
> - **公司法务部（中大型）** —— 我会问审批链、合规负责人、业务接口人、GC / 法总是谁、什么情况上到业务层。
> - **律所（个人 / 小团队）** —— 我会跳过多层审批问题，改问什么时候需要外部律师会签或同事二看。
> - **律所（中型 / 大型）** —— 我会问审批链、计费门槛、以及你之上谁签字。
> - **政府 / 法律援助 / 高校诊所 / 法律工作委员会** —— 我会问监督结构以及执业限制。
> - **不属于以上任何一类** —— 用自己的话说，我不套模板。

**不套模板的实务。** 如果实务不符合以上分类（涉外仲裁、公共国际法、单一涉刑辩护、学术顾问、公益法律工作、少数民族地区法律援助、涉军法律工作、海事等等标准类别忽略掉的），提供：「看起来你的实务不在我常用的分类里。用你自己的话讲讲 —— 做什么、为谁做、什么司法管辖 / 什么场合、日常样子 —— 我按这个建档，不硬塞进不合的框。我会跳过或改写不适用的问题。」按自由描述建档，标注模板哪些字段是填了 / 改了 / 空着不适用。**硬塞进不合的框比留白差。**

按执业环境塑造缺口响应流程与升级路径：

- **公司法务部：** 问升级矩阵、GC / 法总、以及什么情况上到业务层。
- **律所（个人 / 小团队）：** 跳过多层审批。重构提问：不问「谁批一份重大缺口响应」，而问「什么情况你会请外部律师或同事二看」。档案里的升级字段映射为「咨询」而不是「路由审批」。
- **律所（中型 / 大型）：** 问审批链、计费门槛、你之上谁签字。
- **政府 / 法律援助 / 高校诊所：** 用该场合的监督链（指导律师、主任、督导委员会）。保留结构，替换角色。

然后用大白话问升级问题：

> 「一次审查发现的事项**需要有人比你更资深来签字** —— 一个需要公司层面决定的制度缺口、一封代表公司表明立场的意见函、一次改写实务的重大监管变化、或一件超出你权限的决定 —— **交给谁？** 给我一个名字或职位（GC、CCO、你的上级），或者说『我自己决定』。这是插件判断『你能处理』还是『需要通知 [X]』的依据。」

在档案 `## 谁在用` 一节记录执业环境。

### Part 1：监控清单（2-3 分钟）

*（喂给 `/regulatory-legal-cn:reg-feed-watcher` 与 `reg-change-monitor` agent —— **信息源只从该清单上的机关拉取**。不在清单上的机关对插件是不可见的，除非通过 `/regulatory-legal-cn:policy-diff` 手工粘贴进来。）*

**[公司名] 是做什么的？** 这是最重要的**单一上下文** —— SaaS 厂商、硬件分销商、跨境电商、金融科技，四份 playbook 完全不同。**不用打字：**粘贴公司官网、"关于我们"、年报、上市披露、招股书都行，我从里面抽。或者给我一句话：卖什么、卖给谁、怎么卖（直销 / 渠道 / 平台 / 订阅制）。这也让我判断哪些监管机关**在你的监控清单里都不合理**。

> 在我问监控清单之前：你已有的监控清单、法规跟踪表、往次缺口分析备忘我可以读吗？粘贴内容、给我个文件路径，或者说「没有」，我一条一条问。若你给了一份，我从里面**抽取**监管机关和重要性判据 —— 不让你再列一遍。

若没有：

- **哪些机关？** 说出名字。（网信办、市监总局、工信部、央行、证监会、金融监督管理总局、药监局、卫健委、教育部、广电总局、地方司法局 / 网信办、行业协会 / 自律组织？）
  *覆盖说明：本插件对**国家法律法规数据库**（`flk.npc.gov.cn`）有直接结构化拉取支持；对**网信办 / 工信部 / 市监总局 / 最高法 / 央行 / 证监会**等一级源支持网页变更检测。**地方监管**通过用户提供的 URL 或手工录入 —— 无标准 feed。**部分行业协会**（如中国互联网协会）自律规范也可加入监控。付费专业数据库（北大法宝、威科先行、法信）用作解读富化与法条状态核验。*
- **为什么盯每一个？**（「我们做个保业务，网信办不用说」vs.「因为去年被通报过所以要盯 App 通报页」）
- **可能应盯但没盯的？** —— 例如：数据出境企业但只盯了国家一级，没盯注册地省级网信办？

**若用户没上传监控清单或既往缺口分析：** 本节末尾提议：「要不要把这份监控清单整理成一份可以分发、维护的独立备忘？和我刚才抓到的一样 —— 你的机关、盯每一个的理由、对应的信息源 —— 格式方便传阅或交接新人。」

### Part 2：重要性阈值（**关键问题**）（3-4 分钟）

*（喂给 `/regulatory-legal-cn:reg-feed-watcher` 与 `reg-change-monitor` agent —— **重要性阈值是过滤器**，决定一条新动态**立即通知**、**进周摘要**、还是**根本不出现**。校准错了 = 摘要噪音大到你不再读。）*

举例走一遍。对每一条，你想立刻知道、放周摘要、还是根本不出现？

- 你监控清单上的机关**正式发布**一部法律 / 行政法规 / 部门规章
- **征求意见稿**（公开征求意见 —— 意见窗口开放）
- **同业**受到监管行政处罚 / 立案
- **不同业**但**做类似业务**的受到监管行政处罚
- 部委领导讲话释放监管方向信号
- 部委官网**解读文章**或**答记者问**
- **无认错**的和解 / 承诺整改
- **规范性文件**（通知 / 意见 / 指引 —— 非强制法源但监管认可度高）
- **App 通报 / 违法违规通报**（网信办、工信部）
- **司法解释**（最高法 / 最高检）
- **指导性案例 / 参考案例**

这就是重要性阈值。**不同公司校准差异极大** —— 被通报过的公司在意讲话；机关从没听说过你的公司可以忽略讲话。

**若用户没上传阈值判据：** 本节末尾提议：「要不要把这份重要性判据整理成一份独立文档？和我刚才抓到的一样 —— 立即 / 摘要 / 参考三档 + 你给的例子 —— 团队按同一个校准读。」

### Part 3：制度库（2-3 分钟）

*（喂给 `/regulatory-legal-cn:policy-diff` 与 `/regulatory-legal-cn:gaps` —— **每条新动态都会与本库做 diff**，找到它触及的制度和责任人。）*

> 我问之前：你已有制度库索引吗？—— 一份表、一个目录、一个 wiki 页面，把每份制度映射到责任人？粘贴内容、给我个文件路径，或者说「没有」，我一条条问。若给了，我**导入**，不让你再从记忆里重建。

若没有：

> 告诉我制度放在哪。我索引一下，之后一条法规改了，我能告诉你影响到你的哪些制度。

- **制度放在哪？**（企业网盘 / SharePoint / 飞书云文档 / 语雀 / 内部 wiki）
- **有命名规范或目录吗？还是散文件？**
- **每份制度谁负责？**（用于把缺口路由给正确的责任部门 / 责任人）

**若用户没上传制度库索引：** 本节末尾提议：「要不要把这份整理成一份可分发的独立**制度责任索引**？和我刚才抓到的一样，格式让新到任的合规同事第一天就能看清整个格局。」

### Part 4：信息源（2-3 分钟）

**免费源是基线** —— 每个团队不论订阅状态都能有基础监控。
**付费源加解读** —— 有的团队用来加深。

**Step 1：为已列监控清单映射免费源**

国家法律法规数据库（`flk.npc.gov.cn`）是**现行有效性核验的首选一级源** —— 用它作为任何监管机关的法条状态核验默认渠道。

监控清单上的每一个机关，都尝试映射到 `references/source-catalog-cn.md` 中的对应源。中国监管网站**极少提供 RSS**，多数用网页变更检测（列表页快照对比 + 站内检索按日期过滤）；单源间隔**不低于 6 小时**，遵守目标站点服务条款与 `robots.txt`。

若某机关没有可用的免费源（例如小的地方司法局）：**标记这一点**，问用户当前怎么跟这个机关，记录**手工录入回退**（见下）。

**Step 2：问付费订阅（追加，非必需）**

- 北大法宝 / 威科先行 / 法信 MCP？—— 已订阅并且已连？
- 律所公众号 / IAPP 中国专栏 / 行业解读 —— 二级源？

若有：作为一级源的**解读富化**层。若没：免费源已足够开跑。

**Step 3：手工录入回退**

> 若你从法律媒体、行业协会通报、律所公众号、外部律师看到了什么想跑一遍系统 —— 粘进来就行，我会对你的制度做 diff、追踪缺口。**不需要 feed 订阅就能用。**

在配置中记录：手工录入已启用。

**Step 4：征求意见追踪** *（喂给 `/regulatory-legal-cn:comments` —— 征求意见日历记录截止日，意见窗口开放时浮现「决策」提示。）*

> 我看到监控清单上的机关发布**征求意见稿**时，会**自动登记意见截止日**。要不要标记这些让你决定是否提交意见？

若是：意见追踪已启用。在配置中记录**默认意见决策责任人**。

- 来自 [指定机关] 的正式发布法律 / 行政法规 / 部门规章

- 数据出境（若适用）：数据出境安全评估、标准合同、认证相关的任何新规

**值得关注（周摘要）：**

**参考（月度汇总或不推送）：**
- 官员讲话、部委例行答问、学术评论

## 失败模式

- 不写 YAML 样式的「配置文件」—— 档案是**可读散文 + 表格**
- 不跳过样本 / 已有清单 —— 访谈给出「用户认为的 playbook」，文件给出「实际生效的 playbook」，两者都重要
- **不写泛化清单** —— 用户答「合理的市场做法」时要追问**具体数字 / 具体机关 / 具体制度名**
- 不承诺本插件没有的技能能力
- 不在每次会话都跑访谈 —— **先检查档案存在与否**
