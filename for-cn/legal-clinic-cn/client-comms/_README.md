# client-comms/ —— 按案件的沟通日志

每案一个文件夹。文件夹内是运行中的 `log.md`，跟踪每次受援人接触 —— 来 / 去，跨电话、微信、邮件、短信、信函、面谈。由 `/legal-clinic-cn:client-comms-log` 产出并追加。

## 结构

```
client-comms/
├── _README.md              # 本文件
└── [case-id]/
    └── log.md              # 只增不改的运行日志
```

## slug

与该案件在其它位置使用的 ID 一致（接待记录、`deadlines.yaml` 的 case_id）。一案 = 一文件夹。

## 为什么存在

- **执业风险管理** —— 「我们在 Y 日告知了 X」需要有记录。指导老师承担学生工作的监督责任。
- **交接连续性** —— 接手学生可读日志，不必重问受援人。
- **模式可见性** —— 一个月内 5 次未回复的电话是监督信号。
- **案卷完整性** —— 高校诊所有维护完整案卷的义务；沟通历史是其中一部分。

## 条目样式

```markdown
## [YYYY-MM-DD HH:MM] —— [来 / 去] —— [方式]

**谁（学生）：** [name]
**谁（受援人一侧）：** [受援人姓名，或若来自对方 / 亲属注为「第三方：xxx」]
**时长 / 长度：** [10 分钟通话 | 3 段微信 | 2 页信]

**摘要：**
[发生了什么，2-4 句。重要时含实质与语气。]

**待办：**
- [学生欠受援人的（含期限）]
- [受援人欠学生的（含预期时点）]

**跟进日期：** [如适用]

**备注：**
[值得记但不属以上的 —— 使用的方言、观察到的家庭动态、受援人焦虑程度]
```

## 本文件夹**不**包含什么

- 实质案件分析（在接待 / memo / status 文件里）
- 文书草稿（在其它案件目录里）
- 律师专有笔记（在诊所内部案件笔记里）

沟通日志是**接触事实**记录，不是法律工作成果。实质放日志外，接触事实放日志。

## 保密提醒

日志内容是受援人材料的一部分，散布到诊所之外可能违反保密义务。**学生禁止在私人聊天里转贴。** 存放遵循诊所案卷保密要求。

## 留存

只增不改。绝不改历史条目 —— 有错就写新条目引用并更正。什么时候说了什么的记录是案卷的一部分；改写历史等于毁掉本日志的意义。
