# /escalation-flagger

按档案的升级矩阵点名审批人，并起草请示，免得你在下午 5 点还在写「有点事，能聊几分钟吗」。

## 说明

1. **加载 `~/.claude/plugins/config/claude-for-legal-cn/commercial-legal-cn/CLAUDE.md`** → 升级路径章节。若缺失，说出来 —— 执业档案需要补充。

2. **界定问题：** 金额阈值 / 条款偏差 / 自动升级触发 / 商务决策。

3. **对照矩阵，点名审批人。** 具体到人或角色，不是「法务领导」。

4. **按下方模板起草请示：** 合同怎么说、playbook 怎么说、选项与建议、期望决定时限。

5. **不发送。** 起草、展示，由律师发。

## 示例

```
/commercial-legal-cn:escalation-flagger
某供应商的技术服务合同责任上限约定「不承担任何责任」—— 谁批，怎么说？
```

```
/commercial-legal-cn:escalation-flagger
引用：某供应商-审查备忘录.md
问题：第 8.2 条免责范围
```

## 事项上下文

**事项上下文。** 检查执业档案 CLAUDE.md 的 `## 事项工作区`。若 `Enabled` 为 `✗`（公司法务用户默认），跳过本段。若已开启且无活动事项，问：「这是哪个事项的？运行 `/commercial-legal-cn:matter-workspace switch <slug>`，或说 `practice-level`。」加载活动事项的 `matter.md`。输出写入事项文件夹。除非 `Cross-matter context` 为 `on`，绝不读取其他事项的文件。

## 目的

每个法务团队都有升级矩阵，无论明写还是心照。本技能读明写的那份（在档案），把合同问题对照矩阵，点名审批人，起草请示，让律师不再写「有点事，能聊几分钟吗」的消息。

## 加载矩阵

**哪一侧？** 对照矩阵前先判断我方立场。通常明显：相对方是提供货或服务的供应商，我方是采购方；相对方是买我方产品的客户，我方是供应方。不明显就问。读匹配的 playbook 小节（`### 采购方 playbook` 或 `### 供应方 playbook`）来评估条款是在退让范围内还是触发自动升级 —— 同一条款在两侧的处理可能是「可以」与「绝不」的差别。请示中注明适用了哪一侧，让审批人知道。

读 `~/.claude/plugins/config/claude-for-legal-cn/commercial-legal-cn/CLAUDE.md` → `## 升级路径`。若缺失或含糊，说出来 —— 冷启动访谈应当已经采集，若未采集则档案需要补充。

期望结构：

| 谁可批 | 无需升级的门槛 | 升级给 | 渠道 |
|---|---|---|---|
| 法务专员 | 标准条款，合同额 < 50 万 | 法务经理 | 企业微信 |
| 法务经理 | 非标但在退让范围内，合同额 < 500 万 | 法务总监 | 企业微信 / 邮件 |
| 法务总监 | 其余 | 总法律顾问 / CFO / 董事会 | 会议 |

加上**自动升级触发** —— 无论金额都要升级的项。典型：责任无上限、知识产权归属给对方、数据出境、涉刑/监管风险、命中「绝不接受」清单。

## 工作流

### 第 1 步：界定问题

被升级的是什么？

- **金额阈值：** 合同额超出某人的审批权
- **条款偏差：** 条款在退让范围外 —— 需要更资深的人决定是否接受
- **自动升级触发：** 命中「无论金额都升级」清单
- **商务决策：** 不是法律问题 —— 需要业务负责人，不是法务领导

**不要把本来就 OK 的东西也升级。** 若条款在档案的退让范围内，不需要往上走。

### 第 2 步：对照矩阵

```
问题是不是自动触发？
  → 是：升级给触发对应的审批人
  → 否：继续

合同额是不是超出审查人的门槛？
  → 是：升级给该金额层级有权限的人
  → 否：继续

条款偏差是不是超出所有文书退让？
  → 是：升级给能批非标条款的人
  → 否：审查人可自行批准 —— 不需升级
```

### 第 3 步：点名审批人

具体到人。不是「升级给法务领导」—— 从档案里点名。若矩阵没有覆盖此情形，说出来：「升级矩阵没覆盖 [情形]。建议问 [法务总监姓名] 谁负责这条。」

### 第 4 步：起草请示

审批人应当仅凭这条消息就能做决定 —— 不需要「让我打开合同看看」。

```markdown
[草稿头 —— 按档案 ## 输出头部]

**升级给：** [姓名]
**渠道：** [企业微信 #群名 / 钉钉 / 飞书 / 邮件 / 会议 —— 按档案]
**紧急度：** [截止日 —— 若有]
**适用侧：** [采购方 / 供应方]

---

您好 [姓名] ——

需要您就 [相对方] 的 [协议类型] 决策一下。[一句交易背景。]

**问题：** [白话，一段。对方想要什么、为什么超出我们标准、真实的风险是什么。]

**合同原文：**
> "[精确摘录]"

**我们 playbook 怎么说：** [从档案引用]

**依据：** [法条 —— 如民法典第 585 条违约金调减、第 506 条免责边界、个保法第 21 条委托处理必备]

**选项：**
1. **接受** —— [一行说明为何可能可以]
2. **反驳，改为：**「[拟议对案措辞]」—— [一行说明对方可能反应]
3. **放弃** —— [一行说明是否现实]

**我的建议：** [选哪个，简述为什么]

**需要决定的时限：** [日期，若有]

[链接：完整审查备忘录]
```

### 第 5 步：记录升级

若团队用工单系统或合同管理系统的审批流，登记。若没有，在审查备忘录里注明升级已发、发给谁、什么时候。下一个读备忘录的人应该看到状态。

## 校准：拿不准就升级 + 附说明

一次不必要升级的代价大约是审批人 30 秒 —— 他们读一下说「继续」，记录里显示他们看过了。**漏一次必要升级的代价是签了没批的条款，那是单向门。代价不对称。拿不准就升级。**

什么算值得升级由档案决定，不是本技能。查 playbook 立场、退让、以及「无论金额都升级」清单：

- **清楚在退让内：** 不用升级。
- **清楚在退让外，或在自动升级清单上：** 升级。
- **不确定 —— 条款含糊、新颖、勉强算在退让内但站不太住脚：** 也升级，并明确说出不确定的地方。起草里标出审批人需要决定的具体问题，以及本技能无法自信落入退让的原因。审批人来收窄；本技能不代替判断。

不要因为「过度升级会训练审批人不认真看」而压住升级。那是审批人体验问题，律师去调整档案里的阈值来解决，不是本技能通过对自己不确定的条款做主观判断来解决。

若遇到 playbook 未覆盖的问题类型，不要猜阈值 —— 问审查律师这一类问题该不该升级，并提议把答案记入档案，让今后的审查一致。

## 本 skill 不做的事

- 不批准任何东西。它路由。
- 不代选选项。起草包含建议，审批人来选。
- 不发送升级消息 —— 它起草。律师读后发送。

## 质量自检（本技能转换说明）

- **A 级直转：** 五步工作流（界定 → 匹配 → 点名 → 起草 → 记录）、拿不准就升级的校准、起草模板结构、不代批准的边界 —— 方法论层原样保留。
- **B 级大改：** 升级矩阵示例金额改为人民币阈值（50 万 / 500 万）；审批人角色改为中国法务体系（法务专员 / 法务经理 / 法务总监 / 总法律顾问）；渠道改为企业微信 / 钉钉 / 飞书；请示模板加「适用侧」「依据（法条）」字段；自动升级触发新增「数据出境」「涉刑/监管风险」两项 —— 中国实务高频。
- **C 级删除：** 无英美法特有概念残留；privilege 头部替换为草稿头。
- **D 级新增：** 无独立新增。
