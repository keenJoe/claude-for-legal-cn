# /dpa-review

1. 读取 `~/.claude/plugins/config/claude-for-legal-cn/privacy-legal-cn/CLAUDE.md` → 委托处理协议立场。存在 `[待填写]` 就停下并引导 setup。
2. 拿到协议。判定方向：我方是**受托人**（客户发来他们的协议）还是**委托方**（我们发协议给供应商）？模糊就问。
3. 按下方流程逐条审查——对照 playbook 对应一侧。
4. 做隐私政策一致性检查。
5. 输出：审查备忘 + 建议修订。按团队风格保存。

```
/privacy-legal-cn:dpa-review 供应商协议.pdf
```

# 委托处理协议审查

## 事项上下文

**事项上下文。** 检查执业档案 `## 事项工作区`。`启用` 为 `✗`（公司法务默认）时跳过本段。若启用且无活动事项，问：「这是哪个事项？运行 `/privacy-legal-cn:matter-workspace switch <slug>` 或说 `执业级`。」加载活动事项的 `matter.md`。输出写到事项文件夹。除非 `跨事项上下文` 为 `on`，不读另一事项的文件。

---

## 目的

委托处理协议在中国法下有两种流向，审查几乎相反。客户发来他们的协议时，我们守护运营弹性;我们发给供应商时，我们保护数据（我方及我方用户的）。两种审查从同一份 `~/.claude/plugins/config/claude-for-legal-cn/privacy-legal-cn/CLAUDE.md` playbook 读，但读的是相反行。

## 首先：哪个方向？

任何事之前先确定：

- **我方是受托人** → 客户在向我们发他们的协议 → 读 `## 委托处理协议立场` → 「我方作为受托人」表
- **我方是委托方（个人信息处理者）** → 我们在给供应商发协议（或审查他们的） → 读 「我方作为委托方」表

不明就问。搞错这个会把每一条建议都反过来。

**易混淆的另一情形——独立处理者 vs 受托人：** 若相对方虽为「供应商」但自行决定处理目的和方式（不受我方指示、有独立处理决策权），他们是**独立处理者**而非受托人。此时不是委托处理关系，是「向他人提供」（个保法第 23 条），需单独同意与独立协议。识别信号：他们要用数据训练自家模型、开展自家业务、按自己需要保留超过服务所需时间——这些都指向独立处理者。识别错误会导致合规义务错位（独立处理者不受第 21 条委托处理约束，但触发第 23 条提供规则）。

## 法域假设

本审查假定档案里配置的法域范围（默认中国境内、个保法/数安法/网安法）。若委托方、受托人或个人信息主体在不同法域，规则不同——见跨法域识别。

## 加载相对方 / 处理活动的过往上下文

审查前，扫输出目录里针对此相对方或此处理活动的既往工作。读 `## 输出` 拿路径。看：

- **同相对方 / 同处理活动的过往 `use-case-triage` 结果** —— 分流评的风险等级与条件是本次审查应尊重或明确背离的起点。
- **过往 `pia-generation` 输出** —— PIIA 可能标出协议需实现的风险缓解。
- **同相对方过往 `dpa-review` 输出** —— 早前审查设定了「可接受、被标红、已定」的期望。新审查静默否定旧审查会侵蚀工作产品的可信度。

找到过往，就在审查里引用：

> 「过往分流（[日期]）评为 [风险等级] 并有条件（[X]）。本审查与该结论一致。」——或——
> 「过往分流（[日期]）评为 [风险等级]。本审查偏离该结论，因为 [新事实 / 范围不同 / 改变判断的合同条款]。」

**从上游承接严重度作为下限**——见执业档案 `## 共同护栏` 的技能间下限规则。分流评为 🔴 的处理活动不能在协议审查里静默降为 🟢；任何降级都要写明并解释。

未找到过往工作（新相对方 / 新活动）就明说——「输出目录未找到此相对方的过往分流或 PIIA」——让审查律师知道检查跑过了。

## 加载 playbook

读 `~/.claude/plugins/config/claude-for-legal-cn/privacy-legal-cn/CLAUDE.md` → `## Playbook → 委托处理协议立场`。同时读 `## 隐私政策承诺` —— 签的协议不能承诺隐私政策没覆盖的东西。

## 行业专门规定叠加（先问，再逐条走）

逐条审查前先答：**流经此协议的数据是否含行业专门规定所约束的类别？** 个保法与出境规则是基线；行业专门规定通常在其之上叠加实体义务。一份看似满足个保法的协议仍可能在金融/医疗/未成年人条线上是空白，且这些条线的相对方（金融机构、医疗健康 App、儿童教育产品）会注意到。

> **按活动叠加的行业规定——先问：**
>
> 本协议处理是否触及：
> - **金融账户、征信数据、支付信息**（金融监管总局、人民银行规则；征信业管理条例）？如是，协议还需：金融数据分类分级说明；参照《金融业金融信息保护技术规范》等国标的安全措施说明；符合征信业务规则的数据使用限制。
> - **医疗健康数据**（卫健委规则；健康医疗大数据管理办法）？如是，协议还需：符合《信息安全技术 健康医疗数据安全指南》（GB/T 39725）的处理规则;数据脱敏/去标识化标准说明。
> - **不满 14 周岁未成年人个人信息**（个保法第 31 条 +《儿童个人信息网络保护规定》）？如是，协议还需：**监护人**同意的取得机制、儿童个人信息处理规则、专项安全评估。
> - **汽车数据、地图数据等重要数据**（汽车数据安全规定；测绘法）？如是，协议需明确处理是否触及重要数据认定与本地化义务。
> - **App / SDK 收集使用个人信息**（网信办、工信部通报口径；GB/T 41391 App 收集个人信息基本要求）？

任一命中，援引具体规定并把行业缺口在关键问题清单里与个保法一起标。

无行业规定叠加时明确写「未识别行业专门规定约束的数据类别；行业叠加不适用」，让审查律师看到检查跑过而不是被跳过。

## 逐条审查

### 核心条款（每份协议都要过）

**个保法第 21 条列出委托处理协议的必备条款**——处理目的、期限、处理方式、个人信息种类、保护措施、双方权利义务。缺一即为**必备条款不完整**，是自动 🟠 甚至 🔴（法定必备）。审查从这里开始，再看具体数字与实质立场（时限、赔偿口径、审计频率），后者从 CLAUDE.md `## Playbook` 拉。

> **不静默补齐。** 检索规则的返回稀少时，报告已找到的然后停下。不要在未征询下用网络检索或模型知识补齐。
>
> **来源标注分层。** 每条引用标来源——个保法条文、行业规定、国标推荐、监管指引。模型知识引用用三层而非笼统「待核验」：
> - `[已核验]` —— 已核对稳定的成文法条文（如个保法第 21 条、第 55-57 条）。仍应送审前核验，优先级低。
> - `[模型知识 —— 待核验]` —— 模型知识里可信的引用（具体规定、监管指引、案例、阈值、生效日）。
> - `[精确引用 —— 必核验]` —— 精确到条款字号或段号的引用最高伪造风险，务必对一手来源核验。

| 条款 | 找什么 | Playbook 字段 | 常见争点 |
|---|---|---|---|
| **角色定性** | 明确委托方（处理者）/ 受托人；且与实际相符 | — | 相对方把关系标为「独立处理者 / 联合处理者」但事实上按我方指示 |
| **处理目的、期限、方式、信息种类**（第 21 条必备） | 具体、书面、不含开放式扩容（「以及相关目的」） | — | 开放式扩容 |
| **保护措施**（第 21 条必备） | 附件引具体控制或国标（如 GB/T 22239 等保、GB/T 35273 个人信息安全规范） | 保护措施 | 「适当技术和组织措施」而无附件 = 空承诺 |
| **转委托**（第 21 条） | 必须**事先书面同意**方可转委托 | 转委托 | 相对方无条件转委托权 |
| **安全事件通知** | 明确触发点（发现 vs 确认）、时限 | 通知时限 | 「及时」太模糊；应结合我方履行第 57 条通知义务倒推 |
| **审计权** | 方式（报告 vs 现场）、频率、通知期、费用分摊 | 审计权 | 短通知的现场审计 |
| **数据存储地与出境** | 存储地披露；出境情形指向合规路径（第 38-43 条） | 数据位置 | 未披露、无出境合规安排 |
| **期满或解除后返还或删除** | 时限、证明、备份除外 | 删除 | 「商业合理时间」= 空 |
| **数据责任** | 服务协议上限内 vs 单独设定；除外情形 | 数据责任 | 责任无上限 = 生存性风险（民法典 506 条：故意与重大过失免责无效，但常规责任仍可上限） |
| **个人权利实现路径** | 受托人接到个人请求时的路由；权利实现协作义务 | — | 未约定，导致我方无法响应第 44-45 条请求 |

### 我方作为受托人：防守性审查

客户协议试图把运营负担推给我们。逐条对照 playbook。客户所要求超出 playbook 时，先争到我方标准立场（配置 CLAUDE.md），准备退让到可接受立场。

| 条款 | 风险 | 检索 / playbook 查询 |
|---|---|---|
| 转委托否决权（逐次批准） | 无法在客户级别外新增基础设施 | 应用 playbook 转委托立场 |
| 短通知的现场审计 | 规模上不可行 | 应用 playbook 审计立场 |
| 激进的安全事件通知时限 | 常在还没搞清发生什么时就要通知 | 参照第 57 条我方通知义务的技术可行性；对照 playbook |
| 硬性数据本地化（单一机房） | 与架构不匹配 | 应用 playbook 存储位置立场;确认能承诺什么 |
| 受托人责任无上限 | 生存性风险 | 应用 playbook 数据责任立场;注意民法典 506 条底线 |
| 客户可发出有约束力的「指令」 | 开放式运营控制 | 定义指令为「协议中书面记录或经书面同意的」 |
| 极短删除时限 | 备份与日志保留使即时删除不可能 | 应用 playbook 删除立场;记录备份轮换除外 |

### 我方作为委托方：保护性审查

供应商协议试图什么都不给。逐条对照 playbook。

| 条款 | 缺口 | 检索 / playbook 查询 |
|---|---|---|
| 无转委托清单 | 不知道谁在碰我方数据 | 要求公开当前清单 + 事先通知 |
| 「行业标准安全」 | 什么都没说 | 要求附件列具体控制或引用国标（等保二 / 三级；GB/T 35273） |
| 无安全事件通知时限 | 想何时告知就何时告知 | 要求 playbook 时限；参照第 57 条通知义务倒推 |
| 完全无审计权 | 什么都验证不了 | 至少要独立审计报告 |
| 供应商可将数据用于「服务改进」 | 潜在用于训练其模型的风险 | 删除；处理仅限为我方提供服务 |
| 无出境合规安排 | 出境路径未识别 | **判定路径**：若数据出境，走安全评估申报 / 保护认证 / 标准合同备案 / 豁免的哪条（个保法 38-43 条 + 2024 跨境规定）。要求相对方承担对应义务 |
| 无删除承诺 | 数据永生 | 要求 playbook 删除立场 + 请求时提供证明 |
| 无数据本地化承诺 | 隐性出境 | 要求境内存储承诺，或触发出境路径判定 |

## 一致性检查：隐私政策

签的协议不能承诺隐私政策没覆盖的东西，反之亦然。

- 若协议承诺仅按 X、Y、Z 目的处理——隐私政策列了这些目的吗？
- 若隐私政策说「不向第三方提供个人信息」——协议里有没有条款事实上就是提供？（个保法第 23 条：向他人提供须单独同意）
- 若隐私政策命名了具体的第三方类别——协议的（转）委托方清单匹配吗？

标出不一致。通常是隐私政策旧了、不是协议错，但总要有人改一边。

## 修订颗粒度

**以最小可能颗粒度编辑。** 红线是谈判文物，不是重写。整条替换发信号「我们扔了你的起草」——攻击性、迫使相对方重读整条、丢弃相对方起草里本来没问题的部分。手术式红线——划掉一个词、插入一个短语、拆一个子条款——传递「我方有具体诉求」，读、理解、接受都更快。

默认走能达到 playbook 立场的最小编辑：
- 先换**词**（如「一周」→「三个工作日」）
- 再换**短语**（「及时通知」→「发现后 24 小时内书面通知」）
- 再重构**子条款**
- 再替换**整句**
- 只有相对方版本离你立场太远以至手术编辑比重写更难读时才替换**整条**——且要在附函说明：「§8.2 我们做了整条替换而非留痕修订，因为改动幅度较大。愿意逐点走一遍。」

疑惑时选更小。收到手术式红线的客户相信你仔细读了；收到整条替换的客户会怀疑你根本读没读。

## 数据出境注意

若协议涉及个人信息出境（境外接收方；或境内数据境外可访问；或境外总部访问境内系统），**必须**判定合规路径：

- CIIO 向境外提供个人信息或重要数据 → **强制安全评估申报**
- 非 CIIO 累计向境外提供 100 万人以上一般个人信息 或 1 万人以上敏感个人信息 → **强制安全评估申报**
- 非上述情形 → **标准合同备案**（省级网信办，10 个工作日内）或**保护认证**或**豁免**（2024《促进和规范数据跨境流动规定》七情形）

协议缺出境合规安排且存在出境情形 → **🔴**。协议还应约束境外接收方（个保法第 39 条：告知境外接收方名称、联系方式、处理目的与方式、个人信息种类、行使权利的方式和程序），单独同意的取得（第 39 条，除非命中「订立、履行个人作为一方的合同所必需」或「按依法制定的劳动规章制度和依法签订的集体合同实施跨境人力资源管理所必需」的豁免）。

详细路径判定参见跨境专项技能（如已装配 `cross-border-transfer` 技能）。

## 门：签署协议

审查协议是研究。**签署**——或指示他人代为签署——才是承担后果的行为。

**签署前**（含返回已签版本、在相对方平台上同意自动执行、指示签署人签署）：读 `## 谁在用`。若角色是非律师：

> 签署委托处理协议是法律行为——它把公司绑定到具体的个人信息保护义务，义务向监管和个人流转。你已与律师复核过了吗？是则继续。否则以下一页纸交律师：
>
> [生成一页纸摘要：相对方、方向（我方是受托人 / 委托方）、偏离 playbook 的条款及其解决方式、任何未定的退让决策、签署前三个要问律师的问题]。

未获明确「是」不得越过此门。

按执业档案 `## 输出` 用下一步决策树收尾。把选项定制到本技能刚产出的东西——五个默认分支（起草 X、上报、补事实、观望、别的）是起点不是锁定。

## 本技能不做的事

- 不从零起草协议。答案是「用我方模板」时，从种子文件路径拉模板。
- 不做完整的出境影响评估——它标出需要什么时候做。
- 不决定超出退让方案的条款是否接受。它按上报表路由。

## 跨法域提示
