# /flashcards

1. 读取 `~/.claude/plugins/config/claude-for-legal-cn/law-student-cn/CLAUDE.md` → 当前课程、弱项科目、大纲位置、口诀偏好。
2. 应用下面的框架。
3. 按参数路由：
   - `--generate`：从来源（大纲路径、笔记、教材）按写卡规则生成卡。写入 `~/.claude/plugins/config/claude-for-legal-cn/law-student-cn/flashcards/[科目]/cards.md`。
   - `--drill`（默认）：优先到期卡 + 新卡；显示 Q，等答案，显示 A，做自评，更新桶 + 下次复习日期。
   - `--review`：按桶浏览卡组。
   - `--stats`：进度快照；把卡在低桶的标出来做口头带练。
   - `--session <n>`：专项 N 张卡训练，按往次错卡 + 到期卡加权；结果追加到 `study-plan.yaml` 的 `session_history`。
4. 应用可信度纪律：从未附来源的知识生成的卡一律标 `[VERIFY]`。

## 真实纠纷识别

如果学生问的问题听起来像**真实情况** —— 他的租房合同、他被开的罚单、他家里的生意、朋友被抓、真实的金额、真实的截止日、真实的当事人姓名 —— 停下。

> 「这听起来像真实情况，不是练习假设的案例。我不能给法律意见，你现在也还不能 —— 你还不是执业律师。如果这是真的，[当事人] 需要真正的律师：可以联系当地律师协会、法律援助机构、公共法律服务中心，或（涉及金额时）委托执业律师。我很乐意帮你理解其中涉及的法律概念，但那是学习，不是意见。」

警惕：真实姓名、真实地址、真实日期、具体金额、「我房东 / 老板 / 家人 / 朋友」、「我收到一份通知 / 函件 / 罚单」、以天计算的期限。任何一项出现就是触发信号。

## 目的

大纲用来综合；闪卡用来背诵。法考和大多数法学院期末考都在奖励对规则、构成要件、法条位置的快速回忆。这个技能从你的大纲（或笔记、教材摘录）生成卡，用轻量的间隔重复带练，追踪什么记住了、什么还没。

**不是完整的 SRS。** 简单的 Leitner 桶。够用来学、轻到能坚持。想要 Anki 就用 Anki；这个是你在对话里想快速刷一下的工具。

*中国法考背诵有一个独特工具：**口诀**。* 老师和培训机构常把复杂构成要件、法条罗列编成朗朗上口的口诀（如「四要件说」「不作为犯的四条件」）。若学生偏好口诀记忆，写卡时把已有口诀嵌入卡片的**备注**栏，或提示学生自己编。

## 可信度纪律

同其他内容生成型技能：

- 若从你提供的来源（大纲、笔记、教材摘录）生成卡，卡的 Q 和 A 来自该来源。可信。
- 若从我的知识生成而无来源，我给每张我对规则表述不完全有把握的卡标 `[VERIFY: 规则 — 对照来源核验]`。你应在把这张卡当作学习目标锁定前核验。
- 若我对某个领域了解不够，宁少写不硬编。8 张好卡胜于 20 张里有 5 张是错的。

## 模式

参数：`--generate | --drill | --review | --stats | --session <n>`（默认：询问）

### `--session <n>` —— 专项 N 张卡

用户说「练 5 张民法卡」或跑 `/law-student-cn:session 民法 5 --flashcards` 时进入。

- 读取 `~/.claude/plugins/config/claude-for-legal-cn/law-student-cn/study-plan.yaml`（若存在），读该科目的 `session_history`。
- 优先级：以往标错的卡 > 到期卡 > 新卡。
- 按 `--drill` 流程逐张跑 N 张。
- 结束时把结果追加到 `study-plan.yaml` 的 `session_history`：

```yaml
session_history:
  - date: 2026-05-08
    subject: 民法
    type: flashcards
    n_cards: 5
    right: 3
    partial: 1
    wrong: 1
    stuck_topics: [表见代理构成要件]
```

- 若无 `study-plan.yaml`，改写入 `~/.claude/plugins/config/claude-for-legal-cn/law-student-cn/session-history.yaml`。

### `--generate` —— 生成卡

**输入：**
- 科目（课程名或知识点）
- 来源（大纲路径、笔记，或「用我 `~/.claude/plugins/config/claude-for-legal-cn/law-student-cn/CLAUDE.md` 里的已有大纲」）
- 可选：目标张数（默认每次 10-20 张）

**卡片结构：**

```markdown
### 卡 [N]
**Q：** [问题 —— 一张卡一个知识点]
**A：** [答案 —— 规则一至两句]
**来源：** [大纲章节、教材页码、课堂笔记日期]
**桶：** 新
**上次复习：** —
**下次复习：** [今天的日期]
**备注：** [可选 —— 区分点、例外、陷阱、口诀]
```

**写卡规则：**
1. **一张卡一个知识点。** 「过失的构成要件」拆成 4 张，不是 1 张。
2. **正面是问题，不是话题。** 「表见代理」不好。「表见代理的构成要件是什么？」好。
3. **背面是规则，不是段落。** 若答案需要一段，拆成多张卡。
4. **写来源** 便于对练时回查。
5. **口诀入备注。** 若某规则你有惯用口诀（如「刑法三阶层」「无因管理的构成要件」），写在备注栏。

**引用核验。** 从我的知识（而非你粘贴的来源）生成卡时，背面的规则、援引的案例 / 法条均由 AI 生成、未经核实。在把某张卡背熟前，对照大纲、教材、国家法律法规数据库核对。一张被背到滚瓜烂熟的错卡，比没有这张卡更糟。

### `--drill` —— 学习环节

**优先级：**
1. `下次复习 <= 今天` 且 `桶 != 掌握` 的卡
2. 尚未做过的新卡
3. 若无到期无新卡：问用户是否想复习掌握桶的卡（防遗忘）

**每张卡的对练流程：**
1. 显示 Q。等答案。
2. 用户答（或输入「跳过」/「不知道」）
3. 显示 A。
4. 用户自评：`对` / `部分` / `错` / `不知道`
5. 按下表更新桶 + 下次复习：

| 自评 | 桶变化 | 下次复习 |
|---|---|---|
| 对 | 升一桶（新 → 学习 → 复习 → 掌握） | 新 +1 日，学习 +3 日，复习 +7 日，掌握 +21 日 |
| 部分 | 同桶 | +1 日 |
| 错 | 降一桶（复习 → 学习；学习 → 新；新不动） | 今天 +4 小时 |
| 不知道 | 降一桶 | 今天 +4 小时 |

### `--review` —— 浏览卡组

按科目显示全部卡。按桶分组。用于扫一眼卡组里都有什么，手工调整卡内容。

### `--stats` —— 进度快照

按科目：总卡数、桶分布、今日到期、本周复习。把降到 `新` 桶超过两次的卡挑出来 —— 那些是**该用口头对练打通的卡点**（转 `/law-student-cn:socratic-drill`）。闪卡对付「本来就理解、只需背熟」的东西；「理解不透」的应该换工具。

## 与其他技能的集成

- **outline-builder：** 建 / 扩大纲后，提议从新材料生成闪卡
- **socratic-drill：** 若某张卡错了 2 次以上，转 `/law-student-cn:socratic-drill` 做口头对练 —— 闪卡搞不定「你其实没懂」的概念
- **bar-prep-questions：** 法考科目里闪卡表现差的，客观题训练加权

## 存储

```
flashcards/
└── [科目]/
    └── cards.md
```

每科一份文件。卡是 markdown。桶 / 复习元数据内联在每张卡里。不适合超大卡组（>500）但对法学院常规大小够用。

## 这个技能不做的事

- **替代 Anki。** 若你已有 Anki 习惯，保留。这是「你在对话里想快速刷一下、不想切 app」时用的。
- **凑张数硬编卡。** 若我从你的来源只能生成 8 张有把握的，那就 8 张。用 `[VERIFY]` 一堆猜测填数比不填更糟。
- **强制你复习。** 错过复习会累积；技能只显示到期的。做不做你决定。
- **教你规则。** 卡是给已学过的东西加强记忆。若某卡一直错，问题在上游 —— 用 `/law-student-cn:socratic-drill` 或回去重读来源。
