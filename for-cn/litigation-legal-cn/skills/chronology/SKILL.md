# /chronology

1. 读 `~/.claude/plugins/config/claude-for-legal-cn/litigation-legal-cn/matters/[slug]/matter.md` → 代理思路、关键事实。
2. 读 `~/.claude/plugins/config/claude-for-legal-cn/litigation-legal-cn/CLAUDE.md` → 文档存储来源、默认案件文件夹模式。
3. 按下方工作流与参考。
4. 识别来源顺序：本会话用户提供的路径、默认案件文件夹、CLAUDE.md 中声明的来源。
5. 对可读来源：抽取带日期事件。对不可达：在缺口章节记录。
6. 去重，按事件合并来源。
7. 按代理思路标重要性（🔴/🟡/⚪）。
8. 写 `matters/[slug]/chronology.md`（或按参数变体）。
9. 若前版存在：版本号递增，向用户展示 diff 摘要。
10. 定稿前确认：「这是我建的时间线。扫一眼 🔴 —— 有标错的吗？」

# 时间线

## 已披露文书使用限制

处理一批诉讼文书前，问：「这些文书是通过法院调取、举证质证程序、行政协助移送获得的吗？」若是：

- **民诉法与证据规定：** 通过法院调取或证据交换获得的文书受民诉法第 68 条约束（涉及国家秘密、商业秘密和个人隐私的证据应当保密）。用于本案外的其他事项、其他诉讼、商业目的，可能违反证据保密要求，甚至触犯反不正当竞争法第 9 条或个保法。
- **保护令 / 保密协议：** 若法院裁定或双方约定过保密处理，按之执行。
- **境外调取：** 若通过海牙送达/取证公约或商事外交渠道调取，境外规则同样适用。

确认：「本次使用在本案范围内，或已获授权，或文书已合法公开。」未确认则标：「⚠️ 披露文书可能有使用限制。使用前确认合规。」

## 目的

事实按时间顺序发生。时间线是每一段叙事挂靠的脊柱 —— 事实与理由（起诉状）、代理词、和解备忘录、证人准备、证人出庭提纲的骨架。人工造时间线慢；AI 擅长结构化抽取。**代价：垃圾进 垃圾出**。本 skill 从档案声明的来源和用户上传中拉取。

## 模式

本 skill 服务两种执业场景。默认取自 `CLAUDE.md` 的 `## 角色`；用户可按次覆盖。

- **`--matter` 模式（公司法务默认）。** 案件历史为中心。读案件的代理思路与关键事实（从 `matter.md`），从声明的文档存储来源拉取（Google Drive、SharePoint、企业微信文档库、飞书、iManage、CLM —— `CLAUDE.md` `## 可用集成` 声明的），把 `history.md` 视为内部运行日志（决定、保存启动、准备金备忘 —— 有意不进入时间线）。输出以案件为中心：整场争议中什么时候发生了什么，为诉讼准备用途打标。
- **`--documents` 模式（律所律师 / 独立执业默认）。** 举证材料为中心。从档案的 `## Playbook` 读代理思路，然后从举证质证材料、当事人卷宗、编号提交（对方或法院编号）中抽取。输出以举证材料为中心：文书显示了什么，附出处引用，按代理思路打标。

两模式汇入同一输出结构（时间线、🔴/🟡/⚪ 标记、缺口、事实与理由变体）。差别在来源分布与重要性框架。

若 `## 角色` 是 `独立执业` 或 `其他`，默认 `--matter`，但首次跑时提两种模式让用户选。

## 立场框架（重要性标签）

同一事件按我方在证明或反驳请求上不同而重要性不同。读 `CLAUDE.md` `## 立场`（案件覆盖优先于默认）：

- **原告方（进攻框架）** —— 🔴 标记那些**确立**请求要素（责任、因果关系、损失、通知）、**填补**被告拟打开的缺口，或**启动**诉讼时效算数对原告有利的事件。🟡 标记支持请求但可能受质疑的事件。⚪ 是背景。
- **被告方（防御框架）** —— 🔴 标记**打破**请求要素（因果关系断裂、无通知、无依赖）的事件、**打开**诉讼时效或管辖抗辩、或**支持**反诉/抵销（免除、放弃、比例过错）的事件。🟡 是削弱对方叙事的事件。⚪ 是背景。
- **两侧兼有 / 视案件** —— 逐个时间线问用户按哪一侧打标。底层时间线中立；只有重要性读数变。

顶部标注适用框架：`重要性标签按 [原告方 / 被告方] 视角适用。` 生成事实与理由变体时，按立场默认，除非用户另指定。

## 加载上下文

通用：
- 插件档案 `CLAUDE.md` → 代理思路（公司法务：`## 可用集成` 取文档来源；律所：`## Playbook` 中的代理思路与举证质证准备），`## 输出` 取工作产品头，`## 主观法律判断的立场` 取保密标注规则。
- 本案件既有的 `chronology.md`（若存在）。
- 用户在本会话上传的文件或提供的路径。

`--matter` 模式加读：
- `matters/[slug]/matter.md` → 代理思路、关键事实、关键事实（用于重要性标）、关键日期。
- `CLAUDE.md` 默认案件文件夹模式 → 本 slug 的文书在哪。

`--documents` 模式加读：
- 若有 MCP 连接器：eDiscovery 平台（Everlaw / Relativity / DISCO / Aurora）、iManage —— 按人员+日期范围。国内实务少用美式 eDiscovery 平台，更常见是律所文书管理系统 + 云盘。
- 编号清单或举证材料索引（若用户指过路径）。

**利益冲突门槛 —— 不可绕过（`--matter` 模式）。** 构建前检查 `matters/_log.yaml` 是否有 slug。若不在：拒绝并路由到 `matter-intake`。不推进未立案案件。`--documents` 模式（对无 slug 的临时文书集）豁免，但输出视作立案前研究，不作为案件工作产品归档。

## 工作流

### 第 0 步：保密关卡（每次都先跑）

时间线工作从文书拉取。文书常受保密（律师-委托人保密、律师工作产品、共同利益、商业秘密、涉个人信息）—— 公司法务案件材料默认多为此类；举证材料尤其滚动举证或涉商业秘密的批次常含未复核保密材料。从保密文书抽取内容到时间线，之后又外发，可能**破坏**保密（视接收方和依据而定）。放弃保密分析是事实性的 —— 分发前律师签字。

未选保密姿态前本 skill 不抽取：

> 抽取前：来源是否已做保密筛查？
>
> - **A. 全部已清理** —— 你已筛完。我不加保密标注抽取。输出为可对外的姿态；仍标为工作产品。
>
> - **B. 混合或尚未筛查** —— 我抽取并给每条打 `priv` 标：`ok`（明确非保密材料）、`flag`（可能保密 —— 律师-委托人 / 工作产品 / 共同利益 / 商业秘密 / 个人信息）、`review`（来源不明）。加旗条目在输出中可视化标注，且事实与理由变体默认排除。
>
> - **C. 中止 —— 先筛** —— 暂停本 skill。筛完源。回来再跑。

选择记录到时间线头 `privilege_posture: A-cleared | B-mixed | C-aborted`。若 B 或 C，简记理由。

**为何是关卡而非警告：** 警告读一次就忘。关卡把姿态决定推入记录，意味着每份时间线文件自带来源属性 —— 之后读者能看到这些条目是否派生自保密筛过的材料。

### 第 1 步：识别文书来源

**`--matter` 模式：**

1. **用户提供路径** —— 本会话拖入的（文件路径、云盘链接、邮件导出）。
2. **默认案件文件夹** —— 按 `CLAUDE.md` 的文档存储模式，展开为本 slug（例：`~/legal-matters/[slug]/`、`G:/Legal/Matters/[slug]/`）。
3. **声明的来源** —— `CLAUDE.md` `## 可用集成` 表，筛为本案可能触及的（例：企业微信/钉钉/飞书归档、SharePoint 法务文件夹、CLM）。
4. **询问** —— 若来源看着薄：「我可以从现有的构建，但时间线会不完整。还有别的可指的吗？关键邮件、合同、内部备忘、往来函件？」

**`--documents` 模式：**

1. **举证材料导出 / 编号集** —— 用户指路径或索引；本 skill 按编号 + 日期读。
2. **eDiscovery / DMS 连接器** —— 若可用（Everlaw、Relativity、DISCO、Aurora、iManage），按当事人 + 日期范围拉。
3. **当事人材料** —— 用户提供的邮箱/云盘导出。
4. **询问** —— 若关键当事人或日期范围覆盖薄，提问。

### 第 2 步：拉取 + 读

对每个有可读文件的来源：

- **PDF、邮件（.eml）、.docx、.txt、图片（含扫描件 OCR）、录音转文字** —— 直接读。
- **邮件归档（企业邮箱、Outlook、Gmail）** —— 若 MCP 已认证，按日期范围 + 对方 / 关键词查询；否则用户导出相关对话到文件夹。
- **企业微信 / 钉钉 / 飞书聊天记录** —— 用户导出为文本或截图集；含时间戳。
- **eDiscovery 平台或 DMS** —— 若连接器可用，按当事人 + 日期范围拉；否则用户提供导出。

若不可访问某声明来源，在输出"缺口"章节明确点名，不假装继续。

**不做隐性补充。** 若某时间窗覆盖薄 —— 声明的时间段内文书数少于预期、某当事人邮箱不可访问、举证质证未完成 —— 如实报告并停。**不**未经询问从网页搜索、公开信息查询、模型对本案的训练知识补空。说：「来源返回 [N] 个事件覆盖 [周期/当事人]。覆盖看着薄。选项：(1) 指更多来源（编号、文件夹、邮箱），(2) 试另一 MCP 连接器（若已配置），(3) 网页搜索本时间窗的公开事件 —— 结果标 `[网页搜索 —— 待核验]`，依赖前对原始来源核对，(4) 就此停并记缺口。你选？」律师决定是否接受低置信度来源；skill 不替他决定。

**来源标注。** 每条时间线条目标注事件出处：文件路径、编号、MCP 连接器、或声明的文档存储来源（已在来源列捕捉）。凡不能追溯到检索文书的事件或日期（例如模型训练数据里记得的事实、通过网页搜索到的公开事件），行内标 `[网页搜索 —— 待核验]`、`[模型知识 —— 待核验]`、`[用户提供]`（用户会话中直接陈述的）。标 `verify` 的伪造风险高于文书源条目，先核对。永远不剥离或压缩标签 —— 它们是律师最快的信号，指明哪些条目在拉进代理词或事实与理由前先核对。

**标签延伸到每一节陈述法律结论、期限、计算日期的地方 —— 不只是时间线条目。** 时间线来自文书。缺口章节、关键事件章节、思路衔接行、任何关于诉讼时效、中断/中止事件、举证期限、上诉期、专属管辖、保密判断的陈述，都是本 skill 从模型知识写出的法律分析（除非有来源）。每一条这样的陈述附来源标签：`[计算依据：<引用规则并标签>]`、`[模型知识 —— 待核验]`、`[用户提供]`、或若本会话由检索连接器取得则用连接器标签。无标签的诉讼时效窗口默认为 `[模型知识 —— 待核验]`。给事实定法律意义的"关键事件"行也是分析，需标签。规则简单：若是对法律的主张，而非对文书内容的主张，须携与时间线条目相同的来源标签。

### 第 3 步：抽取事件

对每份文书，识别带日期事件：

- **邮件：** `[日期] [发送人] 告知 [收件人] [主题/内容]`
- **微信 / 钉钉 / 飞书消息：** `[日期时间] [发送人] 向 [群/个人] 发送 [内容]`
- **会议：** `[日期] [参会者] 就 [主题] 开会`（按日程或纪要）
- **决定：** `[日期] [决策人] 决定 [什么]`（按备忘录）
- **文书 / 起诉状 / 判决：** `[日期] [当事人] 提交 [起诉状 / 答辩 / 裁定]`
- **外部事件：** `[日期] [事情发生]`（合同签订、产品上线、监管处罚、跨过某阈值）
- **公证 / 存证 / 时间戳：** `[日期] 就 [内容] 做了公证 [公证书编号] / 时间戳 / 区块链存证`

通常一份文书对应一个事件。偶尔零个（无日期或未确立事件）。有时多个（一份会议纪要涵盖若干决定）。

**每条保密旗（仅当 privilege_posture == B-mixed）。三态规则 —— 绝不悄悄决定主观保密检验未满足：**

- `priv: ok` —— 来源**明显**非保密（起诉状/裁定 [但按案件规则可能含个人信息]、监管往来、公开文书、不含我方律师的对方通信）。仅在无合理保密理论时使用。
- `priv: flag` —— 来源明显或可能保密（与外聘律师的通信、律师工作产品、涉及内部法务对法律事项的沟通、保密草稿、共同利益材料、含商业秘密的技术文档、含个人信息且未去标识化的记录）。**任何不确定的默认这里** —— 若主导目的判断临近、诉讼预期是否形成边界、内容混合，归这里不归 `ok`。
- `priv: review` —— 来源初看不明，且本 skill 完全无法判断（无发件/收件元数据、不可读等）。

`priv: flag` 或 `priv: review` 时，行内加 `[SME 核实：保密属性]` 让律师复核时看到。漏标破坏保密（单向门）；多标复核时纠正（双向门）。宁可可恢复的错。

### 第 4 步：去重

同一事件出现在多份文书中：一场会议在三个日历里 + 一封纪要邮件 —— 是**一个事件带四个来源**，不是四个事件。合并。合并条目引全部来源。

### 第 5 步：按代理思路标重要性

从 `matter.md` 读关键事实与关键事实（`--matter` 模式），或从档案的 `## Playbook` 读（`--documents` 模式）。标每一事件：

- 🔴 **关键** —— 事件是关键事实或对我方为/反的关键事实之一
- 🟡 **相关** —— 上下文、模式证据、支持次要论点
- ⚪ **背景** —— 用于完整性，不进代理词

**纪律：** 300 条时间线中 300 个 🔴 等于没标签。🔴 留给真正会打动法官/仲裁员的事件。犹豫时 🟡。

**边界标注：** 条目在 🔴 与 🟡 或 🟡 与 ⚪ 之间时，标较低的一档并加 `[SME 核实 —— 边界重要性判断]`。律师判断覆盖 skill 的判断。自信过度标注不如显式表达不确定的。

### 第 6 步：写

默认输出是工作时间线。按需变体。

筛为 🔴 与相关 🟡。按时间叙事顺序呈为散文 —— 起诉状事实与理由的骨架。每段是一个事件或紧密关联的一组，附证据引用（编号、证据 X-Y、公证书编号）。

**保密筛选默认：** 当 `privilege_posture == B-mixed` 时，🔒-flagged 与 🔒-review 条目**默认排除**。事实与理由变体面向最终对外用途（代理词、披露、与对方谈判）—— 🔒 条目不属于那里，除非律师确认保密。若用户仍想含 🔒，要求显式 `--include-flagged` 确认；确认作为永久记录写入输出头。

## 与 matter.md / history.md 的整合

**有意分开**（公司法务 `--matter` 模式）。`history.md` 是律师的运行日志 —— 决定、更新、程序里程碑、内部策略笔记。`chronology.md` 是面向诉讼的事实时间线。两者重叠但不合并：

- 启动了证据保存 → 进 history.md（内部动作）。通常不进时间线（不是争议的事实）。
- 对方于 3 月 14 日发律师函 → 进 chronology.md（🟡 —— 确立其知情）。若立案访谈引用过也进 history.md。
- 我方准备金推荐备忘 → 只进 history.md。

律师想把 history 事件放进时间线时，可以粘贴。默认它们分开。

## 转换决策

- 分级：**B 大改**。工作流保留（保密关卡 → 来源 → 抽取 → 去重 → 标重要性 → 写 → 变体）。实体层重写：eDiscovery 平台名称保留但补充"国内实务少用美式 eDiscovery，更常见 DMS + 云盘"；聊天记录源具体化为企业微信/钉钉/飞书/微信办公群；来源清单加入公证书/时间戳/区块链存证；FRE 408 / privilege doctrines 换为民诉法第 68 条、律师法第 38 条、证据规定第 96 条、反不正当竞争法第 9 条商业秘密、个保法个人信息；已披露文书使用限制的英美法门槛换为民诉法第 68 条与保密令；诉讼时效焦点保留但换为中国 3 年一般时效框架。原版的 attorney-client privilege / work product doctrine 三态规则整体保留（律师保密义务与工作产品的类似判断在中国实务也适用，但保护基础不同）。

## 这个 skill 不做的事

- **解决矛盾。** 两份文书说同一事件不同时间时，两条都进带旗。解决是律师的判断；可能需要询问证人或进一步取证。
- **发明来源中没有的事件。** 若文书里没有（且未在 matter.md 或档案作为捕捉事实登记），就不进时间线 —— 但"缺口"可能会点出缺失。
- **保证完整性。** 时间线只跟来源一样好。若举证质证仍在进行只落地 20%，时间线反映这个。点出限制。
- **替用户决定保密属性。** 第 0 步关卡强制姿态决定；每条 `priv` 标是首轮分类。实际保密判定按 `[SME 核实]` 是律师的判断。
