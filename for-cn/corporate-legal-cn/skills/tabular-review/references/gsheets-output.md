# 在线表格输出规范（飞书表格 / 腾讯文档 / Google Sheets）

面向国内团队常用飞书文档/腾讯文档在线表格的场景，以及跨境语境下的 Google Sheets。结构与 Excel 规范一致，机制不同。若 Excel 和在线表格两条路径都可用，问用户偏好——不要从环境猜。

## 如何写它

三条路径，按偏好顺序：

1. **在线表格 MCP**（若连接了带写/建能力的 `feishu`、`gdrive` 或 `gsheets` MCP）。创建表格、写各表、通过 API 设置格式。
2. **在线表格 API**（若用户配置了对应服务的 API 访问）。使用批量更新格式接口。
3. **回退：CSV + 手动导入。** 写 CSV，告诉用户导入到表格软件。同时写 `format-instructions.md` 让他们手动应用颜色编码和数据验证。

不要假设你有未验证的写权限。先检查；优雅回退。

## 工作簿结构

精确镜像 Excel 规范——同样的表、同样的语义、在线表格原生机制：

**表：`审查`**（主网格）
- 第 1 行：待审核草稿头（合并单元格）
- 第 2 行：列标签
- 第 3 行起：每份文档一行
- A 列：文档名 / 链接（若源文档在飞书/云盘中，超链接到文件——这是在线表格相对 Excel 的优势）
- B 列起：每 schema 列一列
- **源引用放在单元格备注中**（备注是持久注释）。备注在悬停时浮现，导出到 `.xlsx` 时变为批注。
- 按状态填充色：默认 = `answered`，浅黄 = `unclear` 或 `needs_review`，浅灰 = `not_present`。
- 每组后 `已核验` 列：默认空白，数据验证下拉 `✓ | ✗ | ?`。

**表：`标记`**
- 同 Excel 规范。每个标记单元格一行。

**表：`_schema`**
- `.review-schema.yaml` 的列定义。

**表：`_summary`**
- 计数、标记列、核验提醒。

## 在线表格特有优势可用

- **源文档超链接。** 若被审文档在飞书/云盘中（VDR 导出和内部库常见），每行文档名应超链接到文件。这是点击到源的模式，在线表格原生支持。
- **共享审查。** 在线表格比本地 `.xlsx` 更好处理并发审查。若交易团队要分工核验，用这个格式。
- **命名区。** 每列定义命名区，让下游公式（透视、条件计数）可读。
- **按状态列的条件格式。** 若每个数据列写一个隐藏 `_state` 列，可用条件格式规则驱动颜色——比逐单元格格式更干净，且排序时保留。

## 在线表格特有陷阱

- **备注是逐单元格且打印不可见。** 若输出会被打印或转 PDF 给合伙人开会用，也把引用写到 `标记` 表让它们留存。
- **在线表格有单元格上限。** 你在法律审查中不会碰到，但若有人试图对 50000 份文档乘以 30 列加源列建网格，警告。
- **分享默认。** 按插件执业档案，这是律师工作产品。创建表格时设为限制分享（只有所有者），告诉用户刻意分享。默认不要「有链接的任何人可访问」。
- **公式转义。** 若某逐字引用以 `=`、`+`、`-` 或 `@` 开头，前缀单引号（`'`）以免表格解析为公式。这是真实失败模式：以「- 双方约定……」开头的合同条款不转义会渲染为公式错误。

## 不要做的

同 Excel 规范：不要置信度百分比、不要截断引用、数据区不要合并单元格、总是写 `_schema` 和 `_summary` 表。

## 公式注入防御

在 Excel、表格或 CSV 输出中写入任何单元格前，中和公式注入。相对方来源文本（合同引用、当事方名称、代理数据、合同管理系统导出）是攻击者可控。以 `=`、`+`、`-`、`@`、制表符、回车、换行开头的单元格会被当作公式或破坏行结构。

- **前缀单引号：** `'=SUM(A1:A10)` → `=SUM(A1:A10)`（显示为文本，不执行）
- **适用于每个含文档、工具结果或用户粘贴来源文本的单元格。**
- **CSV：还要转义嵌入的逗号、双引号、换行**（RFC 4180 引用）。
- 这不是可选项。用户在 Excel 打开你的表格触发宏或通过 DDE 泄露数据，是对用户的供应链攻击。
