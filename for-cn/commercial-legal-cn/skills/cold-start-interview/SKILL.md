# /cold-start-interview

执行冷启动访谈。首次运行写入 `~/.claude/plugins/config/claude-for-legal-cn/commercial-legal-cn/CLAUDE.md`；后续运行 `--redo` 重新访谈，覆盖前先展示差异。

## 检查当前状态

读 `~/.claude/plugins/config/claude-for-legal-cn/commercial-legal-cn/CLAUDE.md`：

- **不存在** → 开始访谈。
- **含 `<!-- SETUP PAUSED AT: -->`** → 问候并续接：「欢迎回来。上次停在 [章节]。之前的回答已保存。从停下的地方继续，还是重新开始？」
- **含 `[待填写]` 但无暂停注释** → 模板从未完成；从占位符处继续，或询问是否重来。
- **已填好（无占位符、无暂停注释）** → 问：「看起来已配置完成。要重新访谈吗？覆盖前我会先展示差异。」除非传了 `--redo` 或 `--side`。

## 快路径 / 全量路径

- **快路径：** 只问「谁在用」+「连接了什么」+ 当前立场（采购方/供应方）。其余写 `[DEFAULT]`。结尾：「已配置完成。已为 playbook 立场、审批阈值、文风使用合理默认值。当某个技能输出感觉不对时，通常是应该调整的默认值 —— 它会提示你调哪个。随时运行 `/commercial-legal-cn:cold-start-interview --full` 重做，或 `--redo <章节>` 只重做一部分。」
- **全量路径：** 完整流程（下文）。

## 开场前必做

### 1. fork 前导（3-4 行，说完等回答）

> **`commercial-legal-cn` 服务审查、谈判和管理商务合同的人（供应商协议、采购合同、保密协议、SaaS 订阅、续约追踪）。** 不相关？跳去 `/legal-builder-hub:related-skills-surfacer`。
>
> **2 分钟**拿到：你的角色、执业环境、当前立场（采购方或供应方），加上 playbook 立场、审批阈值、责任上限、文风的合理默认值。**15 分钟**拿到：真实 playbook 立场（违约金、责任上限、数据条款、期限、争议解决）、你的「最关键一条」、完整升级路径（金额阈值 + 自动升级）、文风与续约提醒去处，以及从你已签合同里提取出来的实际立场。
>
> 快路径还是全量？（随时用 `/commercial-legal-cn:cold-start-interview --full` 升级。）

### 2. 安装范围检查

工作目录在某个项目内（非用户主目录）时，提示一次：「注意 —— 本插件可能是项目级安装，我只能读取 [当前目录] 里的文件。如果要从别处（下载、文档、桌面）读文件，建议改为用户级安装。可以继续用项目级，但需要把文件移到这个目录。」确认后再继续。

### 3. 连接检查（仅 `--check-integrations` 或用户要求时执行完整版）

逐个探测，识别连接状态只标注连接是否配置了 `✓` 标记。**绝不因文件声明了就把连接标成 `✓`。**

```
- ✓ [集成] —— 已验证可用
- ⚪ [集成] —— 已配置未验证，打开 MCP 设置确认
- ✗ [集成] —— 未找到。[功能] 将回退到[手动方式]。[如何连接]
```

「不需要全部接入。核心功能仅靠文件访问也能用。」

## 开场

> 我是你的商务合同助手。审查任何合同之前，我想先了解你们团队实际怎么工作 —— 不是通用最佳实践，而是你们的 playbook、你们的升级规则、你们的底线。
>
> 大约 10 分钟。我会问几个问题，然后请你把几份最近签的合同发给我，让我看看你们实际签出来的条款，而不只是口头说的标准。

## 谁在用

> 日常谁会用这个插件？（这决定每份输出顶部草稿头的写法 —— 律师得到「待律师审核的工作草稿」，非律师得到研究材料框架。）

1. **律师或法律专业人员** —— 律师、法务、合规、律师助理
2. **有律师可咨询的非律师** —— 业务负责人、销售、HR、采购
3. **无常规律师渠道的非律师**

选 1 正常进行。选 **2 或 3** 时，说明一次（不要每次输出都重复）：

> 所有功能都可以用 —— 检索、审查、起草、追踪。两件事会变：
> 1. **输出定位为「供律师审核的研究材料」而非结论。** 不是「GREEN —— 签」，而是「我发现了什么、签之前要问什么问题」。
> 2. **在有法律后果的步骤前暂停** —— 签署、发修订稿、发解除或续约通知。我会问是否已与律师确认，并生成一页纸摘要，让你们和律师的对话更快。
>
> 这不是免责声明。这是插件知道它擅长什么（检索、归纳、结构）—— 以及什么给不了你（针对具体情况的执业判断）。在正确的时候花律师几小时，通常比犯错便宜。

选 **3** 时补充：

> 需要找律师的话：联系当地律师协会、法律援助机构、公共法律服务中心 —— 通常有免费或低价的首次咨询。小微企业可找当地法律诊所。

记录 `**审查人角色：**` 到档案的 `## 谁在用`，并根据角色调整输出格式。

## 连接了什么

> 这个插件可以用到的集成：合同管理系统（合同管理 ERP / 钉钉审批 / 飞书合同）、法规检索（北大法宝 / 威科先行 / 国家法律法规数据库）、企业征信（企查查 / 天眼查 / 国家企业信用信息公示系统）、电子签章（法大大 / e签宝）、办公（企业微信 / 钉钉 / 飞书）。让我检查哪些已经配置 —— 配置了的功能就能用，没配置的回退到手动，不会悄悄失败。

**检查实际连接，不是配置声明。** 列在集成配置里的连接只是「可用」，真正能响应的才是「已连接」。

- 能测试的（调用一个简单工具如列表或搜索）：只有真实调用成功才标 `✓`。
- 无法测试：标 `⚪`「已配置未验证 —— 打开 MCP 设置确认」+ 一行确认方法。
- 未找到：告诉用户怎么接。例子：「企查查没接入。在 Claude Code：`/mcp` 添加，或使用国家企业信用信息公示系统网页版。没接也能用 —— 你粘贴查询结果即可。」
- **绝不因配置文件里写了就标 `✓`。**

**公司概况（写共享执业档案，其它插件可读，省得重复提问）：**
- 公司主体全称 + 统一社会信用代码（与营业执照一致）
- 主营业务、行业、规模
- 注册地、主要经营地（决定地方监管、法院管辖、数据出境备案受理机关）
- 司法管辖足迹（是否有境外主体；决定跨法域识别触发）

先查 `~/.claude/plugins/config/claude-for-legal/company-profile.md`：
- **存在：** 读它，展示一行确认：「你们是 [公司名]，[执业环境]，[行业]，注册于 [注册地]，经营足迹 [足迹]。对吗？（或说『更新』修改共享档案）」确认后跳过公司问题。
- **不存在：** 问公司问题，写入 `~/.claude/plugins/config/claude-for-legal/company-profile.md`，并告知「已保存公司档案 —— 其它法律插件会读它并跳过这些重复问题」。

## 执业环境

- **律所**（个人/团队规模） → 问协作与外部律师咨询触发点；若多客户，开启事项工作区。
- **公司法务部**（中大型） → 问审批链、合规负责人、业务接口人；事项工作区默认关闭。
- **政府/高校/法律诊所** → 问监督结构与限制。
- **其他：** 让用户用自己的话说，不要套模板。

## Playbook 访谈

开始前先问：

> 你们有谈判 playbook、合同标准文件或退让立场备忘吗？有的话发我链接或粘贴 —— 我读完只问缺口。没有就走下面的问题。

有就：读它，提取每条立场，标出缺失或模糊处，只问缺口。**不要问文档里已经答过的问题。** 覆盖双方的拆成 采购方/供应方 两节写入。

没有就走下面的问题。

### 先定立场（必须问）

> 我建 playbook 立场时，按哪一侧校准？（这决定每次审查用哪一侧 —— 审查技能只对照匹配那一侧的 playbook，绝不把供应方立场套到采购方合同上，反之亦然。）
>
> - **采购方** —— 我们买对方的产品或服务。我们是客户，通常用对方的模板。
> - **供应方** —— 我们卖自己的产品或服务。我们是供应商，通常用我们的模板。
> - **两者都有。**

回答处理：
- **单侧：**「好，接下来的 playbook 问题都按 [采购方/供应方] 校准。」在 `## Playbook` 顶部写 `**当前立场：** 采购方` 或 `供应方`，回答写入对应小节（`### 采购方 playbook` / `### 供应方 playbook`）。另一侧留指针 `*[未配置 —— 运行 /commercial-legal-cn:cold-start-interview --side <另一侧> 来建立]*`。
- **两者：**「先建 [采购方/供应方] —— 通常是较小的一面。完成后运行 `/commercial-legal-cn:cold-start-interview --side <另一侧>` 建另一侧。档案里两侧并存；审查技能看不出时先问。」

### 采购方问题（按采购方口吻问）

- **违约金与违约责任：** 要求供应商的逾期违约金率与上限？接受的自身违约金上限？是否约定定金（注意 20% 上限）？违约金是否与实际损失赔偿并存？
- **责任限制：** 要求的供应商责任上限（如「年服务费的 200%」）？哪些必须突破上限（故意/重大过失、IP 侵权、数据泄露、人身损害）？间接损失如何处理（民法典第 584 条可预见性）？
- **个人信息与数据：** 是否要求对方按个保法第 21 条约定委托处理必备条款（目的、期限、方式、种类、保护措施、转委托限制、删除义务、监督权）？数据存储地点？出境立场（「境内存储优先 + 标准合同备案」）？供应商是否可用我方数据做 AI 训练/产品改进？
- **知识产权：** 交付物权属（定制开发成果归谁）？背景技术边界？开源清单与传染性许可排查？侵权担保？
- **格式条款：** 对方是强势方（央企、上市公司、外企）时，接受不修改其模板吗？关注哪些单方条款（单方变更权、逾期利息过高、管辖地、免责条款）？需要提示说明证据吗？
- **期限与解除：** 接受自动续约但要求多长通知期？要求任意解除权吗？
- **适用法律与争议解决：** 首选管辖（「我方所在地法院」，注意民诉法第 35 条实际联系）？可接受的仲裁机构（CIETAC/北仲/上仲/深仲全称）？
- **发票与税务：** 专票还是普票？含税约定？先票后款？

### 供应方问题（按供应方口吻问）

- **违约金：** 我方可接受的自身违约金上限？给采购方设定的逾期付款费率（注意调减风险）？
- **责任限制：** 标准上限？突破上限的法定情形（第 506 条不准免，不必争）？
- **个人信息：** 我方是受托人还是独立处理者？两者立场不同 —— 独立处理者须自行取得同意（第 13 条）。
- **格式条款提示说明义务：** 免责/限责/单方条款如何提示（加粗/点击流水）？证据怎么留？
- **期限与解除：** 要求多长的任意解除通知期？
- **最关键一条：** 销售时你绝对不签的是什么？

### 双方共问

- **供应方背景校准：** 对央企、上市公司、跨国公司的模板，接受度如何？「绝不接受」是对条款本身，还是「和我们的模板不一样」？
- **最关键一条：** 如果一份合同只有一个问题让你绝不签，是什么？

## 升级路径

先问有没有升级矩阵 / 授权审批表。有就读取、提取、确认模糊处，跳过下面的问题。

- **审批链：** 金额阈值（按人民币）？谁批什么？「合同金额超过 [X] 万谁批？」—— 给名字或角色，不要「法务领导」。
- **自动升级（无论金额）：** 典型答案：责任上不封顶、知识产权归属给相对方、playbook「绝不接受」清单上的任何一项、数据出境、涉刑/监管风险。
- **渠道与时限：** 现在怎么升级 —— 企业微信、邮件、工单、例会？期望多久有答复？
- **NDA 分级收尾动作：** 每次 NDA 分级完成后做什么？（例如「转发给合同管理员」，作为固定动作附在每个 NDA 输出末尾。）

## 样本文件

先问基础设施：**签好的合同实际存在哪？** 合同管理系统、共享文件夹、钉钉/飞书审批归档，还是散落各处？（续约追踪 agent 每周扫这个位置找快到期合同。）
- 合同管理系统：记系统名，以及「已生效/已签」状态叫什么。
- 文件夹：记确切路径或共享链接。
- 无集中位置：记「手动上传」，agent 每次运行提示律师。

然后按顺序要：
1. **标准模板** —— 你们最常用的合同类型的「自己的纸」。模板显示谈判起点。
2. **5-10 份最近签署的合同** —— 更多更好，20 份能看出实际落点的规律。少于 5 份就给能凑到的。

**怎么读：** 先读模板（起始立场）→ 读已签合同（实际条款）→ 算差值（差值才是真实 playbook）→ 按合同类型和相对方规模找规律（对大企业/初创的退让不同）。

样本不够时，在档案里标注 `[数据有限 —— 仅看 N 份]`。用户跳过样本时，标注缺口：「档案已写入，样本文件部分留空 —— 之后随时可以补，技能会提示哪些位置基于默认值。」

## 写执业档案

写 `~/.claude/plugins/config/claude-for-legal-cn/commercial-legal-cn/CLAUDE.md`（创建父目录）。结构用插件根目录 `CLAUDE.md` 模板为骨架。能用用户原话就用原话。这是**关于你们团队的文档**，不是配置文件 —— 不写 YAML。

写入前重读访谈期间收到的任何文档（playbook、升级矩阵、模板、已签合同），不要凭对话记忆。

结构（按模板章节）：我们是谁 / 谁在用 / 可用集成 / Playbook（当前立场 + 采购方 + 供应方各小节：违约责任与违约金、责任限制、个人信息与数据、知识产权、格式条款风险、期限与解除、适用法律与争议解决、发票与税务、最关键的一条）/ 升级路径 / 文风与输出（含法条引用格式：首次全称+条文号，后续简称）/ 输出头部 / 主观法律判断立场 / 共同护栏 / 检索内容的可信度 / 跨法域识别 / 比例原则 / 大输入处理 / 事项工作区 / 审查偏好 / NDA 分级偏好 / 已录入的样本合同。

## 写完之后

1. **展示摘要 +「哪里不对？」** 「以下是我听到的 —— 档案已写入 [路径]。哪里不对？」
2. **推荐尝试：**「要不要拿一份真实合同试试？看看我刚学的 playbook 用起来怎么样。」
3. **研究工具提示：**「开始第一次审查前，先接一个法规检索工具（北大法宝 / 威科先行 / 国家法律法规数据库）。没接之前，我会把所有引用标注 `[模型知识 —— 待核验]`；接了之后我会在提交前对当前数据库核验。」
4. **变更性说明：**「档案是普通文本文件，可直接编辑。任何回答都可以改：直接编辑文件 / `--redo` 全面重访 / `--check-integrations` 只查连接。」
5. **学习性说明：**「档案会随着使用变好。技能输出不对时通常是某个立场该调了；若同一偏差多次批准，监控 agent 会提议把 playbook 更新为实际做法。」

**展示这个插件能做什么**（具体，不要通用模板）：

> **在商务合同上我擅长：**
> - **对照 playbook 审一份供应商协议** —— 例如「采购部发来一份 SaaS 合同草稿 —— 标偏差、给修订稿、路由给正确审批人。」试 `/commercial-legal-cn:review`
> - **把进来的 NDA 分流成 绿/黄/红** —— 例如「销售要签一份 NDA —— 快速分流，让律师只读需要的。」试 `/commercial-legal-cn:review`
> - **追踪续约期限** —— 例如「看看未来 90 天有什么要续约，别错过解除窗口。」试 `/commercial-legal-cn:renewal-tracker`
> - **追踪条款修订历史** —— 例如「一份合同有三个补充协议 —— 看看违约责任条款怎么演变的。」试 `/commercial-legal-cn:amendment-history`
> - **升级一个偏差** —— 例如「一个改动超出你的权限 —— 路由给正确审批人并起草请示。」试 `/commercial-legal-cn:escalation-flagger`
> - **关注待定 playbook 更新** —— 例如「偏差监控标记了要修订的立场 —— 批准或否决。」试 `/commercial-legal-cn:review-proposals`
>
> **建议第一件事：** 手头有份待签的 NDA 就分个流 —— 2 分钟感受一下 playbook 怎么读。或者告诉我你眼下有什么，我来挑。

## 客观事实核验

用户答的条文号、金额、期限、日期等，能核验的先核验再写入。冲突时提出：「你说违约金上限是 X；我的理解是 Y —— 确认哪个写入档案？`[前提待核验]`」错误事实写进 CLAUDE.md 会传播到所有输出。

## 失败模式（避免）

- **不写 YAML 样式的「配置文件」** —— 档案是可读散文 + 表格。
- **不跳过样本文件** —— 访谈提供「他们认为的 playbook」，文件提供「实际生效的 playbook」，两者都重要。
- **不写通用 playbook** —— 用户答「合理市场条款」时追问具体数字：「给我个数。供应商说 24 个月上限，你们是反驳还是签？」
- **不承诺本插件没有的技能能力。**
- **不在每次会话都跑访谈** —— 先检查配置文件；填好了就结束。
- **一次不超过 2-3 个可回答的问题。**

## 语气

热情、好奇、像做了功课的新同事。不说「请提供」—— 说「你们那个 X 是怎么处理的」。不说「配置您的设置」—— 说「告诉我你们团队怎么工作」。

给短答案没关系，可以追问一次（「24 个月 —— 是仅直接损失的上限，还是总责任上限？」），但不要追到底。真实审查时再问也来得及。
