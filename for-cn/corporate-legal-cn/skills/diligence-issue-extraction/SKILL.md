# /diligence-issue-extraction

1. 加载 `~/.claude/plugins/config/claude-for-legal-cn/corporate-legal-cn/CLAUDE.md` + `~/.claude/plugins/config/claude-for-legal-cn/corporate-legal-cn/deals/[code]/deal-context.md`。
2. 用下面的工作流。
3. 检查 `ai-tool-handoff`——若类别是批量且工具已配置，先交接。
4. 读文档，应用重要性筛选，按类别抽取。
5. 发现以本所备忘录格式产出。同意事项交接到交割清单。

---

## 事项上下文

**事项上下文。** 检查执业档案 CLAUDE.md 中的 `## 事项工作区`。若 `启用` 为 `✗`（法务用户的默认值），跳过本段其余内容——技能直接使用执业层上下文，事项机制不可见。若已启用且没有活动事项，询问：「这是哪个事项？运行 `/corporate-legal-cn:matter-workspace switch <slug>` 或说『执业层』。」加载活动事项的 `matter.md` 获取事项特有上下文与覆盖项。输出写入事项文件夹 `~/.claude/plugins/config/claude-for-legal-cn/corporate-legal-cn/matters/<matter-slug>/`。除非 `跨事项上下文` 为 `开`，绝不读取其他事项的文件。

## 用途

VDR 有 2000 份文档。其中某处有对交易真正重要的 30 份。本技能对照档案中的尽调类别和重要性门槛读取文档，抽取问题，以本所备忘录格式写出。

## 加载上下文

- 档案 → 尽调结构（类别、重要性门槛）
- 档案 → 问题备忘录格式（发现怎么表述）
- deal-context.md → 交易特定门槛、VDR 位置

若 deal-context.md 不存在，问这是哪个交易。

## 工作流

### 第 1 步：清点 VDR

若 VDR 连接器（Box/Datasite/飞书文档/网盘）已授权，拉取索引。把 VDR 文件夹映射到尽调清单类别。记录缺口——清单里有、但 VDR 无对应内容的类别。

```markdown
## VDR 清点：[交易代码]

| 清单类别 | VDR 文件夹 | 文档数 | 状态 |
|---|---|---|---|
| 公司与组织 | /01-公司 | 45 | 已审 |
| 重大合同 | /02-合同 | 312 | 进行中 |
| 知识产权 | /03-知产 | 89 | 未开始 |
| [其他] | | | |

**缺口：** [无 VDR 内容的清单类别——需发补充清单]
```

### 第 2 步：应用重要性筛选

按档案 / deal-context 门槛。门槛说合同 > X 万元的，就不要审全部。

合同尤其：按标示金额（若在文件名/元数据中）或按相对方重要性排序。从上往下审，直到触及门槛或该类别读完。

### 第 3 步：抽取问题

对读过的每份文档，对照其类别的标准尽调关注点检查：

**重大合同——标准抽取集：**
- 控制权变更条款（本次交易触发？需同意？）
- 转让限制（合同能转到买方吗？）
- 排他 / 竞业限制（限制买方业务吗？）
- 最惠国待遇（价格约束）
- 终止权（相对方能因交易退出吗？）
- 异常赔偿或责任敞口
- **对外担保**（是否经董事会/股东会决议，公司法第 15 条——未经决议的对外担保效力存疑）

**公司与股权——标准抽取集：**
- 股权结构真实性：**股权代持**（隐名股东、代持协议）、**对赌协议/回购条款**（与股东对赌 vs 与公司对赌——九民纪要：与公司对赌须履行减资程序，实践中效力和可履行性有别）
- **注册资本实缴 / 抽逃出资**（公司法 2023 修订：有限公司 5 年实缴，第 47 条；出资不实、抽逃出资的补足与连带责任）
- 交易所需的董事会/股东会决议（召集程序、表决权、回避、章程约定）
- 股东协议限制（拖售权、随售权、优先购买权——公司法第 84 条股东优先购买权）
- 子公司结构与关联交易、同业竞争

**外资与监管——标准抽取集：**
- **外商投资负面清单**（外商投资法——目标是否处于限制/禁止类；VIE 架构提示）
- **经营者集中申报**（反垄断法——营业额门槛：全球合计超 100 亿 + 中国境内两方各超 4 亿 / 单方超 8 亿 `[待核验最新申报标准]`；达标必须申报，未申报即交割是违规）
- **境外投资备案 / ODI**（若涉及资金出境；37 号文外汇登记——境内居民境外投资/返程投资）
- 行业专项审批（金融、电信、数据、医疗等）

**知识产权——标准抽取集：**
- 权属链（创始人/员工的**职务发明**权属是否清晰，专利法职务发明规定；是否有权属转让协议）
- 产品中的开源软件（copyleft 传染风险）
- 关键 IP 是自有还是被许可
- 未决或潜在的 IP 诉讼、商标是否被抢注

**劳动——标准抽取集：**
- 控制权变更的补偿触发、关键员工留任风险
- **经济补偿敞口**（劳动合同法第 46-47 条 N/N+1；违法解除 2N，第 87 条）
- 未决劳动争议、社保公积金欠缴（尽调高频问题）
- 劳务派遣/外包用工的合规性

**涉诉与合规——标准抽取集：**
- 未决诉讼/仲裁及计提（**裁判文书网、中国执行信息公开网**检索）
- 潜在索赔、被列为被执行人/失信名单
- 行政处罚、监管问询
- **环保合规**（环评手续、排污许可）
- 税务合规（欠税、税务稽查）

### 第 4 步：陈述每条发现

> **来源标注。** 发现引用法条、法规、案例或监管行动时——如某控制权变更条款按适用法分析、某 IP 权属缺口引用具体规则、某未决诉讼带案号——给引用标注来源：`[国家法律法规数据库]`、`[裁判文书网]`、或法规检索连接器的 MCP 工具名（会话中实际检索的）；`[网络检索 — 待核验]`（网络检索的）；`[模型知识 — 待核验]`（训练数据回忆的）；`[用户提供]`（来自 VDR、交易团队备忘录或外部律师反馈的）。文档来源引用（VDR 路径、文件名、页码）保留原生引用。标 `待核验` 的引用编造风险更高，应优先核查。绝不删除或合并标注。
>
> **不同意用户引用的法条时，引用原文或拒绝描述。** 若用户（或交易团队记录、卖方披露）引用某法条支持一个你认为不正确的命题，而你手头没有该法条原文（无检索工具或 VDR 来源），不要编造该法条内容。改说：「这一条与我预期的 [批量转让通知 / 继受责任 / 其他] 要求对不上——我需要调出实际条文才能告诉你它到底规定了什么。`[条文未检索 — 待核验]`」然后 (a) 用检索工具调出并引用，(b) 请用户粘贴条文，或 (c) 交外部律师。对真实法条的自信错误描述比「我不知道」更糟——引用了编造章节的交易备忘录比一个缺口更难纠正。
>
> **不做静默补充。** 若对某发现所需法律依据的检索返回很少或没有结果（如控制权变更同意要求的规则、职务发明权属规则、劳动关系认定标准），报告找到了什么并停下。不要未经询问就用网络检索或模型知识补洞。说：「检索从 [工具] 返回 [N] 条结果。[规则/原则] 覆盖似乎不足。选项：(1) 扩大检索词，(2) 换检索工具，(3) 搜网络——结果会标 `[网络检索 — 待核验]`，依赖前须对一手来源核查，或 (4) 标为未核验并停下。你要哪个？」律师决定是否接受较低置信度来源。

按档案中的发现模板。若种子备忘录用了这个：

```
问题 #N：[标题]
类别：[清单类别]
严重级别：[本所体系级别]
文档：[VDR 路径 + 文档名]
发现：[文档说了什么、为什么重要]
建议：[价格调整 / 赔偿 / 需同意 / 陈述与保证 / 放弃]
```

……就用这个。种子备忘录用要点式，就写要点。

**严重级别校准**（若本所体系是 R/Y/G）：
- 🔴 **红：** 影响交易价值或结构。需重大客户同意的控制权变更。未披露的重大诉讼。IP 权属缺口。注册资本抽逃。应申报未申报的经营者集中。
- 🟡 **黄：** 需关注，可解决。需同意但可能取得。需整改的开源。劳动用工合规风险。
- 🟢 **绿：** 记录存档。与陈述一致。除陈述外无需动作。

### 第 5 步：按类别组装

按清单类别分组发现。类别内按严重级别排序。

```markdown
[待审核草稿头——按档案 ## 输出——因角色而异；见 ## 谁在用]

> 本输出源自保密的 VDR 材料。它继承来源的保密性——分发超出知悉范围可能造成泄密。与事项保密文件一同存放，审慎决定分发范围。

# 尽调问题：[交易代码] — [类别]

[发现，按严重级别排序]

---

## 缺口

- [清单项无对应文档]
- [文档被引用但不在 VDR]
```

## 交接

- **到 ai-tool-handoff：** 若在用 Luminance/Kira（按档案），把批量合同审查交过去。本技能处理需判断的文档（补充函、修订、工具难处理的）。
- **到 deal-team-summary：** 汇总发现喂给交易团队简报。
- **到 material-contract-schedule：** 合同级抽取喂给披露清单。
- **到 closing-checklist：** 任何暗示离散交割前动作的发现成为清单项。交接不限于第三方同意，还覆盖：
  - **股东会/董事会决议或其他交割动作** —— 所需股东会决议、所需董事会决议、异议股东回购通知期（公司法第 89 条）、其他公司审批。说明动作、审批门槛、法律或章程依据、时限约束。
  - **监管申报与批准** —— 经营者集中申报、外商投资准入、行业专项审批、ODI 备案，抽取中标记的。
  - **相对方同意** —— 控制权变更、禁止转让、触发最惠国的同意。
  - **解除、终止或清偿** —— 与控制权变更挂钩的劳动关系解除、清偿函、抵押解除。
  - **托管/留存机制** —— 若抽取浮现赔偿托管、陈述保证保险交付物、或与特定问题挂钩的留存。
  每个带交割前动作标签的发现都应到达 closing-checklist，不止标「同意」的。若发现处于灰区（可能需交割动作、也可能是交割后承诺），带标记交接——closing-checklist 可据协议丢弃。漏交接是单向门；过度交接在审核中可纠正。

**继受责任。** 标记：未决或潜在的侵权/产品责任索赔、环境事项与治理义务、债权人保护/欺诈性转让敞口（卖方是否保留足够资产偿付剩余债权人？）、卖方交割后注销计划（若卖方注销，债权人转而追买方）、以及交易协议是否有承担/排除债务清单实际覆盖已知敞口。即便是资产收购，中国法下的债务随企业财产变动、公司分立连带责任、以及未按法定程序通知债权人的减资/合并瑕疵，都可能转移责任——这是让以为「干净买资产」的买方吃惊的分析。

## 批处理

大类别（300 份合同）分批处理。每批后更新运行中的问题清单，任何 🔴 立即标记——不要等整个类别读完才浮现影响交易的问题。

## 收尾：下一步决策树

结尾按 CLAUDE.md `## 输出` 给出下一步决策树。按本技能刚产出的内容定制选项——五个默认分支（起草 X、升级、补充事实、观察等待、其他）是起点，不是锁死项。树本身就是输出；律师来选。

若抽取浮现超过约 10 项问题，或用户任何时候要求：提供仪表板（见 CLAUDE.md `## 输出 → 数据密集输出的仪表板提供`）。为这个输出定制——按严重级别计数（🔴/🟠/🟡/🟢）、按本所类别计数、可排序的问题网格（重要性、类别、VDR 来源）。

## 本 skill 不做的事

- 不对临界情况做重要性判断。它应用门槛；边界由人决定。
- 不谈判陈述与保证。它产出为其提供信息的发现。
- 不替代批量 AI 审查。高量级条款抽取交给 ai-tool-handoff。

## 质量自检

本次转换决策：本技能为 B 级大改。抽取工作流架构全部保留（清点→重要性筛选→抽取→陈述→组装、红黄绿严重级别、批处理、交接矩阵、继受责任分析）。核心重写的是**标准抽取集**——从美国法尽调焦点重写为中国法尽调重点：新增对外担保（公司法第 15 条）、股权代持与对赌（九民纪要与公司对赌须减资）、注册资本 5 年实缴与抽逃出资（公司法第 47 条）、经营者集中申报门槛（反垄断法，标 `[待核验最新申报标准]`）、外商投资负面清单与 VIE、ODI/37 号文、职务发明（专利法）、经济补偿 N/N+1/2N（劳动合同法第 46-47、87 条）、裁判文书网与执行信息公开、环评。检索来源标注从 Westlaw/CourtListener 改为国家法律法规数据库/裁判文书网。异议股东回购（公司法第 89 条）替换 appraisal rights。不确定的申报门槛数值和条文号标 `[待核验...]`。
