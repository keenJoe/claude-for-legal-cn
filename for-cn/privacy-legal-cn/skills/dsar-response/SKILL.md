# 个人权利请求答复起草

## 事项上下文

**事项上下文。** 检查执业档案 `## 事项工作区`。`启用` 为 `✗` 时跳过。若启用且无活动事项，先问再进入。输出写事项文件夹。跨事项默认关闭。

---

## 目的

一次个人权利请求有一个响应时限、一个流程（核验、定位、评估、答复）和一堆可能出错的地方。本技能走每一步并起草答复。

## 法域假设

本分析假定档案配置的法域范围（默认中国境内，个保法体系）。若请求人、处理活动或处理者在不同法域（如境外主体行使当地数据保护法权利），响应窗口与豁免均不同——见跨法域识别。

## 加载流程

读 `~/.claude/plugins/config/claude-for-legal-cn/privacy-legal-cn/CLAUDE.md` → `## 个人权利请求流程`。这里有：
- 系统清单（用户数据存在的每一处）
- 身份验证方式
- 响应 SLA（内部）
- 谁处理常规请求、谁升级

系统清单空或过时 —— 标出来。不知道去哪找就做不到完整定位。

## 流程

### 第 1 步：分类请求

个保法第四章列了个人权利：

| 权利 | 条文 | 内容 |
|---|---|---|
| 知情、决定 | 第 44 条 | 有权知悉处理并决定;限制或拒绝他人处理 |
| 查阅、复制 | 第 45 条第 1 款 | 有权查阅或复制其个人信息 |
| 可携带 | 第 45 条第 3 款 | 请求转移至指定处理者，条件符合网信办规定 |
| 更正、补充 | 第 46 条 | 发现不准确或不完整时可请求 |
| 删除 | 第 47 条 | 五种法定情形之一时应主动删除或应请求删除 |
| 撤回同意 | 第 15 条 | 基于同意处理的，个人有权撤回;撤回不影响撤回前的处理效力 |
| 解释说明 | 第 48 条 | 有权要求处理者对处理规则解释说明 |
| 自动化决策拒绝 | 第 24 条 | 通过自动化决策方式对个人权益有重大影响的决定，有权拒绝并要求说明 |
| 死者近亲属权利 | 第 49 条 | 死者的近亲属为自身合法、正当利益可行使查阅、复制、更正、删除等权利，死者生前另有安排的除外 |

有些请求是组合——「删除我的账号并先给我数据」是删除 + 可携带（或复制）。作两个联动的请求处理。

**响应时限：** 个保法第 50 条要求「及时」，未规定统一天数。实务参考：一般请求 15 个工作日内完成核实与响应，可基于请求复杂度延长并说明。行业规则可能更严（如金融、征信）。**内部 SLA 记在 CLAUDE.md**，SLA 严于监管口径的用 SLA;监管有硬性规定的以监管为准。 `[待核验条文号——第 50 条未指定天数,实务口径请核实当地/行业规定]`

### 第 2 步：核验身份

按 `## 个人权利请求流程` 里的方式：

- **已登录核验：** 请求来自已认证会话 → 身份确认
- **邮箱匹配：** 请求来自档案预留邮箱 → 通常足够
- **加强核验：** 高价值账户或删除请求 → 挑战问题、手机号验证、身份证件

**按风险校准。** 过度核验把权利请求流程变成障碍（监管眼里不好看）;核验不足有把别人的数据交给冒充者的风险。

个保法第 50 条第 2 款：处理者接到请求后应及时核实处理者身份和请求真实性。核验期间应通知请求人，不宜静默拖延时钟——响应受理函（第 5a 步）可先发。

无法核验身份时：

```markdown
您好，我们收到您的请求。为核实身份以保护您的个人信息，请[验证步骤]。在完成身份核实前，
我们无法就您的个人信息提供响应。核实完成后我们会尽快处理。
```

### 第 3 步：定位数据

按 CLAUDE.md 的系统清单逐项走。每个系统：

| 系统 | 已查 | 找到数据 | 是什么 |
|---|---|---|---|
| 生产库 | | | |
| 分析（如神策、GrowingIO） | | | |
| 工单（如 Zendesk、企微客服） | | | |
| CRM（如销售易、纷享销客） | | | |
| 邮件营销 | | | |
| 日志 | | | |
| 备份 | | | （通常不适用于删除请求 —— 见下） |
| 第三方受托人 / 独立处理者 | | | 委托处理关系时应通知受托人删除;独立处理者按第 47 条第 3 款 |

**若我方是受托人**：请求人通常是**客户的**用户。检查这是不是应该由客户（作为处理者）处理的请求。多数受托人协议约定「把权利请求转发给委托方」。

### 第 4 步：法定不予支持情形分析

不是所有请求都会被支持。对每类请求，识别可能适用的情形。**每条援引条文、写理由。**

**删除请求（第 47 条第 1 款）应支持的情形：** 处理目的已实现或为实现目的不必要；处理者停止提供产品或服务、或保存期限已届;个人撤回同意;违反法律、行政法规或约定处理；法律、行政法规规定的其他情形。**第 2 款：法律、行政法规规定的保存期限未届满或者删除个人信息从技术上难以实现的，处理者应停止除存储和采取必要安全保护措施之外的处理。**

**查阅、复制的例外（第 18 条第 2 款、第 35 条等）：**
- 处理为履行法定职责所必需（政府机关场景）
- 应保守国家秘密、商业秘密或个人隐私（保护他人利益）
- 法律、行政法规另有规定的紧急情况

**其他常见法定不予支持理由：**
- **法律法规规定的保存义务**：如公司法记账凭证保存 10 年;税收征管保存 10 年;网络日志留存 6 个月（网络安全法第 21 条第 3 款）;药品销售相关记录、金融交易记录等。**引具体法条。**
- **诉讼或调查保全**：诉讼保全、涉嫌违法调查
- **含第三方信息**：请求人的记录里含关于他人的个人信息，涉及他人的部分需处理（脱敏、删除、隐去后再提供）
- **备份轮换**：技术不可行的完全立即删除；应记录并说明策略（下次轮换时删除），不作为对抗一切请求的借口

**别在主观判断上收窄清单。** 有善意基础的情形都提出并旗标不确定的，由律师收窄再发。放掉一个后来发现应主张的情形代价大——一旦材料披露，情形事实上失效。过度主张一个善意情形可由律师在审阅中收回。选可恢复的错误。

每个建议主张的情形都带说明：**「建议 —— 提出前需律师审阅。监管会审视笼统情形主张，因此律师负责收窄，本技能不代做。」**

要走的常规问题：

- 记录里是否含其他人的数据需先脱敏再提供？
- 有没有具体的法定保存期限阻断删除？援引它。
- 有没有针对此人的诉讼保全？
- 是不是备份轮换的技术限制需要记录（不当作一般借口）？

**每个主张的情形都记录。** 监管问你为什么没删除时,「有法定保存义务」需要具体条文。

### 第 5 步：起草答复——两封函

> **检索连接器预检。** 起草前检查法规检索连接器在本会话是否可达（国家法律法规数据库、北大法宝、威科先行或律所配置的 MCP）。收集到审阅提示——审阅提示置于**内部**分析和覆函，**不**置于对个人的两封答复函。若第 1 步、第 4 步或本步中的时限研究无连接器返回（或运行时未配置），在内部审阅提示 **来源：** 行记录——例如 `未连接 —— 引用来自训练知识;主张的情形、响应时限、延长机制尤其易被伪造,主张任何情形或向监管答复前核验`。逐引用 `[模型知识 —— 待核验]` 标签保持内联。

多数场景合理做法是先发受理函，再发实质答复函；不要合成一封拖到第 50 条要求的合理时限最后一天才发。

- **第 5a 步——受理函。** 收到后数日内发（目标：当天到 3-5 个工作日，远早于内部 SLA/监管口径的最后期限）。确认收到、复述所理解的请求、告知响应时钟与目标日、请求任何未完成的身份核验材料。**不含**实质披露。及时受理是监管可见的「流程在运转」的第一信号；也减少重复请求或早发投诉的风险。
- **第 5b 步——实质答复函。** 实际的披露、删除确认或可携带导出。在内部 SLA / 监管期限内发出。仅在身份核验完成、第 3/4 步数据定位与情形分析完成之后。

**发送前**（读 `## 谁在用`）。若角色是非律师：

> 发出个人权利请求答复有法律后果——内容、主张的情形、遗漏都可被监管审阅，误述成为执法暴露。你与律师复核过了吗？是则继续。否则以下一页纸交律师：
>
> [生成一页纸摘要：请求人、援引权利、适用法域、系统清单里找到什么、拟不予支持的项及依据、身份核验状态、响应期限、发出前三个要问律师的问题]。

未获明确「是」不得越过此门。

> **注意：** 两封答复函都是**对外**交付物，发给请求人。**不要**在函上加工作产物头部。内函（内部覆函、情形分析、日志）留内部，附上工作产物头部。

> **发送前：** 这是供律师审阅的草稿，不是发送稿。发送把处理者绑定到一个立场，可能弃权情形，可能启动监管时钟。持证律师审阅、修改、批准后再发给请求人。未审勿发。

#### 第 5a 步——受理函模板

```markdown
主题：您的个人信息权利请求已收到——[公司]——[日期]

尊敬的[姓名]：

我们于[收到日期]收到您的[查阅 / 删除 / 可携带 / 更正 补充 / 撤回同意 / 解释说明]请求。

**我们理解您的请求为：** [一句复述]

**接下来会怎样：**
- 我们的实质响应目标日为[日期——不晚于内部 SLA 或适用监管期限]。[若身份核验未完成：「我们需要[具体核验步骤]方能推进——见下」。]
- 若因请求复杂或同一期间收到您的多个请求需要延长时间，我们会在初始期限届满前通知您并说明原因。
- 本次请求不收取费用。[或：仅当请求明显不合理或过度且规则允许时收取费用——援引具体依据。]

[若身份核验未完成:]
**为核实您的身份**，请[具体核验步骤——如从档案预留邮箱回复本邮件并提供支付方式后四位]。
我们在此期间并行推进不需要该核验的准备工作。

如有问题，请联系[个人信息保护联系人]。

[发件人]
```

**时钟起算规则：** 第 50 条要求「及时」，实务通常从**收到请求**之日起算，不因等待身份核验而暂停。规则另有要求的除外。发出「需要更多时间」通知要早，别拖到最后一天。

**查阅、复制答复：**

```markdown

尊敬的[姓名]：

我们于[日期]收到您对个人信息的查阅、复制请求。

**我们保存的与您相关的个人信息类别：**

| 类别 | 来源 | 目的 | 保存至 |
|---|---|---|---|
| [账户信息：姓名、邮箱] | 您注册时提供 | 账户管理 | 账户注销时 |

| [客服沟通记录] | 您 | 客户服务 | [期限] |
```

### 第 6 步：登记

个人权利请求会被审计。记录：
- 收到日期
- 身份核验完成日期
- 答复日期
- 已提供 / 已删除内容
- 主张的法定不予支持情形及依据
- 处理人

## 升级触发

按 CLAUDE.md 上报表升级，且当：

- 请求人是（或可能是）原告、对方律师、记者
- 请求范围异常（「所有关于我的数据，包括内部通讯」）
- 有针对此人数据的诉讼保全（删除请求 + 保全 = 冲突，律师定）
- 请求人对既往答复提出质疑
- 有监管抄送或被点名

## 期限管理

**两封函规则。** 每次权利请求都产生一封受理函（及时——目标收到后 3-5 个工作日）和一封实质答复函（内部 SLA / 监管口径的最后期限内）。多数规则期望或要求受理与实质答复分开;合成一封拖到最后一天即便实质无错也是流程失败。

**研究现行响应时限。** 个保法第 50 条要求「及时」，未指定统一天数。行业专门规定（金融、征信、汽车）可能有具体时限——**援引一手来源**。查看是否存在延长机制、延长多少、需向请求人发何种通知。识别时钟起算点（收到 vs 核验 vs 其他触发——默认收到；按规则核实）。

CLAUDE.md `## 个人权利请求流程` 里的内部 SLA 若严于监管口径，用内部 SLA 并注明监管兜底。

## 本 skill 不做的事

- 不直接查询系统。它带你走清单;人（或已连的工具）真的去查。
- 不在临界案例上做情形判断。它标给律师。
- 不发答复。起草 → 审阅 → 人来发。

## 跨法域提示

本流程覆盖中国法（个保法体系）下的个人权利请求。若请求人是境外主体（如欧盟境内数据主体行使 GDPR 数据主体权利）或处理适用外国法，权利范围、豁免和响应窗口都不同——按 GDPR 常规窗口为 1 个月起、CCPA 为 45 天等，需按对应法域研究。中国法下同时处理的部分仍适用个保法。
