# /cold-start-interview

1. 检查 `~/.claude/plugins/config/claude-for-legal-cn/legal-clinic-cn/CLAUDE.md`。已填好且无 `--redo`，先确认再覆盖。
2. 运行下方访谈，从**第 0 部分**（角色核验 → 伦理前置条件 → 集成可用性）开始。若用户不是指导老师，停下并转向。
3. 读取种子文件：诊所工作手册、办案指引、地方规定、接待登记表、脱敏范例案卷。
4. 关键决策：监督模式（正式队列 / 可配置标记 / 轻监督）。
5. 迁移：若已有填好的 CLAUDE.md 存放在旧缓存路径 `~/.claude/plugins/cache/claude-for-legal-cn/legal-clinic-cn/*/CLAUDE.md` 而当前 config 路径无，先复制过去再继续。
6. 写入执业档案，含 `## 谁在用这份档案` 与 `## 可用集成`。展示监督模式选择、纠纷类型模板供确认。
7. 提供 `/legal-clinic-cn:ramp` 预览。

```
/legal-clinic-cn:cold-start-interview
```

**`--check-integrations`：** 只重跑第 0 部分的集成可用性检查（案件管理、法规检索、文档存储）。更新执业档案的
`## 可用集成` 一节，不动角色、伦理前置条件、监督模式或纠纷类型模板。添加或移除 MCP 连接器后使用。

探测时：只有 MCP 工具调用**实际成功**才标 ✓。已配置但未测通的标 ⚪，附一句如何确认。**绝不**因 `.mcp.json` 里声明了就报 ✓ ——
这会误导用户以为接好了实际没有。

# 冷启动访谈：高校法律援助诊所

## 目的

法律援助诊所在结构上就受产能约束：一位指导老师带 5-10 名学生，每人几个案件，学生每学期换一批。轮候单越排越长，有人等不下去就走了。

本插件的职责是压缩**律师工作周围**的时间成本 —— 接待记录、初稿、检索起点、状态更新、期限管理 —— 让同样的师生服务更多受援人，
让学生把更多时间放在真正让诊所教学值得的分析与策略上。

本访谈**一次性**设置诊所上下文，之后通过 `/ramp` 上手的每一届学生、之后运行的每一个 skill 都在同一份诊所理解之上工作。

**受众：指导老师。** 学生不跑这个 —— 学生跑 `/ramp`。

## 冷启动检查

读取 `~/.claude/plugins/config/claude-for-legal-cn/legal-clinic-cn/CLAUDE.md`：
- **不存在** → 开始访谈。
- **含 `<!-- SETUP PAUSED AT: -->`** → 问候并从该章节续接。
- **含 `[待填写]` / `[PENDING]` 但无暂停注释** → 模板未完成；提议全新开始或从占位符起接着做。
- **已填好（无占位符、无暂停注释）** → 已配置；除非带 `--redo`，回复：「看起来已配置完成。要重新访谈吗？会先展示差异再覆盖。」

## 共享机构档案检查

寻找 `~/.claude/plugins/config/claude-for-legal-cn/company-profile.md`。
- **存在：** 读取。一行确认：「你是 [姓名]，[执业环境]，在 [依托机构]，[行业/领域]，办案地覆盖 [法域]。对吗？（或说『更新』改共享档案。）」若确认，跳过机构问题，直接进入插件专项问题。
- **不存在：** 你是用户设置的第一个插件。开场与快/全量分岔之后，先问机构问题并写入共享档案（按模板），再进插件专项。告诉用户：「我已保存机构档案 —— 其它法律插件会读它并跳过这些问题。」

共享档案里的问题（若已存在**不要**重问）：诊所名称、依托高校、司法行政指导机关、行业设定、办案地、司法管辖足迹、风险姿态、升级链上的人。
插件专项（每个插件各自问）：playbook 立场、审核框架、文风、监督模式等。

## 安装范围检查

在正式开场之前，若工作目录不在用户主目录内（比如在某项目里），提示一次：

> **提醒 —— 看起来这个插件可能是项目级安装的，那样我只能读 [当前目录] 下的文件。若你想让我读 [下载 / 文档 / 桌面 / 云盘] 里的材料，
> 请改用户级安装 —— 见 QUICKSTART.md。可以继续用项目级，但需要把文件挪到本目录来。**

请用户确认后再继续。工作目录**就是**用户主目录时，静默跳过本项检查。

## 访谈开始前

先展示这段前导（3-4 行短句，别更长）：

> **`legal-clinic-cn` 面向为高校法律援助诊所配置与带学生的指导老师。** 不是你的领域？`/legal-builder-hub-cn:related-skills-surfacer`。
>
> **2 分钟**给你纠纷类型、办案地、监督模式基本盘 —— 加上受援人信函格式、法律咨询意见书结构、期限节奏的工作默认值。
> **15 分钟**加上伦理前置条件记录、监督标记触发条件、按纠纷类型的文书模板（从你现有案卷抓取）、送入 `/ramp` 的工作手册内容、
> 送入 `/draft` 的地方规定、以及学期日期。
>
> 快还是全？（随时用 `/legal-clinic-cn:cold-start-interview --full` 升级。）

## 用户选完快或全之后

先给指导老师做个 orientation。用你自己的话讲：

- **本插件维护什么：** 诊所档案（纠纷类型、监督模式、诊所模板）、每个案件的文件（接待记录、期限、沟通日志、交接备忘）、以及一个指导老师审核队列。
- **本次 setup 做什么：** 支撑高校法律援助诊所 —— 接待、案件分析、受援人信函、状态更新、期限管理 —— 覆盖你办的纠纷类型，
  监督内建。它学会诊所的纠纷类型、办案地、监督模式，写入一个所有 skill 与所有学生 `/ramp` 都会读的纯文本文件。之后一切都可以改。
  做完之后，命令会按诊所实际的运作方式工作，而不是按通用模板。
- **数据来源：** setup 从你的回答与访谈中上传的文档（工作手册、办案指引、地方规定、接待表、脱敏范例）建立**新的**诊所档案。
  它**不读**私人 Claude 历史、其它对话、你主目录的 CLAUDE.md。若本会话中先前提到过某些相关内容（学校、纠纷类型），我会先问再纳入。
  不经你输入或批准，什么都不会加进配置。
- **下一步：** 第 0 部分 —— 谁在运行 setup、以及伦理前置条件。

## 访谈节奏

- **假设答案已经写在什么地方。** 当问题涉及的内容可能已有文档 —— 机构说明、办案手册、升级链、文风、值班表、纠纷类型清单 ——
  先请求链接或粘贴，再让用户凭记忆手打。「粘个链接或文档，或说个简短版」是任何超过一句话内容的默认问法。
- **给真回答留时间。** 第 0 部分很多是「点选」式的，但伦理前置条件、第 1-5 部分（尤其第 4 部分种子文件）需要指导老师**打字**或**上传**。
  上传项：「粘贴内容、给个路径，或说『先跳过』。若跳过，我会在档案里标出缺口，并说明它对 `/ramp` `/draft` `/client-letter` 的影响
  （变薄或回退到默认）。」然后**真的等**。别静默继续。
- **写档案之前复盘。** 逐条过跳过的或用占位符回答的题目，问：「写档案之前，这些还开着：[清单]。现在补，还是暂时留占位符？」
- **一次别问超过 2-3 个可回答问题，包含子问题。** 测试：用户不用滚屏就能回答吗？超一屏就是太多。能用点选就用点选。
- **暂停与恢复。** 一开始就告知：「要停就说『暂停』或『先到这』，我会保存进度。之后再 `/legal-clinic-cn:cold-start-interview` 我从这里接。」
  用户暂停时，写部分配置到档案，加 `<!-- SETUP PAUSED AT: [章节名] —— 重跑 /legal-clinic-cn:cold-start-interview 恢复 -->` 顶注，
  未答字段用 `[PENDING]` 标记（区别于 `[待填写]`）。setup 再次运行发现暂停配置时，问候「欢迎回来。你在 [章节] 暂停。之前的答案已保存。从这里继续还是重新开始？」
  已答过的题不再问。

**当场核验用户陈述的法律事实。** 用户答某条文号、金额、期限、门槛、机关名，若能核验就先核验再写档。冲突时说：
「你提到时效是 X；我理解是 Y —— 哪个进档案？`[前提存疑 —— 待核验]`」错误事实写入 CLAUDE.md 会传播到所有产出，此处是全产品最高杠杆之处。

## 访谈内容

### 第 0 部分：谁在跑 setup、伦理前置条件、连接了什么

#### 谁在跑 setup？

> 你是本诊所的指导老师吗？你需要具备指导资质，能在办案地对学生进行监督。（这一项作为**角色关卡**：setup 只能由指导老师运行，答案会把指导老师姓名与相关资质信息写入档案。）
>
> 1. **是，我是指导老师。** 继续。
> 2. **不是，我是学生 / 行政 / 其他。** 停下。setup 写的是诊所的管治上下文 —— 监督模式、当事人数据规则、伦理前置条件 —— 必须由承担责任的指导老师完成。请他/她运行 `/legal-clinic-cn:cold-start-interview`。学生每学期通过 `/legal-clinic-cn:ramp` 上手。

答 2 就停，别继续。
答 1 记入 `## 谁在用这份档案`（角色：指导老师；姓名与法域已录），继续。

*为什么重要：诊所依托法律援助法与高校实践规范运作，实质法律工作与出庭代理须由执业律师承担。冷启动决策 —— 监督模式、重大行为把关、伦理前置条件 —— 是指导老师的权限。*

#### 伦理与保密前置条件

在指导老师访谈开始之前 —— 也在任何学生用本插件处理真实案件之前 —— 与诊所指导老师和学校信息化 / 法学院管理层确认以下事项。**不要跳过。**

1. **账号级别与数据处理条款。** 本诊所使用的 Claude 账号（Team、Enterprise、Work、Education、个人）在数据留存、训练使用、子处理者上不同。确认适用条款并记入档案。

2. **对受援人的 AI 使用告知实践。** 参考法律援助法与本地律协规范 `[a待核验：本地对 AI 辅助工作向受援人的告知规范]`。决定诊所如何披露 AI 使用并记录。

3. **受援人保密与案卷的处理规则。** 什么内容进对话、产出存哪、谁能访问、留存多久、学生流动如何影响访问。记录学生行为规则。

4. **对特殊案件的加强保密考量。** 家暴、涉未成年人、涉刑辩护援助等有更强保密与安全期待（对方接触风险、传票风险、当事人人身安全）。确认哪些类型需要额外防护（限制放入对话的事实、更严格脱敏、或某类完全不用插件）。

**学生行为底线（写入档案，硬约束）：**
- 学生**不能以律师身份**执业、**不能出庭代理**、**不能收费**、**不能以律师名义**对外行事
- 学生只能在教师指导下做**材料准备、法律咨询辅助、普法宣传、调解协助**
- 学生**不能承诺结果**（不承诺胜诉、不承诺赔偿数额）
- 特殊限度试点区域按当地规定执行 `[a待核验：本地对高校诊所学生参与出庭的具体规定]`

捕获指导老师回答。任何前置条件未落实的，在档案中标出，并注明未落实前学生不得用插件处理真实案件。

#### 连接了什么？

> 本插件可与法规检索（北大法宝、威科先行、国家法律法规数据库）、裁判文书检索（裁判文书网、人民法院案例库）、
> 文档存储（企业微信 / 钉钉 / 飞书 / WPS / 本地）、案件管理（本地台账或诊所系统）配合工作。
> 我来看看哪些连上了 —— 连上的功能会用，没连上的会平缓回退到手动，不会静默失败。

**检查真正连上了什么，不是配置了什么。** 出现在 `.mcp.json` 只是**可用**；真的响应才是**连上**。混淆两者会毁掉信任。对每个本插件用得到的连接器：
- 若可测（调一次列表或检索），只有真的成功才标 ✓。
- 无法探测的，标 ⚪「已配置未验证 —— 开你的 MCP 设置确认」并给一句 how-to。
- 绝不因配置就标 ✓。

未连上的告诉用户怎么连。示例：「北大法宝没连。在 Claude Cowork：设置 → 连接器 → 添加。在 Claude Code：把对应 MCP 加到配置或用 `/mcp` 添加。本插件没有它也能用 —— 你粘贴文本代替 —— 有它则法条核验自动化。」

按下述格式汇报：

> - ✓ [集成] —— 已连接（测通）
> - ⚪ [集成] —— 已配置未验证。开 MCP 设置确认。
> - ✗ [集成] —— 未找到。[功能] 将回退到 [手动方式]。[如何连接。]

不需要全部接上。核心功能 —— 接待、起草、信函、检索、期限、学期交接、教师审核 —— 仅靠文件访问就能跑。

写入 `## 谁在用这份档案` 与 `## 可用集成`。若旧缓存路径 `~/.claude/plugins/cache/claude-for-legal-cn/legal-clinic-cn/*/CLAUDE.md` 已有填好的版本而 config 路径没有，先复制过去。

### 开场

> 这是诊所的一次性配置，十到十五分钟。我会问你的纠纷类型、办案地、你怎么监督学生，然后请你把诊所工作手册、办案指引、
> 地方规定、接待表指给我看。这里学到的一切都会喂给每学期学生跑的 `/ramp`，也喂给本插件的每一个命令。
>
> 这里学到的不替代你的判断、也不替代学生的分析。目标是压缩格式化、结构化、写材料的时间 —— 让更多学生时间用在律师工作上，让更多受援人得到服务。
>
> 我沿途会请你提供材料 —— 工作手册、办案指引、地方规定、接待表、脱敏范例案卷、样本文书、样本信函。目标是访谈全程 10-20 份文件。越多越好。
> 少于 10 份，我会给档案打 `数据有限` 标记 —— 插件仍能用，但 `/ramp` 会薄（讲命令但不讲你诊所的具体流程），`/draft` 回退到一般规则而非你的本地格式，
> `/client-letter` 用通用模板而非贴你的口吻。**模板优先**：你上传一份文档，我读它并对齐格式，而不是让你口述格式。

### 第 1 部分：诊所（2-3 分钟）

**是什么诊所？**（纠纷类型驱动 `/client-intake` 与 `/draft` —— 每个类型有自己的接待模板与文书模板，所以这一项是「劳动诊所工作流」和「民间借贷诊所工作流」之间的开关。）
- 诊所名称、依托高校（法学院）
- 司法行政指导机关（例如 XX 区司法局 / 区法律援助中心）—— 高校诊所以「法律援助工作站/中心」名义运作 `[a待核验：本诊所对接机关的具体名称]`
- 合作律所 / 指派律师（承担实质法律工作与出庭代理）
- 主要办理的纠纷类型（可多选）：
  - 劳动人事争议（拖欠工资、未缴社保、违法辞退、工伤 —— 最典型）
  - 婚姻家事（离婚、抚养、财产、赡养）
  - 交通事故 / 人身损害
  - 民间借贷
  - 房屋租赁 / 物业
  - 消费者权益
  - 刑事辩护援助（值班律师、认罪认罚从宽见证）
  - 其他 —— 请描述

  **不落入常见框的：** 若诊所方向不在上述（涉未成年人专项、老年人权益、涉军、涉外劳务等），说：「听起来你的诊所不套我常用的框。用你的话讲一下 ——
  在做什么、服务谁、在什么法域和场景、工作大体什么样 —— 我从这个描述建你的档案，不硬套模板。」

- 本学期学生人数？典型在办案件量？
- 指导老师人数？

**受援人是谁？**
- 典型受援人情况 —— 谁会来、面临什么
- 方言 / 少数民族语言需求
- 常见转介来源（街道司法所、工会、妇联、社区、12348 热线、法院立案后转介）

**经济困难审查：** 本诊所是否承担法律援助经济困难审查？还是由指导的法律援助中心/司法所审查？（法律援助法第 41 条 —— 申请条件，各地标准不同 `[a待核验：本地经济困难标准]`。）

### 第 2 部分：办案地（1-2 分钟）

（驱动 `/draft` `/research-start` `/memo` `/deadlines` —— 办案地决定文书格式、检索范围、默认期限计算。）

- 主要法院（区县法院、中院、专门法院如互联网法院）—— 影响文书格式、送达、开庭
- 主要劳动人事争议仲裁委员会（劳动案件仲裁前置）
- 有无本地实施性规定或高院/中院指引偏离一般规则的（例如竞业补偿地方标准、租赁登记要求）？

### 第 3 部分：监督模式（2-3 分钟 —— 关键设计问题）

> 诊所之间对学生工作提交前的审核力度差别很大。有的要求每份都进正式审核队列 —— 学生提交、老师批准、才能出。有的偏轻监督 ——
> 学生自己 check-in，老师非正式过一遍，结构更对话式。你怎么做？
> （这驱动 `supervisor-review-queue` 与 `/draft` `/client-letter` `/status` 的标记逻辑 —— 正式队列开启队列；可配置标记只标触发；轻监督完全不加队列。）

三种可选：

**正式审核队列：** 面向受援人或提交法院/仲裁委的产出进入队列。老师审核、修改或退回，然后放行。所有批准留痕。（`supervisor-review-queue` skill 启用。）

**可配置标记，非正式审核：** 某些触发条件（涉家暴、时效将届、涉刑）产出「请与 [指导老师] 确认再发」标记 —— 但没有正式队列机制。学生自行负责请示。（不加队列；学生自行触发时找你。）

**轻监督：** 产出带标准 AI 辅助标注与核验提示，但没有额外审核关卡。老师通过既有诊所结构监督（案件讨论会、一对一），不通过插件。（不加队列或额外标记；靠你既有的讨论会与 check-in。）

> 没有「一定对」的答案 —— 取决于学生经验、案件量、你既有的监督方式。以后可编辑 CLAUDE.md 更改。

记录选择，若正式队列或可配置标记：什么触发标记？（提交法院/仲裁委的材料一律？任何时效提及？涉家暴/未成年人/涉刑指示？）

**教学姿态。** 监督选择记完后问：

> **skill 该做多少？** 这是最重要的一项设置。三选：
>
> - **guide（默认）：** skill 出结构，学生填实质，skill 给反馈。平衡 —— 多数诊所从这里开始。
> - **assist：** skill 出成果，学生复核、修改、由此学习。最快、最省事、最少教学。适合高案件量诊所。
> - **teach：** skill 不出成果 —— 学生先起草，skill 苏格拉底式提问、给反馈，试过两次才给范例。最慢、最强教学。适合学习为主要目标的诊所。
>
> 之后可用 `/legal-clinic-cn:build-guide` 对具体文书类型另行设定。现在先选默认。

写入 `pedagogy_default: assist | guide | teach`（未选默认 `guide`）。

**纠纷类型指引。** 教学姿态记完后提议：

> 要不要为你的纠纷类型编一个指引 —— 接待问题、按文书类型的教学姿态覆盖、审核关卡？5-10 分钟可完成，用 `/legal-clinic-cn:build-guide`。也可以以后再做。
> 现在 skill 用默认（你刚选的教学姿态 + 面向受援人的产出都要你审）。

记录用户回答；在访谈末尾（写档后的第 3 步）作为下一步提示，别打断当前访谈。

### 第 4 部分：种子文件（3-4 分钟）

> 三样东西，尽你所有。（工作手册喂 `/ramp` 上手；办案指引喂 `/draft` 格式；接待表成为 `/client-intake` 的骨架。）
>
> 1. **诊所工作手册 / 值班制度。** 学生第一天你会给的内容。我据此建 `/ramp` 上手，学生就不再是拿一份 PDF 扫两眼。
> 2. **办案指引、地方规定、法院/仲裁委指引。** 告诉学生格式怎么写、去哪立案、当地要求什么的一切。这些喂给 `/draft`，让初稿从一开始就对上本地格式。
> 3. **接待登记表，若有，加一份脱敏范例案卷。** 接待表成为 `/client-intake` 的骨架。范例案卷让我知道你诊所里「好案卷」长什么样。

**从手册取：** 诊所流程、案件管理约定、学生要求、伦理提醒。这就是 `/ramp` 要教的。

**从办案指引 / 地方规定取：** 起诉状 / 仲裁申请书格式、送达要求、本地立案偏好。这就是 `/draft` 要应用的。

**从接待表取：** 按纠纷类型的字段。若诊所对不同类型有不同接待表（劳动 vs. 婚姻家事），都要。

### 第 5 部分：文书模板（1-2 分钟）

对每个本诊所办理的纠纷类型：学生最常起草的 3-5 种文书是什么？（这喂给 `/draft` —— 每份成为一个模板起点。）

| 纠纷类型 | 常见文书 |
|---|---|
| 劳动 | 仲裁申请书、劳动关系确认申请、答辩状、证据清单、代理词 |
| 婚姻家事 | 起诉状（离婚 / 抚养费 / 探望权）、答辩状、财产清单、人身安全保护令申请书 |
| 交通事故 / 人身损害 | 起诉状、诉前保全申请、赔偿计算表、答辩状 |
| 民间借贷 | 起诉状、答辩状、支付令申请（民诉法第 224 条 `[待核验条文号]`）|
| 消费维权 | 投诉举报书（12315）、起诉状、和解协议、退一赔三主张书 |
| 刑事辩护援助 | 值班律师法律帮助记录、认罪认罚具结见证记录（律师签署，学生辅助） |

这些成为 `/draft` 的模板集。老师有现成模板就摄入；没有就记录哪些需要建。

**若老师没上传手册或接待表：** 本节末尾提议：「要我用你说的这些 —— 监督模式、纠纷类型、办案地 —— 帮你起草一份诊所工作手册和接待表初稿吗？下学期学生的入门材料，你可以改。」

## 写档之前 —— 复盘

写入执业档案前，逐条重读答案。捕获：

1. **答案间矛盾** —— 例如「正式队列」但描述实际审核方式时说「靠讨论会轻监督」。都指出来，问以哪个为准。
2. **漂移的具体值** —— 姓名、法院名、日期在不同章节出现变化的。确认最终值。
3. **值得点名的跳过** —— 纠纷类型列了但没模板、监督模式选了但没填触发条件、手册答应上传但没传。给机会补，而不是留到 `--redo`。

## 写执业档案

按 `## Playbook` 各节结构写入 `~/.claude/plugins/config/claude-for-legal-cn/legal-clinic-cn/CLAUDE.md`。关键内容：

- **诊所档案** —— 名称、依托高校、纠纷类型、办案地、学生人数
- **监督模式** —— 三种之一，及标记触发条件（如适用）
- **纠纷类型模板** —— 每种类型的接待模板与文书模板
- **管辖与办案地** —— 主要法院、仲裁委、录入的地方规定
- **学期** —— 学生流转时点（`/ramp` 知道下次何时用、`/semester-handoff` 知道何时触发）
- **手册路径** —— 摄入手册的存放位置，供 `/ramp` 读取

**数据有限标记：** 访谈全程分享少于 10 份材料，就在 CLAUDE.md 顶部（日期下方）加 `> 数据有限` 注：「本档案基于 [N] 份材料写成。下游 skill 仍可运行但产出会更薄 —— `/ramp` 只讲命令不讲诊所具体流程，`/draft` 用一般规则不用本地格式，`/client-letter` 用通用模板。收集更多样本后 `/legal-clinic-cn:cold-start-interview --redo` 重跑以磨齐。」

## 内建护栏说明

写入档案 `## 输出护栏` 一节：

```markdown
## 输出护栏（每个 skill 都应用）

每份产出都包含：
- **AI 辅助标注：** `[AI 辅助草稿 —— 须经学生分析与教师审核]`
- **不确定标记：** 明确说不确定，而不是猜
- **核验提示：** 学生依赖产出前应核实的具体事项
- **与任务匹配的伦理提醒：** 学生行为底线（不代理出庭、不承诺结果、不收费、不以律师名义）；依赖 AI 产出须经教师审核

以上不可选、不可配置。是基线。
```

## 写完之后

**展示插件能做什么。** 结束前提议：

> **想看看我能帮你做什么？**

若是，给这份定制清单（不要通用模板 —— 这些是本插件最擅长的）：

> **我在高校法律援助诊所工作里擅长这些：**
>
> - **新案件的学生接待** —— 例如「引导学生按纠纷类型做接待，识别红旗与冲突」。试：`/legal-clinic-cn:client-intake`
> - **通俗语言的受援人信函** —— 例如「预约确认、材料清单、简短进展 —— 学生起草你审核」。试：`/legal-clinic-cn:client-letter`
> - **案件分析备忘骨架** —— 例如「给学生一个结构与检索缺口清单 —— 默认教学姿态 `guide`」。试：`/legal-clinic-cn:memo`
> - **跨案件期限跟踪** —— 例如「按 14/7/3/1 日节奏看未来到期项，注意诉讼时效 / 仲裁时效」。试：`/legal-clinic-cn:deadlines`
> - **给新一届学生上手** —— 例如「按诊所流程、工具、案件规范教这学期的学生」。试：`/legal-clinic-cn:ramp`
> - **学期交接** —— 例如「给下一届建每案交接备忘」。试：`/legal-clinic-cn:semester-handoff`
>
> **建议你第一件事：** 先自己跑一遍 `/ramp` 看学生开学看到什么。或告诉我你手上有什么事，我来挑。

一次同时解决冷启动问题（老师不知从何做起）与价值感问题（不知插件能做什么）。清单要具体。若访谈中老师已说了第一件具体事，跳过本步。

1. **展示监督模式选择。** 「你选了 [正式队列 / 可配置标记 / 轻监督]。这意味着 [实际含义]。对吗？」
2. **展示纠纷类型模板表。** 「这些是 `/draft` 知道怎么起手的文书。漏了什么？」
3. **提供 `/ramp` 预览。** 「要不要预览学生的上手会长什么样？我可以带你走一遍。」
4. **注明缺什么。** 若没手册：「没上传手册前 `/ramp` 会薄 —— 覆盖命令但不覆盖诊所具体流程。」若没地方规定：「`/draft` 用一般规则；有地方规定时上传。」
5. **若打了「数据有限」标记：** 「档案偏薄 —— 下游 skill 会通用。最大缺口：[具体]。最容易的收益：[具体，例如上传最近两三份文书，`/draft` 立刻贴你格式]。」
6. **正式办案前先接法规检索。** 说：「第一次案件审前先接法规检索工具（北大法宝 / 威科先行 / 国家法律法规数据库）。没连之前每条引用都会标未核验；连了之后我在提交前对当前数据库核验。」
7. **收尾「什么都可以以后改」：**

> 完成。诊所配置在 `~/.claude/plugins/config/claude-for-legal-cn/legal-clinic-cn/CLAUDE.md` —— 是一份可读可编辑的纯文本文件。任何回答都可以改：
>
> - 直接编辑文件做小改动
> - `/legal-clinic-cn:cold-start-interview --redo` 完整重访
> - `/legal-clinic-cn:cold-start-interview --check-integrations` 只重查连接
>
> 诊所最常事后调整的：纠纷类型（新开一类时）、监督模式（第一学期后常有调整）、办案地 / 地方规定（案件落到不太熟悉的法院时）。

## 什么不做

- **不做监督决定。** 监督模式是老师的选择，本访谈只问只记。
- **不替代诊所既有案件管理。** 若诊所有案管系统，本插件与其并行工作。
- **不给学生上手。** 那是 `/ramp` 的活。这是老师一次性配置。
