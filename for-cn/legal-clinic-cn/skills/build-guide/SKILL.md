# /build-guide

1. 读 `~/.claude/plugins/config/claude-for-legal-cn/legal-clinic-cn/CLAUDE.md` → 角色（须为指导老师）、纠纷类型、办案地。
2. 按下方工作流。
3. 若用户不是指导老师，停下并转向（学生跑 `/legal-clinic-cn:ramp`）。
4. 走：纠纷类型 → 接待问题 → 教学姿态 → 审核关卡 → 跨插件检查 → 地方规定。
5. 写入 `~/.claude/plugins/config/claude-for-legal-cn/legal-clinic-cn/guides/<纠纷类型>.md`。必要时创建 `guides/` 目录。
6. 提供试跑 —— 在配置好的教学姿态下运行 `/legal-clinic-cn:draft`，让老师看到学生会看到什么。

```
/legal-clinic-cn:build-guide
```

允许多份指引 —— 一个纠纷类型一份。重跑本命令可修订。快速改动直接编辑文件。

# 建立指引：指导老师撰写的纠纷类型指引

## 目的

老师指引是把学生面向 skill 从「把活干完」转成「教学生把活干好」的旋钮。本插件每个学生面向 skill 在产出前都读这份指引：
接待问的问题老师定；起草类 skill 挑教学姿态（assist / guide / teach）；审核关卡按老师关注点路由；跨插件检查把其它插件的 skill 包一层监督。

本 skill 帮老师用 5-10 分钟为一个纠纷类型编好指引。指引是纯 markdown，路径固定 —— 随时手改。

**受众：指导老师。** 不是学生。学生跑 `/legal-clinic-cn:ramp` 再跑学生面向 skill；不写指引。

## 工作成果头部

本 skill 的产出是**面向老师的配置文件**，不是学生工作成果。**不要**加 `[AI 辅助草稿 —— 须经学生分析与教师审核]` —— 该标注是学生产出用的。
本 skill 写的指引文件与 CLAUDE.md 并列存在插件配置目录，不在案件工作区。

## 你的指引应涵盖的关键项

作为开头清单让老师快速跳/用作访谈目录：

- 学生动手前必知什么？（伦理与行为底线：不代理出庭、不承诺结果、不收费、不以律师名义；保密与工作纪律）
- 本类型学生最常犯的 3-5 个错误，skill 该如何捕获？
- 什么时候学生必须停下要你签字？（提交法院/仲裁委、发受援人信函、做法律陈述、给案件策略建议）
- 面向受援人的通俗语言目标？（诊所常见目标：初中文化程度可读懂）
- 本类型学生要知道的地方规定、样式、期限？
- skill 何时该「教」、何时该「做」？（按文书类型设默认，可覆盖）

访谈开头走一遍让老师知道会问什么、能标记哪些项有强观点、哪些想边聊边想。老师明示跳过的记入指引「未指定 —— skill 用默认」。

## 工作流

### 第 1 步：查角色

老师专用 skill。读 `~/.claude/plugins/config/claude-for-legal-cn/legal-clinic-cn/CLAUDE.md` → `## 谁在用这份档案` → 角色。若不是「指导老师」，说：

> 本 skill 面向指导老师 —— 它配置学生面向 skill 的行为。若你是老师，请在 `/legal-clinic-cn:cold-start-interview` 里把角色设为「指导老师」。
> 若你是学生，本 skill 不适合你 —— 用 `/legal-clinic-cn:ramp` 上手，或请老师给你编一份指引。

角色不是老师就停。

### 第 2 步：哪个纠纷类型？

> 这份指引针对哪个纠纷类型？（劳动 / 婚姻家事 / 交通事故 / 民间借贷 / 房屋租赁 / 物业 / 消费维权 / 刑辩援助 / 其他）

答「其他」问一个短名 —— 该名成为文件名（小写连字符：`environmental-injury.md`、`elderly-rights.md`）。

对比 CLAUDE.md → `## 诊所概况` 与 Playbook。若所选类型不在诊所办理清单，注明：「我会写这份指引，但你诊所档案没列 [类型] 为办理类型。这没关系 ——
用 `/legal-clinic-cn:cold-start-interview --redo` 添加即可 —— 但学生面向 skill 在档案未列它之前不会把接待路由到这一类型。」

若指引已存于 `~/.claude/plugins/config/claude-for-legal-cn/legal-clinic-cn/guides/<纠纷类型>.md`，提问：「[类型] 指引已存在，路径 [path]。要 (a) 分节修订，(b) 全新覆盖，(c) 先看现有内容？」

### 第 3 步：接待问题

> 本诊所类型的新受援人要问什么？我先给 [纠纷类型] 通用接待默认 —— 告诉我要加、要减、要改的。红旗是什么？什么样的案件是本诊所的目标 vs. 该转介？

展示该类型的通用默认（与 `client-intake` 相同 —— 劳动：用人单位、合同、社保、争议起因、证据、仲裁时效 1 年、是否已仲裁；婚姻家事：关系、子女、人身安全、现有裁判、冷静期；交通/人身损害：事故认定、保险、伤情、误工、诉讼时效 3 年；民间借贷：借条、转账凭证、利率、时效；租赁/物业：合同、押金、争议、证据；消费：经营者、凭证、损害；刑辩援助：涉嫌罪名、阶段、强制措施、认罪认罚从宽，学生不会见不出庭）。四大类别之外的，请老师从头描述接待。

记录：要加、要减、要改措辞的问题；红旗清单；适合本诊所标准（受援人经济困难符合法律援助法第 41 条 `[a待核验：本地标准]`、纠纷类型属本诊所办理范围、无学生行为底线冲突）；转介标准。

### 第 4 步：教学姿态

> skill 做多少 vs. 学生做多少？
>
> - **guide（默认）：** skill 出结构，学生填实质，skill 给反馈。平衡 —— 多数诊所从此开始。
> - **assist：** skill 出成果，学生复核、修改、由此学习。最快，最省事，最少教学。适合高案件量。
> - **teach：** skill 不出成果 —— 学生先起草，skill 给反馈、追问，试过两次才给范例。最慢、最强教学。适合以学习为主要目标。
>
> 可按文书类型设定（例：受援人信函 teach、内部案件分析备忘 assist）。

记录本类型的默认姿态与文书类型覆盖。skill 读取字段：

- `pedagogy_posture_default: assist | guide | teach`
- `pedagogy_posture_client_letter: [覆盖]`
- `pedagogy_posture_memo: [覆盖]`
- `pedagogy_posture_draft: [覆盖]`

老师提到 skill 目前没有的文书类型时，记入 `pedagogy_posture_other:` 块并加注 —— 未来 skill 可读。

### 第 5 步：审核关卡

> 哪些工作成果需要你审核才能给受援人？哪些学生可直接送？默认：面向受援人的都要审。

以表格让老师填：

| 工作成果 | 关卡 |
|---|---|
| 接待记录 | [学生写；老师在讨论会审 / 老师在给受援人前审 / 学生留存] |
| 案件分析备忘（内部） | [老师审 / 学生留存] |
| 受援人信函（预约 / 材料清单 / 简短进展） | [老师审 / 学生直发] |
| 受援人信函（实质咨询 / 坏消息） | [必须老师 —— 不可覆盖] |
| 起诉状 / 仲裁申请书 / 答辩状（拟提交法院/仲裁委） | [必须指导老师 + 指派/合作律师 —— 不可覆盖] |
| 提交法院/仲裁委的状态说明 | [必须指导老师 + 指派/合作律师 —— 不可覆盖] |
| 检索路径 / 备忘骨架 | [学生直接使用] |

以下关卡不可协商：给出实质咨询的受援人信函、拟提交法院/仲裁委的材料、面向法院/仲裁委的状态说明，一律走指导老师 + 出庭代理律师。
学生**不能出庭代理**，涉出庭材料实质由律师签字或以律师名义提交（学生辅助）。

### 第 6 步：跨插件检查

> 是否要让学生用其它插件的 skill（定义术语检查、文书一致性、法规检索）？我可以包一层监督 ——
> 学生跑，产出的不确定处标给你审，不签字就不出。

按纠纷类型给具体例子：

- **劳动诊所：** `commercial-legal-cn:review` （若涉劳动合同/竞业条款审），学生审出竞业限制条款效力风险，标记等老师审。
- **交通事故 / 人身损害诊所：** `litigation-legal-cn:chronology` 从证据搭时间线，标记等老师审再进文书。
- **民间借贷 / 消费维权：** `commercial-legal-cn:review` 复核合同条款、`litigation-legal-cn:evidence-triage` 分流证据。
- **数据 / 个人信息线索：** `privacy-legal-cn:triage` —— 受援人涉个人信息侵权（如遭遇 App 违规、隐私泄露）时。

老师点名想用某跨插件 skill，记：skill 名、学生何时用、什么监督包装（一律老师审 / 只在标记时 / 不加）。

### 第 7 步：地方规定与办案地

> 你诊所在哪个法院/仲裁委办案？有哪些地方规定或表格学生要用？

对照 CLAUDE.md → `## 管辖与办案地` —— 主要法院与仲裁委在 cold-start 已设。本步用于本纠纷类型专属的地方规定与表格
（例：本地劳动仲裁委答辩期与举证期指引、本地法院对民间借贷电子证据的偏好、本地物业纠纷调解前置要求）。列一份指针清单让学生面向 skill 起草或建议时使用。

> 要看教学姿态怎么改变体验吗？我会用一份样本受援人信函在 [姿态] 下跑一遍 `/legal-clinic-cn:draft` —— 你看到学生会看到什么。

老师同意就模拟起草 skill 读你刚写的指引、在配置姿态下产出。走完一整轮让老师精确看到学生看到什么。

## 输出

本 skill 的「输出」是写入 `~/.claude/plugins/config/claude-for-legal-cn/legal-clinic-cn/guides/<纠纷类型>.md` 的文件。与老师的对话是访谈；写下的指引是产物。

写完显示简短确认：

> **指引已写。** `[纠纷类型]` 已配置：
>
> - 接待：[N] 个自定义问题、[N] 个红旗、[N] 条转介标准
> - 教学：[默认姿态]，覆盖 [列表]
> - 审核关卡：[路由到老师/学生的摘要]
> - 跨插件：[N] 个 skill 已接入
>
> 学生下次跑本纠纷类型的诊所命令时会看到变化。手改 `[path]` 改动任何项，或再跑 `/legal-clinic-cn:build-guide` 修订。

## 本 skill 不做的事

- **不做插件级配置。** 指引是按纠纷类型的。插件级配置（监督模式、办案地、纠纷类型清单）是 `/legal-clinic-cn:cold-start-interview`。
- **不产出学生工作成果。** 这是老师面向配置，不是给受援人的草稿。
- **不覆盖 cold-start 里选的监督模式。** 监督模式（正式队列 / 可配置标记 / 轻监督）在 setup 定。指引的审核关卡为本纠纷类型细化该模式，不替换。
- **不让学生 skill 跳过 AI 辅助头部、不确定标记或核验提示。** 这些是共同护栏基线。指引改姿态，不改护栏。
- **不改学生行为底线。** 学生不代理出庭、不承诺结果、不收费、不以律师名义 —— 老师指引里不能开例外。

## 转换决策自检

- **A 级直转：** 9 步工作流骨架、教学姿态 3 选（assist/guide/teach）、审核关卡表结构、跨插件检查列表机制、指引文件模板结构。
- **B 级大改：** 纠纷类型清单（immigration/housing/family/consumer → 劳动 / 婚姻家事 / 交通事故 / 民间借贷 / 租赁物业 / 消费维权 / 刑辩援助）；跨插件 skill 例子改成 for-cn 系（`commercial-legal-cn:review`、`litigation-legal-cn:chronology` / `evidence-triage`、`privacy-legal-cn:triage`）；审核关卡里的「Draft filing (court/agency)」→ 「拟提交法院/仲裁委材料 —— 指导老师 + 出庭代理律师（固定；学生不代理出庭）」。
- **C 级重写：** 「学生动手前必知」加入学生行为底线 4 条；不可协商关卡里加入「出庭代理律师签字」维度（美式只需 supervising attorney，中式明确律师身份）。
- **D 级新增：** 「本纠纷类型专属地方规定」段位加入本地劳动仲裁委答辩期与举证期指引、地方民间借贷电子证据偏好等中式特有指针；「学生不改行为底线」显式写入本 skill 不做的事。
