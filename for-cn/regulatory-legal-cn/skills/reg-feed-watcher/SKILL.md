# /reg-feed-watcher

1. 读取 `~/.claude/plugins/config/claude-for-legal-cn/regulatory-legal-cn/CLAUDE.md` → 监控清单、重要性阈值、信息源配置。
2. 使用下文的工作流。
3. 逐源拉取。按重要性阈值过滤。
4. 输出：新增内容，按重要性分栏。

---

## 目的

拉信息源。按重要性过滤。产出剩下的。**过滤本身**才是价值 —— 未过滤的信息源是噪音。

## 加载上下文

- `~/.claude/plugins/config/claude-for-legal-cn/regulatory-legal-cn/CLAUDE.md` → 监控清单、重要性阈值、信息源配置、摘要输出路径（若已设）
- `references/source-catalog-cn.md`（本插件 references/ 下）→ 中国监管源目录，按立法机关 / 网络数据监管 / 市监与反垄断 / 司法机关 / 行业监管 / 地方监管 / 二级源 / 无 feed 需网页监控整理。配置新源或用户监控清单有覆盖缺口时使用（见 Step 0）。

## 工作流

### Step 0：覆盖检查（拉取前）

拉取前，比对 CLAUDE.md 中监控清单 + 信息源配置与 `references/source-catalog-cn.md`：

- 用户按监控清单关心哪些类别（立法机关 / 网络数据监管 / 市监与反垄断 / 司法机关 / 行业监管 / 地方监管）？
- 这些类别中哪些配置的源为 0 或极少？

若有明显缺口 —— 例如用户监控清单包含「个人信息保护合规」但只配置了 `cac.gov.cn/gzzcwj/`，缺少 App 通报页与国家标准委 —— 在摘要顶部**一次性**浮现：

> **发现覆盖缺口：** 你的监控清单包含 [类别]，但只配置了 [N] 个源。目录中该类别下列出 [X] 个选项（例如 [名称 2-3 个]）。要不要建议补入？运行 `/regulatory-legal-cn:cold-start-interview --redo` 更新，或直接编辑 CLAUDE.md。

不要就同一缺口反复唠叨 —— 若用户明确说过「地方监管暂不接」，就尊重这个立场。把该立场落进 CLAUDE.md，让它固化。

### Step 1：拉取

按已配置的分级拉取。每个安装都有 Tier 1。Tier 2、3 是**追加**，配了就用，没配就跳。

**Tier 1 —— 免费源（始终启用）**

中国监管网站**大多无 RSS**。默认按下列方式拉：

- **国家法律法规数据库（`flk.npc.gov.cn`）** —— HTML，有站内检索。做**列表页快照对比**发现新增法律 / 行政法规 / 部门规章 / 司法解释；结果含时间效力状态，是判断现行有效性的权威依据
- **国务院政策库（`gov.cn/zhengce/`）** —— HTML + 部分栏目有 RSS。国务院令、国办发文首发地
- **国家网信办政策文件（`cac.gov.cn/gzzcwj/`）** —— HTML。个保法配套规则的首发地
- **网信办征求意见（`cac.gov.cn/gzzcwj/zqyj/`）** —— HTML。窗口期通常 30 日
- **网信办 App 通报（`cac.gov.cn/pdcx/`）** —— HTML。执法风向标
- **工信部 App 通报（`miit.gov.cn/jgsj/xgj/`）** —— HTML。与网信办互补
- **市监总局政策法规（`samr.gov.cn/zw/zfxxgk/`）** —— HTML。反垄断、反不正当竞争、广告、消费者权益
- **最高法（`court.gov.cn`）** —— HTML + 部分 RSS。司法解释、指导性案例
- **人民法院案例库（`rmfyalk.court.gov.cn`）** —— HTML，需注册
- **信用中国（`creditchina.gov.cn`）** —— HTML。行政处罚、失信被执行人
- **行业监管**（按业务领域选配）—— 央行、金融监督管理总局、证监会、药监局、卫健委、教育部、广电总局

**中国监管源拉取要点：**

1. **绝大多数需要网页变更检测。** 对政策文件列表页做定期快照对比，检测新增条目。单源间隔**不低于 6 小时** —— 高频抓取会触发封禁，遵守目标站点服务条款与 `robots.txt`。
2. **部分站点反爬严格**（企业信用信息公示系统、裁判文书网等），自动化拉取不稳定。这类源标为 `[需人工确认]`，只登记「今日检查」时间戳，让用户手工核查。
3. **地方监管**按注册地和主要经营地选配。上海、深圳、北京、海南、天津自贸区等立法活跃度高。
4. **付费专业数据库**（北大法宝、威科先行、法信）：若已通过 MCP 连接，用它们做**法条现行状态核验** —— 不是新增拉取的主渠道。

**Tier 2 —— 付费源（如已配置）**

- **北大法宝 MCP：** 查询按日期过滤的新增；主要用途是**核验现行有效性**（有效 / 已修改 / 已废止）
- **威科先行 MCP：** 同上，附解读

跨源去重 —— 同一份规章可能出现在多个源。选**信息最丰富**的源作为主展示。

**不做静默补足。** 若信息源拉取对监控清单中的某机关返回极少或没有结果，报告已找到的内容并停下。**不要**从网络检索或模型知识补齐。说：「本次检查从 [已命中机关] 找到 [N] 项。[某机关 / 某主题] 覆盖偏薄。选项：（1）扩大时间窗口；（2）换一个源或 MCP；（3）从网络检索 —— 结果会被标 `[网页 —— 待核验]`，据以行动前请对照发布机关核验；（4）在这里停下。」由律师决定是否接受较低置信度的源。

**来源标注。** 每条引用和监管条目都要标来源：`[国家法律法规数据库]`、`[网信办官网]`、`[市监总局官网]` 等一级源；`[北大法宝]`、`[威科先行]`（专业数据库）；`[网页 —— 待核验]`（网络检索）；`[模型知识 —— 待核验]`（训练数据回忆）；`[用户提供]`（手工粘贴）。带 `待核验` 的 fabrication 风险更高，先核。**不得**在输出中剥离或合并这些标签 —— 它们是用户判断先核哪条引用的最快信号。

**二级源。** 目录中的部分条目（律所公众号、IAPP 中国专栏、法律媒体、行业协会解读）是对一级监管动态的**评论 / 转述**，不是一级源。任何拉自这些源的条目，在 feed 名称标签之外再加 `[二级源]` —— 例如 `[某律所公众号] [二级源]`。摘要中如二级源描述监管动作，追加一行：「→ 回溯一级源：[发布机关 URL，或『先到 xxx.gov.cn 查证再据以行动』]。」二级源单独不能升为「始终重要」—— 在找到一级源之前**降一档**处理。

**Tier 3 —— 手工录入**

若用户是手工粘贴监管文本 / 摘要（不是从计划触发进来）：把粘贴内容视为一条，跳到 Step 2 分类，来源记为「手工录入」。**不做拉取**。这条路径与订阅状态无关。

拉取后记录检查时间戳。下次计划触发从此时起向前拉。

### Step 2：分类

每条按 `~/.claude/plugins/config/claude-for-legal-cn/regulatory-legal-cn/CLAUDE.md` 中的重要性阈值分类：

| 条目类型 | 与阈值匹配 |
|---|---|
| 正式发布的法律 / 行政法规 / 部门规章 | 通常「始终重要」 |
| 征求意见稿（公开征求意见） | 通常「值得关注」—— **必须**登记意见截止日 |
| 司法解释 | 「始终重要」若涉及监控范围 |
| 指导性案例 / 参考案例 | 「值得关注」 |
| 行政处罚 / 执法通报 | 同业匹配 → 重要；相关业务匹配 → 值得关注；均无 → 参考或跳过 |
| App 通报 / 违法违规通报 | 涉及类似业务 → 值得关注；执法风向标价值 |
| 规范性文件（通知 / 意见 / 公告） | 值得关注；注意其**通常不构成强制法源**，但监管认可度高 |
| 官员讲话 / 部委解读文章 | 参考或跳过 |
| 立法草案初次公开（意见征集通知） | 值得关注（策略性）—— **不**升为「始终重要」，因为尚无强制义务 |

**征求意见稿处理 —— 具体规则。** 草案条目与正式稿在一点上关键不同：**它们不改变现行法，但它们承载截止日和方向信号**。视为独立分支：

- **不要**把草案分类为「始终重要」—— 合规影响直到正式稿出台前为零
- **可以**分类为「值得关注」若通知的问题领域触及监控清单的「始终重要」类别（例如个人信息保护类企业遇到网信办数据出境规章草案）
- **登记意见截止日**到 `~/.claude/plugins/config/claude-for-legal-cn/regulatory-legal-cn/comment-tracker.yaml`，`item_type: draft`（草案）
- **摘要条目中明确注明：** 「草案。意见截止日 [日期]。转 `/regulatory-legal-cn:policy-diff` 时使用『前置站位分析』分支（尚无合规缺口）。」这提示 policy-diff 使用压缩的前置站位分支而不是完整缺口 diff
- **路由到 comment-tracker，不是 gap-tracker。** 意见决策项不是合规缺口；它们归意见跟踪表，或者 `gap-surfacer` 使用 `comment-decision` 类型（或依团队约定直接分开）

**草案截止日处理：**

对每条草案（分类高于「跳过」）：
- 抽取意见截止日（多数发布机关公告页会明确标出「反馈截止日」）
- 若 CLAUDE.md 中已启用意见追踪：追加到 comment-tracker.yaml，状态「未决定」，默认意见决策责任人取自 CLAUDE.md
- 在输出条目中包含意见截止日

### Step 3：丰富

对每条高于「参考」的条目：

- 一句话摘要（发生了什么）
- 为什么在本公司这里可能重要（相关性锚点 —— 「这条涉及 [你正在做的实务]」）
- 一级源链接
- 生效日 / 施行日 或 意见截止日（如适用）
- 效力层级（法律 / 行政法规 / 部门规章 / 规范性文件 / 地方性法规）

「参考」条目**不逐条摘要** —— 只计数。

## 输出

摘要默认进入对话。**同时写入一份可分享的文件**，若输出含一条或以上高于「参考」的条目，除非用户 CLAUDE.md 中明确设 `摘要输出 → 仅对话`。

**文件输出行为：**

1. 查 `~/.claude/plugins/config/claude-for-legal-cn/regulatory-legal-cn/CLAUDE.md` 中 `摘要输出路径`。已设则写到那里。未设默认：`~/regulatory-legal-cn-digests/reg-digest-YYYY-MM-DD.md`
2. 需要时创建父目录
3. 以 Markdown 写完整摘要（与对话输出一致，含输出头部、来源标签、页脚的「引用请核验」段）
4. 若同日文件已存在：追加一个带时间戳的子标题，不覆盖 —— 同一天可能多次运行（周一晨读 + 临时检查）
5. 写完告诉用户：「摘要写入 `<路径>`。可直接分享，或用 Pandoc 转 docx：`pandoc <路径> -o <路径>.docx`。」
6. 若写入失败（权限、目录未授权、磁盘），回退为仅对话输出，并说明 —— 不静默丢弃

磁盘上的格式与对话格式**完全一致**（下文）。Markdown 在 GitHub、飞书、企业微信、语雀、Notion、腾讯文档等多数工具中都可渲染或粘贴。

## 周一晨读摘要（中国实务场景）

按周一晨会场景，本技能也可产出**周一晨读摘要**。输出格式：

```markdown
# 周一晨读 —— [日期]

| 新规名称 | 发布机关 | 效力层级 | 生效日 | 对本公司影响 | 建议行动 |
|---|---|---|---|---|---|
| [名称] | [机关] | [部门规章] | [日期] | [业务 / 制度触及点] | [跑 policy-diff / 关注意见截止日 / 无需行动] |

**本周意见截止日：** [列出]
**本周合规缺口进展：** [来自 gaps]
```

若用户在 CLAUDE.md 或调用时指定「晨读格式」，用上表；否则默认用「监管动态摘要」格式。

## 档案缺失时的回退

本技能从 `~/.claude/plugins/config/claude-for-legal-cn/regulatory-legal-cn/CLAUDE.md` 读取监控清单、重要性阈值、信息源配置。当所需值仍为 `[待填写]` 或为空，在输出中**具体地**说明，不要泛泛说：

- **监控清单为空：** 停下并说：「你档案中的监控清单为空。没有监控目标就无法拉信息源。请运行 `/regulatory-legal-cn:cold-start-interview --redo` 或编辑 CLAUDE.md 补入至少一个监管机关。」
- **重要性阈值为空：** 回退到默认分层，输出追加：「本输出使用了默认重要性阈值，因为你的档案中未设自定义阈值。请通过 cold-start-interview --redo 或编辑 CLAUDE.md 调整。」
- **信息源配置为空：** 仅拉取国家法律法规数据库 + 网信办公开政策页，输出追加：「本输出仅使用了国家法律法规数据库与网信办公开政策页，因为你的档案未列直接源或付费源连接。请通过 cold-start-interview --redo 或编辑 CLAUDE.md 补充源。」

值已填写时不要提配置。

若无高于「参考」的条目：「一切平静。[N] 条参考项，无需关注。」

## 交接

- **给 policy-diff：** 任一「始终重要」且可能影响制度的条目 → 提议跑 diff
- **给 gap-surfacer：** 若 diff 发现缺口 → 加入追踪表
- **给 comment-tracker：** 任一草案（高于「跳过」）→ 意见截止日自动登记，若意见追踪已启用

## 以下一步决策树收尾

按 CLAUDE.md `## 输出` 的规范收尾。把默认五个分支（起草 X、升级、补事实、观察等待、其他）调整为本次输出实际产生的内容。决策树是输出 —— 律师做选择。

## 本技能不做的事

- 不逐条读完全部条目。分类 + 丰富 —— 深读留给通过过滤的条目
- 不改重要性阈值。若过滤反了，编辑 CLAUDE.md
- 不强依赖付费数据库。免费源是基线 —— 付费源加深度

## 转换决策自检

- **分级：** C 重写为主 + 部分 B —— 拉取源清单从美国联邦（Federal Register API / SEC RSS / FTC RSS）**完全替换**为中国监管信息源目录（国家法律法规数据库、网信办、工信部、市监总局、最高法、行业监管）；网页变更检测取代 RSS 成为主要机制。
- **主要变化：** 加入中国立法效力层级意识（法律 / 行政法规 / 部门规章 / 规范性文件 / 地方性法规）到分类逻辑；引入「反爬严格 —— 需人工确认」的源分类；新增中国实务场景的「周一晨读摘要」输出格式；抓取合规提示（robots、单源间隔 ≥ 6 小时）；ANPR / RFI 替换为「征求意见稿 / 意见征集通知」。
