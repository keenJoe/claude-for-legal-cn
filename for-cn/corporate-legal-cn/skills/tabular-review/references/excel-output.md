# Excel 输出规范

Excel 文件是大多数交易团队实际打开的交付物。做对它。

## 若 Claude in Excel / Office agent 可用

通过 Office agent 直接在 Excel 中构建工作簿。这是首选路径，因为它保留格式、让审阅者在原生工具中工作、并原生支持单元格批注模式。

## 否则用 openpyxl

用 `python3 -c "import openpyxl"` 检查。若未安装，提议安装（`pip3 install openpyxl`）或回退到 CSV。

## 工作簿结构

**表 1：`审查`**（主网格）
- 第 1 行：待审核草稿头（合并单元格，档案 `## 输出` 中的头）
- 第 2 行：列标签
- 第 3 行起：每份文档一行
- A 列：文档名 / 路径
- B 列起：每 schema 列一列，按 schema 顺序
- 每个数据列后跟一个隐藏 `_source` 列，含 `[引用] | [位置]`
- 数据列单元格上的单元格批注 = 引用和位置（悬停时浮现，即便 `_source` 隐藏）
- 按状态填充色：无填充 = `answered`，`#FFF2CC`（浅黄）= `unclear` 或 `needs_review`，`#EFEFEF`（浅灰）= `not_present`
- 每组 [数据 + _source] 后加 `已核验` 列：默认空白。审阅者填。下拉验证：`✓`、`✗`、`?`。

**表 2：`标记`**
- 每个被标为 `unclear` 或 `needs_review` 的单元格一行
- 列：文档、列、状态、值（若有）、引用、位置、注记
- 这是核验工作队列。按列排序让审阅者批量做类似判断。

**表 3：`_schema`**
- `.review-schema.yaml` 中的列定义，每列一行：id、label、type、options、prompt
- 让文件自文档化。半年后打开文件的合伙人能准确看到问了什么。

**表 4：`_summary`**
- 文档数、列数、运行日期
- 每列 answered / not_present / unclear / needs_review 的计数
- 归一化通过标记的列清单
- 核验提醒文本

## 不要做的

- 不要写置信度百分比列。不是信息。状态 + 引用是信号。
- 不要为塞进单元格截断引用。文本换行或把完整引用放批注。
- 不要在数据区合并单元格。律师会排序和过滤。
- 不要写没有 `_schema` 和 `_summary` 表的表。自文档化是让文件可信的原因。

## 公式注入防御

在 Excel、表格或 CSV 输出中写入任何单元格前，中和公式注入。相对方来源文本（合同引用、当事方名称、代理数据、合同管理系统导出）是攻击者可控的。以 `=`、`+`、`-`、`@`、制表符、回车、换行开头的单元格会被当作公式或破坏行结构。

- **前缀单引号：** `'=SUM(A1:A10)` → `=SUM(A1:A10)`（显示为文本，不执行）
- **适用于每个含文档、工具结果或用户粘贴来源文本的单元格。** 你控制的列标题和你计算的值是安全的。
- **CSV：还要转义嵌入的逗号、双引号、换行**（RFC 4180 引用）。
- 这不是可选项。用户在 Excel 打开你的表格触发宏或通过 DDE 泄露数据，是对用户的供应链攻击。
