# /oc-status

要每周运行，可在企业微信/钉钉/Outlook 中设定周一晨间循环提醒调用 `/litigation-legal-cn:oc-status`。自动化调度需要定时任务集成，不与本插件捆绑。

1. 加载 `_log.yaml`，按默认规则过滤（或参数）。
2. 加载 `CLAUDE.md` —— 外聘律师沟通风格、签发人默认、预算立场。
3. 按下方工作流。
4. 每个在范围内的案件：读 `matter.md` + `history.md`，草拟每案邮件。
5. 写 Markdown 到 `~/.claude/plugins/config/claude-for-legal-cn/litigation-legal-cn/oc-status/[YYYY-MM-DD]/[slug].md`。
6. 若邮件 MCP 已认证：建邮件草稿。否则仅 Markdown 并在摘要中说明。
7. 写 `~/.claude/plugins/config/claude-for-legal-cn/litigation-legal-cn/oc-status/[YYYY-MM-DD]/_summary.md` —— 跑了什么、跳过了什么、原因。

# 外聘律师状态

## 目的

每周跨 5–15 个案件给外聘律师写同一封状态问询是机械的认知税。内容按案件保持一致（进度、待决问题、预算），受众一致（外聘主办律师），语气一致（按律所对接习惯）。定时任务把这些都草拟出来；用户复核后发送。

## 加载上下文

- `_log.yaml` —— 过滤与字段来源
- `matter.md` —— 案件上下文（当前节点、待决问题）
- `history.md` —— 近期事件（决定问什么）
- `CLAUDE.md` —— 外聘律师沟通风格、签发人姓名/邮箱、预算立场

## 过滤 —— 挑哪些案件

默认过滤：

- `status != 已结案`
- `outside_counsel.firm != null` 且 `outside_counsel.lead != null`
- 满足以下之一：距最后更新超过 10 天（时间足够发生事情）或 `next_deadline` 在 21 天以内

跳过：最近 10 天内已更新的（不用再问）、`outside_counsel.email` 为空的（邮件草稿需邮箱；仍出 Markdown）。

参数：
- `--all` —— 每个活跃案件都草拟，不看时效
- `--slug=[slug]` —— 仅指定一个（临时请求）
- `--no-mail` —— 即便邮件 MCP 可用也不建草稿

## 每案邮件草稿

同一骨架，内容按案件填。

**主题：** 按律所对接习惯（从 `CLAUDE.md`；缺省 `[案件名] —— 周度状态更新`）

**正文骨架：**

```
[主办律师姓/名]，

[一句自然的开头，匹配律所对接语气]

想同步一下 [案件名] 的进展，几件事想请你确认：

1. **自 [history.md 最后更新日] 以来的进展** —— 有什么动了、什么在等？上次沟通后有立案文书、开庭、往来函件或电话吗？

2. **临近期限** —— 我这边看到 [_log.yaml 中的 next_deadline + matter.md 中的其他期限]。确认覆盖计划，以及是否有该加入的日期。

3. **待决问题** —— [从 matter.md 提取需要外聘律师意见的问题；若无就省略此项并重编号]

4. **费用与预算** —— [按 CLAUDE.md 预算立场：月度/季度/按需]。当前 vs [matter.md 中的委托预算授权]？有偏差要提示吗？

[若实质相关：5. 具体请求 —— 例如「请把答辩状草稿在 [日期] 前发我看下」—— 从 matter.md 待决问题引出]

[署名 —— 姓名、职务、联系方式。从 CLAUDE.md 外聘律师沟通签发人默认]
```

按 `CLAUDE.md` 外聘律师沟通风格调整语气 —— 有的团队正式「贵所」「贵律师」，有的团队直呼其名+要点罗列。匹配。

## 输出

### Markdown 草稿

写到：`oc-status/[YYYY-MM-DD]/[slug].md`

每份是一封邮件，格式：

```markdown
本文件由 AI 辅助生成，是待律师审核的工作草稿，不构成法律意见。
审查人：[姓名]  日期：[今日]  已读范围：[matter.md + history.md 近 10 条]

# [案件名] —— 外聘律师状态邮件 —— [YYYY-MM-DD]

**收件人：** [outside_counsel.email]（[outside_counsel.lead]，[outside_counsel.firm]）
**发件人：** [CLAUDE.md 签发人]
**主题：** [主题行]

> 上方护栏头适用于此内部记录。发出邮件对外聘律师是委托关系下的沟通，属于律师保密义务范围（律师法第 38 条 + 最高法民诉证据规定第 96 条诉讼代理人保密），发送前按 CLAUDE.md 律师保密约定加上外发标记（例如「本函件受律师-委托人保密义务约束」），而不是这里的内部草稿头。

---

[正文按骨架]
```

### 发送关卡（每份草稿的收尾提示）

在每份 Markdown 草稿的正文之后、运行元数据之前追加 —— 发送前删除：

> 这是给律师审核的邮件草稿，不是可直接发送的邮件。检查是否含有本意不外发的分析细节、事实准确性、语气、预算立场。未审阅前不要发送 —— 即便是例行周检，也可能不小心把策略、观点或让步表述写入书面。

### 邮件 MCP 建草稿（若可用）

若企业微信邮件、Outlook、Gmail 等 MCP 已认证：

- 每案在用户邮箱建草稿，`to`、`from`、`subject`、`body` 填好
- 草稿留在草稿箱，用户周一早上复核后发送
- 若 MCP 不可用或失败：回退到仅 Markdown 并告知用户

### 运行摘要

处理完所有案件后写 `oc-status/[YYYY-MM-DD]/_summary.md`：

```markdown
# 外聘律师状态运行 —— [YYYY-MM-DD]

**处理案件数：** [N]
**生成草稿数：** [N]
**邮件系统草稿：** [已建 / 跳过 —— 原因]

## 已草拟

| 案件 | 主办律师 | 最后更新 | 纳入原因 |
|---|---|---|---|
| [slug] | [主办] | [日期] | [陈旧 / 临近期限 / --all / --slug] |

## 已跳过

| 案件 | 原因 |
|---|---|
| [slug] | 近期更新（最后触碰 [日期]） |
| [slug] | 台账中无外聘律师邮箱 —— 用 `/matter-update [slug]` 更新 |

## 异常

- 无外聘律师的案件：[列表 —— 高/严重风险者标注]
- 有外聘律师但邮箱缺失的案件：[列表]
```

## 调度

本 skill 面向每周运行设计。自动化调度需要定时任务集成，本插件不捆绑。要每周运行，可用日历/待办循环提醒调用 `/litigation-legal-cn:oc-status` —— 例如周一早上。

临时：任何时候 `/oc-status`。单案：`/oc-status --slug=案件`。

## 转换决策

- 分级：**A 直接转化**。工作流保留（过滤 → 每案草稿 → 摘要）；实体层：Gmail MCP 换为企业微信/钉钉/Outlook；「house tone」示例换为中式外聘律师沟通语气（「[姓]律师，请问...」vs 「Hi J, quick check-in」）；律师保密援引改为律师法第 38 条与最高法民诉证据规定第 96 条。

## 这个 skill 不做的事

- **发送邮件。** 只草拟。律师复核后发送。
- **凭空生成内容。** 若 `matter.md` 稀薄，邮件就短、问宽泛问题。不无中生有具体问题。
- **重试失败。** 邮件草稿建到中间失败就记录并继续 Markdown。用户修好授权后再重跑。
- **改写 `history.md`。** 读取用作上下文；不改。若外聘律师回复带来新事件，用 `/matter-update` 记录。
- **强制模板。** 若律所对接就是「一行、直呼其名、完了」，草稿就照办，不套骨架。匹配 `CLAUDE.md`。
