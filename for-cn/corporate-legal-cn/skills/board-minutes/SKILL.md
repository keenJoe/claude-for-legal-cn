# /board-minutes

## 事项上下文

**事项上下文。** 检查执业档案 CLAUDE.md 中的 `## 事项工作区`。若 `启用` 为 `✗`（法务用户的默认值），跳过本段其余内容——技能直接使用执业层上下文，事项机制不可见。若已启用且没有活动事项，询问：「这是哪个事项？运行 `/corporate-legal-cn:matter-workspace switch <slug>` 或说『执业层』。」加载活动事项的 `matter.md` 获取事项特有上下文与覆盖项。输出写入事项文件夹 `~/.claude/plugins/config/claude-for-legal-cn/corporate-legal-cn/matters/<matter-slug>/`。除非 `跨事项上下文` 为 `开`，绝不读取其他事项的文件。

## 用途

董事会会议记录是法律文件。它必须准确、完整、经得起审视——无论是融资尽调审查、监管问询，还是并购项目的资料室。本技能按本所/本部门格式起草记录，让你把时间花在审核和修正上，而不是排版和重打。

## 加载上下文

- `~/.claude/plugins/config/claude-for-legal-cn/corporate-legal-cn/CLAUDE.md` → `## 董事会与公司秘书` 节：
  - 记录格式（长叙事式 / 决议摘要式 / 混合式）
  - 从种子文件提取的记录模板（结构、决议表述、抬头格式）
  - 董事会构成与委员会设置
  - 书面决议——用途与限制
- 如果档案没有记录格式：先跑 cold-start。不要用通用格式往下走。

## 第 1 步：确认会议

### 日历检测

如果日历连接器已授权，搜索即将发生的事件，匹配董事会与委员会关键词：

**搜索词：**「董事会」「董事会议」「审计委员会」「薪酬委员会」「提名委员会」「战略委员会」「专门委员会」「监事会」等。

**时间窗：** 向前看 30 天。若未发现即将召开的会议，向后看 14 天（记录经常在会后补写）。

展示你找到的：

> 我在你的日历上找到以下董事会或委员会会议：
>
> 1. **[会议名称]** — [日期]，[时间]，[地点/线上]
> 2. **[会议名称]** — [日期]，[时间]，[地点/线上]
>
> 这是哪场会议？还是有一场不在这上面的？

如果日历连接器未授权或没有返回：直接问——什么会议、什么日期、什么类型（全体董事会 / 哪一委员会 / 股东会）。

### 需要确认的会议信息

会议确认后，补齐或核实：

- **会议类型：** 董事会全体会议 / [委员会名称] / 股东会
- **日期与时间**
- **地点或平台**（现场地址 / 腾讯会议 / 钉钉 / 飞书 / 电话会议）
- **召集与通知：** 是否按规定通知了？按章程与董事会议事规则，会议通知应在会议召开前 [N] 日发出（以章程/议事规则为准）。通知豁免或未通知的，记录中应注明并核查是否满足章程和公司法要求。

## 第 2 步：出席情况

索要出席名单，或在连接器已授权时从日历邀请中提取。

**到会董事：**
- 以档案 `## 董事会与公司秘书` 中的董事会构成作为起点
- 询问实际到会、缺席名单，以及缺席董事是否事先收到通知

**管理层到会：**
- 管理层哪些人参加？（总经理、财务负责人、董事会秘书等）
- 注明：管理层出席人员通常与董事分开列示

**列席人员：**
- 外部律师在场？（姓名与律所）
- 投资银行、审计师或其他顾问？
- 仅为特定议程事项列席的嘉宾（注明仅就该事项列席）

**主持人：** 谁主持？谁作记录（会议记录人）？

**法定人数：**

- 核对章程和董事会议事规则中的法定人数要求。公司章程未约定的，按公司法的默认规则——董事会会议应当有过半数董事出席方可举行，决议须经全体董事的过半数通过 `[公司法（2023 修订）— 具体条文号待核验]`。章程可以约定更高的比例。
- 确认已达到法定人数。未达到：停下并在起草前提示。不要产出暗示会议合法有效的记录。把问题提交给外部律师——补救路径（追认、重新开会、书面决议、其他）取决于公司类型、章程约定和决议事项的性质。

## 第 3 步：材料

索要会议材料。这是议程事项和决议的来源。

> 能把这次会议的议程和会议材料发我吗？哪怕只是一个粗略的议程也足够搭出记录骨架。如果有董事会汇报材料或管理层演示，也一并上传——我会用它们填充议程事项摘要。
>
> 如果材料没有提前分发，告诉我议程事项，我为每项起草占位符。

**从议程和材料中提取：**
- 议程事项及顺序
- 拟议决议（找董事会审批用语：「批准」「授权」「追认」「通过」「选举」）
- 引用的附件（管理层汇报、财务报告、法律备忘录、估值报告）
- 预期表决事项

**如果完全没有材料：** 口头问议程事项，讨论内容用占位符。

---

## 第 4 步：起草记录

使用档案中的本所格式。不要默认通用格式。种子记录就是模板——复刻其结构、抬头、决议表述、讨论细节的详细程度。

### 标准结构（按本所格式调整）

**抬头块：**
```
[公司名称]
[会议类型]会议记录
[日期]
[地点 / 电话 / 视频会议]
```

**开场：**
- [主持人] 于 [时间] 宣布开会
- 通知情况：[按规定通知 / 通知豁免——如适用，说明依据]
- 法定人数确认：[M 名董事中 N 名到会]
- 记录人：[姓名]

**出席人员：**
- 到会董事：[名单]
- 缺席董事：[名单，如有]
- 列席人员：[管理层、外部律师、嘉宾——注明身份]

**上次会议记录：**
标准表述：确认上次会议记录。如有董事会日历可查，取上次会议日期；否则留 [上次会议日期]。

**议程事项——每项一节：**

```
[议程事项标题]

[报告人姓名] [作了汇报 / 报告 / 主持讨论了] [议题]。

[讨论摘要——见起草注释]

[如有决议：]
经与会董事审议，会议决议如下[经全体董事过半数通过 / 表决结果为 N 票赞成、N 票反对、N 票弃权]：

[决议内容——按档案中的本所表述]
```

**闭会：**
标准表述：会议于 [时间] 闭会，无其他事项。

**签署栏：**
记录人签名栏。部分格式含主持人共同签名。

---

### 起草注释

**讨论摘要：** 记录最难的部分是决定记录多少讨论。严格按种子文件中的本所格式：

- *长叙事式：* 概括讨论实质——提出了哪些问题、呈现了哪些信息、董事会考虑了哪些因素。除非具体归因在法律上有意义，不要引用个人发言。
- *决议摘要式：* 只记录什么被提交、什么被决定。「董事会讨论了该事项」之外的讨论内容不写。
- *混合式：* 重大事项（并购、财务、重要批准）全叙事，常规事项只记决议。

有材料时：从演示文稿和管理层汇报中摘出摘要内容。董事会「听取并审议了」某汇报——概括汇报覆盖了什么。

无材料时：插入 `[占位符——此处概括讨论内容]` 并明确标注。不要虚构讨论内容。

**决议：** 使用种子记录中的准确决议表述。决议语言是本所风格，不可随意替换。

**附件引用：** 按出现顺序编号（附件 A、B、C）。常见附件：管理层汇报、财务报表、估值报告、法律意见、通知豁免文件、决议文本。

---

## 第 4.5 步：采用前的后果闸门

**在把记录定为最终版本之前：** 读档案 `## 谁在用`。若角色为**非律师**：

> 采用会议记录意味着它成为董事会决定事项的正式记录——它是会议所采取行动的授权依据。你是否已与律师核对？如是，继续。如否，这里有一页纸供你带去：
>
> - 决定了什么（决议、表决、谁在场）
> - 草稿记录了哪些内容、还有哪些是占位符
> - 未决问题（任何被标记的出席、法定人数或利益冲突问题）
> - 可能出什么问题（决议表述错误、披露缺失、法定人数瑕疵、讨论摘要泄露保密信息）
> - 要问律师什么（讨论深度是否适合本董事会的惯例；相关事项是否需要更多佐证文件）
>
> 如需寻找律师：可联系当地律师协会（律师工作委员会）或公共法律服务中心（法律援助机构）寻求推荐。

未获明确同意，不要越过此关卡产出可直接采用的最终版。标注「供律师审核的草稿」版本没问题。

## 第 5 步：输出与审阅提示

产出完整草稿。**会议记录本身是公司文件，不是保密分析材料**——不要给作为公司文件传阅的记录加上保密分析头。起草注释、占位符标记和下面的审阅清单属于工作文件——按档案 `## 输出`（不同角色不同）在工作文件上加上待审核草稿头：

```
[待审核草稿头——按档案 ## 输出——因角色而异；见 ## 谁在用]
```

草稿之后附审阅清单：

```
[待审核草稿头——按档案 ## 输出——因角色而异；见 ## 谁在用]

审阅清单——传阅前请核实：

□ 全部董事确认为到会/缺席（与实际出席情况核对）
□ 法定人数确认正确
□ 决议表述与实际通过内容一致（仔细核对措辞）
□ 表决记录正确——有无弃权或反对需要注明？
□ 附件编号与引用正确
□ 是否召开了专门讨论？（如有，单独加一段专门讨论记录）
□ 有无利益冲突披露？（相关董事回避与否，视情况注明）
□ 闭会时间待填
□ 外部律师是否已审阅？（如流程要求）
```

标记所有内容为占位符、需要律师补充的段落。

在草稿最后加一段采用前提示（采用时删除）：

> 本文件为供律师审核的草稿，不是已采用的会议记录。已采用的记录是公司行为的正式记录并产生法律后果——须由执业律师审核、修改并承担专业责任后方可采用。未经审核，不要将本稿作为正式记录使用。

## 书面决议

起草不召开会议的书面决议时，使用 `/corporate-legal-cn:written-consent`。该技能处理先例检索、合法性确认以及对重大一次性动作的范围警示。

**中国法注意：** 不召开会议的书面决议在中国法下适用面与英美法不同——有限责任公司股东会经全体股东书面一致同意可以不召开会议直接作出决议（章程另有规定的除外）`[待核验条文号]`；董事会的书面决议则更依赖章程与董事会议事规则的授权，若章程或议事规则未规定，重大事项建议仍召开会议。与本技能无关的一揽子书面核准，先核对档案中董事会与公司秘书节的立场。

## 本 skill 不做的事

- 不参加实际会议、不记录现场讨论——它依据材料和律师输入起草。
- 不判断某一决议是否合法有效或充分——它按本所格式起草；法律判断是律师的事。
- 不最终定稿——草稿须经律师审核后才能传阅。
- 不分发记录——输出供律师审核、修改，并通过自己的流程传阅。

## 质量自检

本次转换决策：本技能为 B 级大改。框架保留（识别会议→出席与法定人数→材料→起草→审阅），实体法重写：法定人数与表决规则改为公司法（2023 修订）「半数以上董事出席、全体董事过半数通过」加章程优先约定（条文号待核验，标 `[待核验条文号]`）；新增审计委员会替代监事会的提示；「书面决议」一节改为中国法语境（股东会全体一致书面同意可不召开会议；董事会书面决议依赖章程授权——与英美 UWC 的普遍适用不同，这是关键差异点）；律师转介改为中国语境（律协、法律援助、公共法律服务中心）；保密头替换为待审核草稿头。会议召集通知期限、记录人签名等按章程与中国法要求，具体条文号未核验处标 `[待核验条文号]`。
