**事项上下文。** 查执业档案的 `## 事项工作区`。`启用` 是 `✗`（内部产品法务的默认）就跳过本段 —— 技能用执业档案层上下文，事项机制不可见。启用但无当前事项时问：「这是哪个事项？运行 `/product-legal-cn:matter-workspace switch <标识>` 或说 `执业档案层`。」加载当前事项的 `matter.md` 取事项级事实与覆盖项。输出写到 `~/.claude/plugins/config/claude-for-legal-cn/product-legal-cn/matters/<事项标识>/`。除非 `跨事项上下文` 为 `on`，绝不读其他事项的文件。

## 目的地检查

出结论前，看它去哪。用户点了目的地（群、分发列表、相对方、「所有人」）时，问它在不在保密范围内。公开群、全员群、相对方/对方律师、供应商、客户（对工作草稿）会破坏保密性。目的地在圈外时标出来，给三个版本：(a) 仅法务的完整版、(b) 面向对外的脱敏版、(c) 两个都要 —— 不要默默套上草稿头再帮着贴到草稿头保护不到的地方。见执业档案 `## 共同护栏 → 目的地检查`。

## 目的

多数「快速法律问题」是三种之一：(a) 没事，快说出来；(b) 是件事，路由过去；(c) 看着没事但有坑，把坑抓住。这个技能一分钟内用校准表分类。

目标是速度。PM 下午 4:47 问的，他要答案，不要备忘。

## 加载校准

读 `~/.claude/plugins/config/claude-for-legal-cn/product-legal-cn/CLAUDE.md` → `## 风险校准`。这个技能的全部意义就是对着这个表做模式匹配。

## 分流

### 匹配校准

问题匹配校准里的某个模式吗？

**匹配「通常仅供参考」：**
→ 说出来。一行。「没事 —— [模式]。发。」

**匹配「通常需要工作」：**
→ 命名那份工作。「要 [PIIA / 供应商审查 / 文案合规查一遍]。通常 [表里给的时限]。要不要我起个头？」

**匹配「通常阻塞」：**
→ 让他停下。「先等 —— [模式]。这个要正经看一遍再定档期。约个时间聊。」

**都不匹配：**
→ 也说出来。「这不像我这儿见过的任何模式。要人来看 —— [你] 或我明天？」

### 常见坑（中国法专项）

有些问题表面没事但有拐弯。识别事实模式，问那个"抓拐点"的问题，然后对具体事实检索适用规则再下结论。

| 问题听起来像 | 为什么可能不简单 | 抓拐点问 |
|---|---|---|
| 「详情页写『最低价』/『第一』行吗？」 | 广告法第 9 条绝对化用语 —— 高频违法，最低 20 万起罚。除非有具体客观依据（出处 + 时间 + 口径）否则一票否决。 | 「有可以证成排名/极值的具体客观依据吗？」 |
| 「划线价能标『原价 999』吗？」 | 明码标价规定：划线价必须是**本次降价前 7 日内本经营场所成交过的最低价**。虚构原价属价格欺诈，可依价格法处罚 + 消保法第 55 条三倍赔偿。 | 「过去 7 日内这个价真的成交过吗？」 |
| 「加个 SDK 抓一下点击行为可以吗？」 | 涉个人信息收集（个保法第 13 条合法性基础、第 17 条告知、第 28 条敏感信息、第 55 条 PIIA）。SDK 收集范围与告知一致吗？ | 「SDK 收哪些字段？哪家的？隐私政策里写没写？」 |
| 「用户注册时默认勾选『同意条款』行吗？」 | 民法典第 496 条格式条款提示说明义务；个保法第 14 条同意需自愿明确；市监与消协执法反复否定「默认勾选」。 | 「勾选是默认的还是主动的？涉个人信息就必须主动同意。」 |
| 「加个『会员自动续费』的功能可以吗？」 | 《消保法实施条例》（2024）：自动续费须服务开始前和扣款前 5 日以显著方式提请消费者注意；应提供便捷取消途径。历史上被通报案例多。 | 「有 5 日前显著提示 + 一键取消吗？」 |
| 「送礼品/开抽奖促销可以吗？」 | 反法第 10 条有奖销售规则：兑奖条件要清楚、抽奖式最高奖金不得超过 5 万元、不得欺骗性宣传。 | 「奖项、条件、概率、兑奖时间地点方式写清了吗？最高奖金多少？」 |
| 「新功能默认开启，用户可关闭可以吗？」 | 涉个人信息或算法推荐时，个保法第 24 条 + 《算法推荐管理规定》要求用户可以选择关闭算法推荐；未成年人相关默认要更严格。 | 「涉个人信息或算法推荐吗？涉未成年人吗？」 |
| 「用客户 logo/名称在官网列出行吗？」 | 客户名义使用是合同关系之外的独立授权。反法上未经许可的商业性使用可能构成不正当竞争；名誉/隐私也是坑。 | 「合同里怎么写？有书面同意吗？」 |
| 「用用户数据训练我们自己的模型行吗？」 | 原收集目的通常不覆盖模型训练。个保法第 14 条同意范围、第 23 条对外提供、第 28 条敏感信息 —— 都要重新看。 | 「当初收集时告知用户会怎么用？涉个人信息还是脱敏后的？」 |
| 「就内部用的工具，不用管吧？」 | 内部工具照样处理个人信息（员工数据、客户数据），个保法一样适用。 | 「谁的数据？员工、客户还是第三方的？」 |
| 「我们已经做过类似的了」 | 「类似」承载太多含义 —— 差在哪往往就是问题所在。 | 「哪里类似？真正的差别是什么？」 |
| 「加个大模型 / AI 智能助手可以吗？」 | 面向公众的生成式 AI 服务须做**安全评估 + 备案**（生成式 AI 办法第 17 条）；输出要做 AIGC 标识（《标识办法》2025-09-01）；训练数据合规（第 7 条）。 | 「面向公众提供吗？做备案了吗？AIGC 标识有吗？」 |
| 「加个『智能推荐』/『猜你喜欢』可以吗？」 | 算法推荐服务要**算法备案**（算法推荐规定第 24 条）；具舆论属性或社会动员能力的更严；要提供关闭选项（第 17 条）；不得诱导未成年人沉迷（第 18 条）。 | 「已做算法备案了吗？关闭选项有吗？涉未成年人吗？」 |
| 「让算法直接决定给用户看什么价（个性化定价）」 | 个保法第 24 条：不得基于个人特征作不合理差别待遇（俗称大数据杀熟）。行政处罚 + 消保法欺诈风险。 | 「差价是基于什么？消费能力？地区？消费历史？」 |
| 「AI 生成的图/视频当广告用可以吗？」 | 深度合成规定 + AIGC 标识办法：AI 生成图像/视频面向公众展示须加显式与隐式标识；广告主/发布者的核对义务（广告法第 34 条 + 互联网广告办法）。 | 「有显式标识和文件元数据标识吗？广告审核记录留了吗？」 |
| 「面向学生 / 未成年人的功能可以怎么做？」 | 未成年人保护法（网络保护专章）、《未成年人网络保护条例》（2024）、《儿童个人信息网络保护规定》（不满 14 周岁按敏感个人信息 + 父母同意）、防沉迷、青少年模式。触发点多，通常🔴。 | 「用户里有不满 14 岁的吗？18 岁以下呢？有青少年模式吗？」 |
| 「上线一个不用备案的小功能可以吗？」 | 关键看是不是构成经营性互联网信息服务 / 特定业务 —— 需要 ICP 经营许可 / EDI 许可 / 版号 / 具体行业牌照。 | 「这块业务收费吗？做什么？收什么钱？」 |
| 「境外服务器上线一个境内用户能访问的功能」 | 数据存境外即涉出境；用境外服务器提供境内服务可能触发 ICP 违规（境内经营须持境内 ICP）。 | 「哪些数据、哪些用户、境外方是谁？」 |
| 「广告里加个『主任医师』推荐可以吗？」 | 广告法第 38 条：医疗药品医疗器械保健食品不得使用广告代言人作推荐；医疗广告不得利用患者、卫生专业人员形象作证明（第 16 条）。 | 「是医疗、药品、医疗器械或保健食品广告吗？」 |
| 「我们的 App 做支付/理财入口可以吗？」 | 涉支付业务需支付牌照；涉基金/证券/保险需相应销售资质；金融广告有专门管理办法与资质要求。 | 「持有什么牌照？合作方是谁？谁在实际提供金融服务？」 |
| 「学习/教育类广告可以怎么打？」 | 「双减」下学科类培训广告严限；广告法第 24 条禁教育培训升学保证性承诺；面向 3-6 岁儿童学习类广告受限。 | 「学科类还是素质类？面向 K-12 还是成人？做承诺性表述了吗？」 |

如果可能有坑，先问那一个问题再答。**一个问题，不是清单。** 回答提示真问题时，标记并路由 —— 不要仅从问题本身模式匹配到法律结论。

## 输出格式

**给群里 / 即时消息（常见场景）：**

即时消息里的分流答复是内部工作草稿。若答复要粘贴到广泛可见的工单/文档/群，加执业档案 `## 输出` 里的草稿头（按角色不同）：

```
[草稿头 —— 按插件档案 ## 输出]
```

给 PM 的短答复格式：

```
[✅ 可 | ⚠️ 要看一下 | 🛑 停一下]

[一句话：结论和为什么。]

[⚠️ 时：涉及什么、多久]
[🛑 时：找谁、什么时候]
```

**示例：**

```
✅ 可 —— 新增 UI 埋点如果收的字段被现行隐私政策覆盖就没事。这次是被覆盖的。
```

```
⚠️ 要做 PIIA —— 新增了 [某类] 个人信息收集。通常一天。要我起个头吗？
```

```
🛑 停一下 —— 「用用户数据训练模型」会牵一堆东西。原收集时告知了什么？合同里怎么写的？先把这些拉出来再对客户/用户承诺。
```

```
🛑 停一下 —— 「全网最低价」是广告法第 9 条绝对化用语的高频命中项，各地市监罚过很多。除非有具体客观依据（出处+时间+口径）能证成，改成「优惠价格」或「本店活动价」。
```

```
⚠️ 要做算法备案 —— 面向公众的算法推荐要备案（算法推荐规定第 24 条）。备案不等于审批，但没备案上线会被通报。要我发起？
```

```
🛑 停一下 —— 面向不满 14 周岁的功能触发《儿童个人信息网络保护规定》，父母同意 + 敏感个人信息级保护 + 单独同意规则叠加。这个规模的事项，先约会议再定方案。
```

## 何时**不**用这个 skill

- 问题实际很复杂（多个议题、新型领域）→ 转 launch-review 或 feature-risk-assessment
- 问题是「帮我审这份 PRD」→ 那是 launch-review，不是分流
- 你不确定 → 说「我不确定，我正经看一下」—— 错的快答复比慢的正确答复更糟

## 语气

快、直接、有帮助。PM 不是来听讲座的。没事就说「没事」，不要罗列你检查过的七件事。有事就说什么有事、怎么处理。

你是别人愿意问的那个法务，不是别人绕开的那个。

## 用决策树收尾

按执业档案 `## 输出` 的决策树收尾。按本次输出定制选项。决策树本身就是输出；律师来选。

## 转换决策自检

- **B 级大改：** 「常见坑」表中的**每一条**换成中国法专有场景：绝对化用语（广告法第 9 条）、划线价规则（明码标价规定）、自动续费提示（消保法实施条例 2024）、有奖销售（反法第 10 条）、大数据杀熟（个保法第 24 条）、算法备案与生成式 AI 备案、未成年人相关触发（未保法/未保网络保护条例/儿童个人信息网络保护规定）、医疗保健广告代言限制（广告法第 38 条）、金融/教育广告特殊规定、境外服务器与 ICP 违规。原版针对境外法域的具体规则名称删除，替换为中国对应机制。
- **A 级直转：** 分流框架（✅/⚠️/🛑）、目的地检查、示例结构、"抓拐点问一个问题不是清单"的原则、输出格式。
- **C 级重写：** 「州法差异」在中国改为「地方执法尺度差异」（各地市监处罚力度不一，特别是广告法绝对化用语）；「州 age-appropriate design code」重写为「未成年人网络保护条例 + 儿童个人信息网络保护规定 + 防沉迷」。
