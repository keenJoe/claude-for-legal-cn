# 送达文书分流

## 目的

送达文书带期限。失败模式：错过期限、过量提交（破坏保密、承担了本可异议的负担）、不足提交（拒绝配合的责任 —— 民诉法第 111 条、行政法上的协助义务）、错过异议窗口。本 skill 分类、分析、生成配合计划附异议框架。

## 法域说明

中国民诉与英美法的调查/证据调取制度不同。中国的「协助调查/证据调取」形式包括：

- **法院调查取证令 / 协助调查通知（民诉法第 67 条、证据规定第 20 条起）** —— 民事案件中法院向第三人调取证据；当事人不能自行取得的证据可申请
- **法院协助执行通知（民诉法第 250 条起）** —— 执行阶段的协助
- **检察机关调查通知 / 协助调查通知** —— 检察机关民事、行政、公益诉讼中的调查权
- **公安机关协助调查通知 / 询问通知书** —— 刑事侦查阶段（本 skill 立即升级）
- **行政监管协助调查 / 证据调取通知** —— 网信办、市监总局、税务、海关、银保监等
- **纪检监察机关调查** —— 特殊路径，通常直接升级
- **境外送达的传票/调证** —— 通过司法协助公约或商事外交渠道，本 skill 主要处理境内

**本 skill 覆盖**：法院与检察机关的民事/行政协助调查、行政监管的证据调取。**不覆盖**：涉刑侦查（升级刑事律师）、纪检监察（直接升级）、境外送达（专项分析）。

## 立场上下文

本 skill 本质是防御性的 —— 送达至我方，姿态是配合/异议/协助。若我方立场是**原告方**，收到调查通知仍适用（例如作为原告需向法院提交证据被法院裁定协助）。若立场是**被告方 / 公司法务**，姿态与默认对齐。若涉刑相关，本 skill 停下升级。

## 加载上下文

- 送达文书（用户给路径或本次会话贴）
- `_log.yaml` —— 关联案件查询与证据保存状态
- `CLAUDE.md` —— 案件组合（我们打交道的监管）、律师保密惯例、升级路径

## 工作流

### 第 0 步：核对适用规则

**分析前，核对适用的证据调查规则**：

- 法院调查：民诉法第 67 条、证据规定第 20-25 条（申请、决定、调取范围、异议）
- 检察调查：民事诉讼监督规则、行政诉讼监督规则
- 行政调查：具体行政法与部门规章（例如《网络安全审查办法》《个人信息保护法》第 63 条监管权、《反垄断法》第 43-44 条调查权、《市监总局程序规定》）
- 证据调取的形式要件：主体、书面通知、协助调查的具体请求、期限
- 异议 / 复议路径：向发出机关申请复议、向上级机关申诉、行政诉讼

引用原始条文。核对现行有效性 —— 部门规章修订频繁。**涉刑侦查程序（公安询问、扣押、监视居住等）不属于本 skill 范围** —— 立即升级到刑事律师。

**不做隐性补充。** 若对配置检索工具查询规则返回稀薄，如实报告并停。见 brief-section-drafter 同款规则。

**来源标注。** 每处规则、案例、条文附来源标注（`[国家法律法规数据库]` / `[北大法宝]` / `[网页搜索 —— 待核验]` / `[模型知识 —— 待核验]` / `[用户提供]`）。标 `verify` 者伪造风险高。

### 第 1 步：分类

按规则识别文书类型：

- **法院调查取证令 / 协助调查通知（民事）** —— 我方非案件当事人；对方或法院要求提供证据。常见异议类别：关联性、负担、商业秘密/个人信息保护、地域范围。
- **法院协助执行通知** —— 执行阶段被要求协助（如扣划、冻结、调取信息）。协助义务较刚，异议空间较小。
- **法院对己方作为当事人的调查决定** —— 我方**是**案件当事人；这实际上是本案的证据调取。当作正在跟踪的案件对应处理。
- **检察机关调查通知（民事监督 / 公益诉讼）** —— 不同规则，姿态与法院类似但主体不同。
- **行政监管协助调查（网信办 / 市监 / 税务 / 海关 / 银保监）** —— 行政法上的协助义务，异议空间视具体法有大有小。**注意**：涉个人信息保护法第 63 条、反垄断法第 43-44 条等专项调查权，负担/关联性抗辩通常较弱。
- **公安询问 / 扣押 / 涉刑侦查文书** —— 立即升级至刑事律师；本 skill 不处理。
- **纪检监察调查** —— 立即升级至专项律师；本 skill 不处理。

### 第 2 步：提取关键字段

- **发出机关** —— 法院（哪一）、检察院（哪一）、监管机关（哪一）、案号（若有）
- **发起方** —— 谁申请调取（民诉中通常是对方当事人）
- **案由 / 事由** —— 涉及的诉讼或行政程序
- **索取文书类别** —— 编号清单
- **询问事项**（若含询问）—— 具体问题清单
- **回复/提供期限** —— 收到日 + 按适用规则算的回复窗口
- **提交日** —— 何时前提交
- **范围** —— 涉及主体、系统、时间段
- **委托代收 / 具体经办人** —— 我方谁签收、谁经办

### 第 3 步：跨案件核对

- **己方为当事人 → 关联已有案件：** 核对案号与 `_log.yaml`。匹配则路由到该案件流程；本分流为信息性。
- **第三方 → 案由不认识：** 捕捉当事人；登记为独立收件。
- **同案多份调证：** 标为协同发出；单一应答策略可能适用。

### 第 4 步：分析范围、负担、保密

**范围 / 关联性**
- 索取类别是否映射到我方确实持有的文书？
- 是否属于捞取式（过宽、与案件请求/抗辩脱钩）？
- 地域范围 / 系统覆盖 —— 按适用规则；调证范围应与案件相关。

**负担**
- 涉及的人员、系统、时间段
- 估计体量（粗：小 / 中 / 大 / 极大）
- 成本 —— 大量数据提取的负担；协助费用（民诉中调证通常无补偿；行政调查中一般也无）

**保密**
- 律师-委托人保密与工作产品可能涉及？（涉及内部法务/外部律师沟通的几乎必然）
- 其他保密：**商业秘密（反不正当竞争法第 9 条）**、**个人信息（个保法）**、国家秘密（涉密文书特殊）
- 数据出境限制（若调证要求提供的数据涉及境外接收或跨境）—— 提示

**其他异议依据**
- 保密令 / 保密协议 —— 是否需要与调证机关协商保密处理？
- 重复 —— 对方是否已从其他渠道拿到？
- 不持有 —— 具体说明我方没有对方要的东西
- 送达程序问题 —— 按适用规则核对送达要件

### 第 5 步：异议框架

起草结构化异议大纲 —— 非最终异议函，是异议要点。用户（可能与外聘律师）定稿。

每条异议：
- 法律依据 —— 引用第 0 步规则的具体条文
- 对本调证的具体适用（哪些类别、哪些主体/系统）
- 强度（强 / 合理 / 弱）
- 中国实务下的异议路径：向发出法院申请复议、向发出机关书面异议、行政诉讼（对行政调查）

### 第 6 步：配合计划

即便异议，通常仍会配合部分。计划：

- **可能提供的范围** —— 异议后我方拟提供的
- **待检索的系统与人员** —— 姓名与系统
- **时间段**
- **复核规程** —— 谁复核保密（我们、外聘律师、外部审计）
- **提交格式** —— 按通知或按协商（纸质、电子光盘、加密传输）
- **保密处理请求** —— 涉及商业秘密或个人信息的，请求以密封方式提交并要求限阅
- **个人信息去标识化** —— 涉及个保法第 4 条，交给机关前如可以匿名化则匿名化

### 第 7 步：期限

用第 0 步的期限。协助调查的回复期通常较短（10-15 日常见），行政调查有专项规定。

- **回复期限** —— 按规则；紧张时先书面申请延期
- **异议 / 复议期限** —— 按规则（对法院调查可申请复议；对行政调查按行政法有复议或诉讼路径）
- **提交日** —— 若异议不成
- **具体提交安排** —— 谁去哪送、如何回执

日历全部。立即行动项。
