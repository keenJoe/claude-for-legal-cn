# 员工手册更新

## 事项上下文

**事项上下文。** 查执业档案 CLAUDE.md 的 `## 事项工作区`。若 `启用` 为 `✗`（公司法务用户的默认），跳过本段。若启用且无活跃事项，问：「这是哪个事项的？运行 `/employment-legal-cn:matter-workspace switch <slug>` 或说 `执业层`。」加载活跃事项的 `matter.md`。输出写入事项文件夹。除非 `跨事项上下文` 为 `开`，绝不读其他事项的文件。

---

## 目的

手册修改有涟漪效应。改了年假制度就影响了离职结算里未休年假的折算、休假制度的交叉引用、以及若干地方补充。本技能在涟漪变成不一致之前找到它们。此外，**每次实质性修改都需要重新走民主程序 + 公示告知**（劳动合同法第 4 条）——否则修改后的制度不能作为管理和解除依据。

## 加载上下文

`~/.claude/plugins/config/claude-for-legal-cn/employment-legal-cn/CLAUDE.md` → 手册位置、地方补充清单、审议周期。

## 工作流

### 第 1 步：拿到修改

- 修改哪一章节？
- 新措辞是什么？
- 为什么？（法律要求、政策决定、清理）

### 第 2 步：与当前版本作差异比对

读当前手册章节。展示差异：

```diff
- [旧措辞]
+ [新措辞]
```

### 第 3 步：找交叉引用

在手册中搜索对被改章节的引用：

- 其他制度引用了这条（「见年假制度中的天数」）
- 本章节使用或定义的术语
- 修改此章节的地方补充

每个交叉引用：修改后还讲得通吗？断掉的都标记。

### 第 4 步：地方补充影响

对 `~/.claude/plugins/config/claude-for-legal-cn/employment-legal-cn/CLAUDE.md` 中的每个地方补充：

- 这个补充修改的是被改的章节吗？
- 修改是否使补充过时、错误或不完整？
- 修改是否在此前不需要补充的用工地产生了新的补充需求？

### 第 5 步：利益减损检查

修改是否减少了旧版本承诺的？

如果是：这是风险。中国法下手册视为劳动合同内容延伸，减损员工利益的调整通常需要：
- **重新走民主程序 + 公示告知**（不可省）
- **对现有员工的适用需其同意或有合法依据**（否则不利变更不能约束现有员工）
- **提前通知与过渡安排**（如涉及薪酬、工时、福利结构性调整）

标记。不阻止——但标记。

### 第 6 步：民主程序 + 公示告知重跑

**任何实质性修改都要重新走。** 不是「上次走过了就不用再走」——每次修改都要为该次修改留下民主程序记录与公示告知证据。列出：
- 是否再次提交职代会/全体职工讨论
- 与工会/职工代表的平等协商
- 公示与员工签字确认

```markdown
|---|---|---|---|

### 利益减损检查

[若减损：标记 + 现有员工的不利变更处理路径 + 需要的过渡安排]

### 民主程序 + 公示告知计划

- [ ] 提交职代会/全体职工讨论
- [ ] 与工会/职工代表协商
- [ ] 公示与员工签字确认
- [ ] 会议纪要与签字留档

### 落地就绪

- [ ] 交叉引用已更新
- [ ] 地方补充已更新
- [ ] [若减损：通知/过渡已处理，现有员工同意已取得（如适用）]
- [ ] 版本号与日期已更新
- [ ] 民主程序 + 公示告知已重跑并留证
```

## 本技能不做的事

- 批准手册修改。HR/法务负责人做。
- 向员工传达修改。
- 追踪确认签字（可路由到 HR 系统的签收流程）。
